# 配置设计第一轮：外部节点、连接关系与轻量诊断

本轮把外部节点接入现有 WinUI 配置设计器，继续使用现有方案、固定客户端核心和导出事务。使用入口为 **配置设计 → 创建或打开方案**。

## 1. 导入与编辑

在「节点」页点击「导入分享链接」，每行粘贴一个链接，选择入口组和节点用途，再进入逐条预览。默认把 Shadowsocks 作为落地，其余协议作为入口；也可明确指定整批作为入口或落地。导入后仍可逐节点调整用途、地区归属及连接组。

| 协议 | 本轮范围 | 明确拒绝的情况 |
| --- | --- | --- |
| VLESS | TCP、Reality、Vision；UUID、SNI、双客户端共同支持的指纹、公钥、short-id、ALPN | 其他传输、非 Reality、非 Vision、其他加密、非空 spiderX、未知参数或指纹 |
| AnyTLS | 官方 URI 的密码、服务器、可选端口、SNI、安全 TLS | 跳过证书验证、未支持的扩展参数；不会把普通 TLS 变成空 ECH |
| Shadowsocks | SIP002；AES-GCM、ChaCha20-Poly1305、AEAD-2022 | 插件、未支持的方法、无效密钥；SS2022 整体 Base64 userinfo |

一次最多 200 行、262144 个字符；单行最多 16384 个字符。空行忽略。认证信息、百分号编码、端口与名称分别验证；重复参数不猜测取值。SS2022 保留完整的多段身份密钥，按方法检查每段长度。

预览逐条标为「可导入」「重复连接」或「无法导入」，错误不会静默丢弃。确认按钮明确显示将导入多少个有效节点；取消任一对话框不改变方案。输入框在离开输入步骤时清空，预览只显示名称、协议、地址、角色和结果。

去重依据两类客户端的完整连接参数，忽略显示名称。相同服务器和端口上的不同用户、不同 TLS 参数不会合并。重复名称自动增加序号，调整后的名称先在预览显示；保留组名和内置名称不能被节点占用。

每个导入节点获得独立 ID，保存来源类型、协议、导入时间和连接摘要，不保存原始分享链接。改名保留 ID；修改连接参数后标注来源已修改。手动编辑也可标注网站出口地址族和预期出口 IP。仅改名时同步方案中对该节点的业务默认值与顺序引用。

受管节点继续关联实例归档；外部节点不会因此成为受管服务器，也没有安装、升级、轮换服务器凭据的权限。受管节点的预期出口来自其归档，外部节点未标注时保持未知。

本轮不读取订阅 URL，不执行来源脚本，不自动刷新或覆盖旧来源。同一连接再次导入会跳过；连接参数变化的链接作为新连接预览，不能仅凭服务器地址猜测它应覆盖哪个旧用户。

## 2. 连接关系与生成

「连接与分组」页按地区显示：

1. 入口组的具体节点候选及连接地址族。
2. 可直接使用的入口网站出口，或经该入口组连接的具体落地。
3. 落地的连接地址族与网站出口地址族。
4. 展开的「业务 → 默认出口」关系和默认出口候选顺序。

例如，使用 IPv4 连接落地，也可以由落地使用 IPv6 访问网站。这两种地址族独立显示，不能从节点名称或连接地址推断网站出口。未标注的外部出口保持「诊断时观测」。

此图展示本地方案的候选连接关系与默认值，不读取或模拟 Route/Clash 当前的实际选择。没有节点的地区候选在生成时过滤，具体成员仍由客户端选择。调整连接沿用原有地区组、落地连接组和业务组配置，不增加服务器路由或端口转发。

移除被引用的节点前显示影响范围。被移除节点或最后一个地区入口影响业务默认值时，默认值会标为待重新指定，生成配置会停止并提示，避免误用另一个出口。孤立落地仍须补全入口后才能生成。

导入或修改节点会使旧候选失效；仍须经过 **生成 → 所选客户端真实核心校验 → 审阅 → 导出**。链接解析成功不等于客户端连接验收成功。现有来源保留、文件冲突、受管来源核对和事务恢复继续生效。

## 3. 轻量链路诊断

在连接页点击「轻量链路诊断」，明确选择具体入口及同组可选落地，然后开始。默认选择会显示在选择框内，可改为组内其他成员；不会根据测速自动切换应用的活动节点。

| 阶段 | 观察位置与含义 |
| --- | --- |
| 入口 DNS | 本机解析入口服务器地址 |
| 本机 → 入口 TCP | 本机到入口监听端口的连接耗时，记录实际连接地址族 |
| 入口握手与 HTTPS 出口 | 隔离核心经指定入口访问 HTTPS IP 回显服务；耗时包括协议握手及网站响应 |
| 入口 → 落地纯 RTT | 本轮明确为未测量，不远程执行探测或把本机耗时冒充远端 RTT |
| 整条链路 HTTPS 出口 | 隔离核心固定所选入口与落地，实际走完整客户端链路；不把各阶段耗时相加 |

仅使用固定、校验过摘要和版本的 sing-box 核心。临时入站只监听 `127.0.0.1`，出口只有所选节点，不添加 DIRECT 备用。不会改系统代理、TUN、正在使用的客户端配置或 VPS 配置。

IPv4/IPv6 已标注时分别请求 `api.ipify.org` / `api6.ipify.org`；未知时使用 `api64.ipify.org` 观测。返回体限制 128 字节、不跟随跳转。提供预期地址时核对实际地址及地址族；没有预期地址时显示「已观测，未核验出口身份」，不能把可连通等同于指定出口已验证。

每个网络阶段最多 12 秒，整项任务最多 75 秒；准备核心和清理有独立边界。可用底部「取消任务」停止。取消、失败及完成均结束本次拥有的临时核心，并删除含节点凭据的临时配置。标准输出按固定缓冲区丢弃，不累计核心日志。

本轮不测吞吐、不发持续探测、没有后台常驻计时器。一次入口直出只有一个短请求；带落地链路最多两个短请求。入口阶段失败后停止后续检查，不进行 DIRECT 回退或自动重试。目标服务不可用也可能导致失败，界面不会仅凭一次失败断言节点故障。

最近最多 8 项诊断随方案保存在加密私人归档中。结果含测试时间、具体路径、测量范围、阶段状态和实测出口；节点、连接组或出口要求变化后标记需重测。诊断记录不替代候选生成与核心校验，不自动发布配置。

## 4. 实现与验证

- Core：`ClientNodeImport` 解析、预览和去重；`ClientTopology` 规划连接、生成隔离诊断配置、计算结果适用摘要；`ClientSchemes` 维护重命名引用及缺失默认值边界。
- Infrastructure：`ClientRouteDiagnostics` 执行有限探测，复用 `IValidationAssets`、版本验证和外部进程执行器。
- Desktop：既有节点页和连接页增加导入、地址族、路径选择与历史结果，沿用原有可取消任务流程。

本轮验证：

- 1010 项 .NET 边界与工作流断言通过，包含新增 54 项。导入、取消预览、重复端点不同用户、无效参数、稳定身份、结果过期及删除引用均有行为检查。
- 使用真实 Python 构建器生成含 VLESS、AnyTLS、SS2022 的双客户端候选，固定 Mihomo / sing-box 校验通过；原有单端与双端生成、校验、导出、删除回归通过。
- 真实 sing-box 在本机建立入口和落地，验证域名入口、入口直出和双跳请求、未知出口观测、预期出口比较、错误落地密码不会绕过链路、过长响应拒绝、错误出口拒绝及取消后进程和凭据文件清理。本机 HTTP 回显是测试夹具，不能作为公网 TLS 或真实 VPS 线路验收证据。
- 原生 WinUI 隐藏窗口验证导入预览与取消、改名和普通 AnyTLS 编辑、竖向连接关系、诊断选择取消及旧结果失效提示。窗口未获得前台焦点，无鼠标输入。
- 秘密扫描通过。构建成功；NuGet 漏洞数据端点不可达产生 NU1900 警告，未改变锁定依赖或跳过现有包校验。
- 客户端兼容性脚本通过；既有审计行为回归的 60 项断言通过。Windows 符号链接权限相关断言在本机跳过，保留 Unix CI 验证。

未执行生产 VPS 操作、真实公网节点诊断、应用安装、推送或发布。订阅 URL 刷新、其他协议、远端转发与纯远端测量留待后续独立轮次。
