# 第十九轮：有限 VLESS XHTTP 独立入站

本页保留第十九轮当时的范围和验收；第二十轮已扩展客户端能力，当前开发源码的操作和边界见[第二十轮指南](XHTTP-ROUND-20-2026-10-29.zh-CN.md)。下面“仅 HTTP/2／stream-one／Mihomo”等表述不再代表当前源码能力。

本轮为通用入站增加 **VLESS + TLS + XHTTP** 和 **VLESS + Reality + XHTTP**。协议、传输和传输安全分别管理，固定 HTTP/2、`stream-one`，不使用 Vision flow。两种安全方式共用独立入站的用户、监听、维护、验收和恢复流程。

当前发行基线仍为 v0.9.38，第十五至十九轮为未发行源码。本文适用于包含本轮改动的开发构建，不代表已安装应用、Route 或任何生产实例已经更新。

## 支持范围

| 项目 | 本轮行为 |
| --- | --- |
| 服务端 | 固定 Xray 26.3.27；每个入站独立 systemd 服务、身份与配置。 |
| 客户端 | Mihomo 1.19.32；输出完整 Clash YAML 原生节点。 |
| TLS 模式 | 自有证书链及私钥、匹配 SNI，TLS 1.3 和 ALPN `h2`，保持证书验证。 |
| Reality 模式 | 独立 X25519 密钥、short ID、握手目标与 SNI；不引用 TLS 证书资源。 |
| XHTTP | `stream-one`、明确的 Host 和受限路径；不猜测 `auto` 或其他模式。 |
| 用户业务 | 实际 HTTPS 和封装在代理连接中的应用 UDP DNS；公网监听为 TCP，不为 XHTTP 额外开放 UDP。 |
| 服务器出站 | 本轮限定直连，按出站资源选择 IPv4、IPv6 或 Auto；不叠加服务器下一跳。 |
| 配置设计 | 从已验收入站按用户、地址族生成来源；方案须明确选择 Clash。不自动修改双客户端方案或静默省略节点。 |
| sing-box／Route | 固定 sing-box 1.14.2 缺少 XHTTP 传输；不生成伪等价配置，不向 Route 增加另一常驻核心。 |

本轮没有新增通用 `vless://...type=xhttp` 分享链接、XHTTP 订阅转换、CDN／反向代理部署、HTTP/3、分离上下行、自定义请求头、`extra`、xmux 调优或任意高级参数支持。现有完整 Mihomo 来源可以保留 XHTTP 节点；保留原生字段不等于已验收任意参数，诊断仍按上述限定范围核对。

## 新建与应用

1. 在已接入实例的「通用入站」选择新建协议 **VLESS / XHTTP**，新增独立入站。它不会覆盖原固定角色或其他独立入站。
2. 设置名称、启用状态、监听地址／端口、UUID 用户引用、SNI 和直连出站引用。端口须与现有服务及其他入站不冲突。
3. 设置 XHTTP Host 和路径。Host 必须为有效域名；路径以 `/` 开始和结束，中间仅用字母、数字、下划线和连字符，可分段，最多 128 字符，例如 `/proxy-stream/`。查询串、百分号转义和额外高级字段明确拒绝。
4. 选择传输安全：
   - **TLS 证书**：在证书资源中导入完整 PEM 链和匹配私钥，再选择证书引用。证书必须在有效期内且覆盖 SNI；不使用跳过校验作为替代。
   - **Reality**：填写握手目标域名／端口，生成该入站专用密钥，核对公钥、short ID 及 SNI。握手目标需实际满足固定核心使用的 TLS 1.3／HTTP/2 条件；是否适合生产线路仍需从该实例实测。选择 Reality 后清除 TLS 引用；切换回 TLS 时清除 Reality 私钥并重新选证书。
5. 先查看审阅：协议、安全、SNI、Host、路径、Reality 目标及本次影响入站应与预期一致。审阅不显示 UUID 和私钥。
6. 确认后按受管服务流程安装固定核心、检查配置、应用 TCP 防火墙范围，逐用户执行真实代理 HTTPS 和应用 UDP 验收。任何用户失败、缺少传输证据或取消，都不能提交为成功。
7. 完成后在配置设计中选择 **Clash** 输出，再添加已验收入站来源。生成候选、固定 Mihomo 校验、审阅差异后导出；最后在实际客户端加载并验证业务。

服务商防火墙也需放行该 TCP 监听。应用不会代替用户修改服务商规则。实例可达地址、TLS SNI、HTTP Host 和 Reality 握手目标含义不同，不自动互相替换。

## 维护与恢复

| 操作 | 作用范围与验收 |
| --- | --- |
| UUID／用户引用变化 | 重验引用该用户的入站；旧用户来源摘要失效，要求重新生成客户端候选。 |
| TLS 证书轮换 | 替换证书资源中的完整链和私钥；只更新引用它的 TLS 入站。Reality 和无关 SS2022 服务不重启。 |
| Reality 密钥／short ID 变化 | 重验对应 Reality 入站，保留无关 TLS 入站；重新生成其客户端配置。 |
| Host／路径变化 | 重新生成连接摘要并逐用户验收；不能继续使用旧来源的资格。 |
| 停用／启用 | 停止／启动该入站独立服务并同步受管监听范围，不停用其他入站。 |
| 固定 Xray 更新 | 使用已保存模型与凭据，只接受包内更高版本；审阅并重验引用 Xray 的 Reality／XHTTP 入站。sing-box 固定版本保留。 |
| 固定 sing-box 更新 | 沿用独立操作，不把 XHTTP 纳入 sing-box 更新范围。 |
| 失败／取消 | 按该事务的影响入站恢复配置、运行状态和受管防火墙；不覆盖其他组件。 |
| 提交响应丢失 | 核对事务及远端身份，确认已提交与否；不自动重放修改。 |

同版本不同摘要不当作普通升级，降级也不走升级入口。核心版本变化属于连接资格变化，旧候选不能冒充重新验收后的节点。远端文件、服务身份或摘要发生外部变动时先停止写入，读取状态并处理漂移；不强行覆盖。

只读检查使用已保存模型，不提交表单草稿。移除入站前先处理引用；移除最后一个入站会清除它拥有的服务、配置与监听，不删除整个实例或其他组件。

## 验收记录与限制

本轮真实协议测试固定为 Xray 26.3.27 与 Mihomo 1.19.32。TLS／Reality 各两名用户均完成 HTTPS 和匹配目标、请求及回答的应用 UDP DNS 往返，产品诊断也返回对应协议、传输、安全方式、HTTP/2 与 Mihomo 证据。错误 UUID、SNI、路径、Host 以及 Reality 公钥／short ID 均不能抵达受控 HTTPS 目标。没有 DIRECT 兜底，临时核心随诊断结束关闭。

两台新建的隔离 Debian 12／13 虚拟机分别通过 17 项生命周期断言：三种并存入站、全部用户、TCP 防火墙、UUID 轮换、错误 SNI 后恢复、取消后恢复、TLS 证书轮换、Reality 密钥轮换、独立启停、提交响应丢失、整机重启及服务移除。通过 systemd InvocationID 检查无关服务未被重启；结束后关闭自有虚拟机进程。

早期证书轮换测试把测试 CA 与服务器证书设置为相同主题，导致新链验证失败；改为独立 CA 签发叶证书并携带完整链后，两版 Debian 重跑通过。调整仅限合成测试材料，没有跳过证书验证、写入系统信任库或放宽产品验收。

完整 .NET 回归通过 2605 项边界／工作流断言。本次完整入口未设置可选 Xray 路径，真实 XHTTP 分支随后指定固定二进制单独补测，22 项实际 TLS／Reality 断言全部通过；两套结果分别保存，不合并伪报一次全量结果。模型还验证更高固定 Xray 版本的影响范围、同版本替换拒绝、失败恢复及保留 sing-box 固定版本；此项使用合成版本元数据，不代表发布或下载了新 Xray。

Python 主机边界 30 项通过，覆盖未知传输、Host、flow、安全方式、HTTP/3、外部证书路径及非直连出站拒绝。原生 WinUI 十项检查通过，覆盖 TLS／Reality 切换、密钥生成、审阅脱敏、取消、核心范围说明及原生 XHTTP 改名保留连接；没有将 XHTTP 送入 Reality／Vision 编辑器。测试前台激活、前台采样和全局输入注入均为零，结束后关闭测试实例，无未完成任务。

`ValidateProject` 通过 956 项主断言及其交互、工作台、审计、更新、GUI、Python／Bash 检查；独立固定客户端兼容与每核心 16 项实际学术分流检查通过。公开文本秘密扫描通过。Windows 符号链接权限分支依原规则跳过；编译的 NU1900 提示 NuGet 漏洞源不可达，不代表已补做新的依赖漏洞扫描。

隔离通过不证明公网 CDN、真实跨境线路、任意客户端参数、持续吞吐、长期 RSS／CPU 或 IPv6 公网端到端已验收。诊断按用户请求有限运行，不新增常驻转接进程或背景探测。本轮没有推送、发行、安装、修改生产实例或切换系统代理／TUN。
