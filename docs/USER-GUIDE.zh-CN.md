# May VPS Deploy 中文完整使用手册

本手册面向第一次使用该工具的人。建议先读“快速上手”和“入口选择”，实际操作时再查对应章节。

配置设计器已更新为方案工作台。新建/打开草稿、节点局部编辑、生成与发布，以及维护事务中断恢复，请优先阅读 [方案工作台与事务恢复](WORKBENCH-AND-RECOVERY.zh-CN.md)。本文后面的长向导说明对应保留的“旧版高级生成流程”兼容入口。

桌面组件的固定/最新版本选择、查询和升级，请优先阅读 [组件版本维护](COMPONENT-UPGRADES.zh-CN.md)；网络测量及 BBR v3 直接升级、回退见 [网络调优说明](NETWORK-TUNING.zh-CN.md)。

文档中的 `<实例受管目录>` 指：

```text
<实例归档根目录>\<服务商>\<实例>\May-VPS-Deploy
```

该目录包含私钥、协议凭据和完整配置，只能保存在你的私人设备上。

## 0. 十分钟快速上手

1. 确认 Windows 已安装 PowerShell 7.4 或更高版本和 OpenSSH Client。
2. 确认 VPS 有可用的 root 密码或 OpenSSH 私钥，并准备服务商网页控制台/VNC 作为救援入口。
3. 在项目目录运行：

   ```powershell
   pwsh -File .\Start-VPSDeploy.ps1 -Mode ValidateProject
   ```

4. 自检通过后双击 `Start-VPSDeploy.cmd`，或运行：

   ```powershell
   pwsh -File .\Start-VPSDeploy.ps1
   ```

5. 根据目标选择主菜单入口：新机器选 1；已有协议但没有计划选 3；已经纳管后增加/切换协议选 4。
6. 按向导填写信息。留空采用默认值，`0` 返回上一级，`help` 查看当前说明。
7. 在最终摘要确认前，脚本不会创建实例计划，也不会修改 VPS。
8. 正式执行后不要关闭窗口。需要密码时由系统 `ssh.exe` 直接提示，脚本不读取密码。
9. 完成后使用 `client-exports` 中的测试文件做真实出口测试，再把节点合入长期使用的客户端配置。
10. 若初始端口未被复用，最后在服务商安全组删除已经从 sshd 收口掉的初始 SSH 端口。

## 1. 先理解四个概念

### 1.1 新部署

适用于新装、用途单一、可以由工具接管 SSH 和 nftables 的 VPS。它会建立新管理密钥或复用服务商私钥、创建管理用户、迁移 SSH、安装协议、应用最小防火墙、验证并归档。

不要把装有 Docker、面板、复杂防火墙或生产业务的机器当成干净新机。

### 1.2 继续未完成部署

只用于已经生成 `deployment-plan.json`、但某些模块因网络或其他原因尚未完成的同一任务。工具读取 `deployment-state.json` 后提供两条路径：跳过成功模块继续执行，或放弃未完成计划并恢复到本次部署/协议变更前。

放弃不是删除 JSON：必须先找到可信回滚基线、恢复远端受管状态并复验 SSH，随后才删除本次远端和本地快照及未完成计划。恢复失败、SSH 失败或快照删除失败时，计划与快照全部保留。已有 SSH 密钥和外部 Cloudflare/Komari Token 文件不会删除。

它不是“给任意现有 VPS 添加协议”的入口。

### 1.3 导入/纳管

适用于 VPS 已经配置好标准 Reality、AnyTLS 或 Shadowsocks，但没有本工具的 `deployment-plan.json`。导入器会：

- 复验当前 SSH；
- 默认复用现有私钥，不轮换服务器公钥；
- 只读识别受支持的标准配置路径；
- 建立计划、协议清单、私有凭据索引和服务器快照；
- 保留当前代理端口和防火墙。

纳管完成后，协议管理、网络调优和运维中心才有可靠的基线。

### 1.4 协议管理与运维中心

协议管理负责代理协议本身：安装、共存、切换、停用、卸载和协议备份清理。

运维中心负责实例生命周期：恢复、审计、凭据、SSH、防火墙、版本、客户端候选、Komari 和退役。

## 2. 主菜单与导航规范

主菜单固定为：

```text
1. 部署新 VPS
2. 继续未完成部署
3. 接入已有 VPS（首次管理）
4. 管理代理协议
5. VPS 运维中心
6. 调整网络参数
7. 客户端配置（Clash / sing-box）
8. 本地自检（不连接 VPS）
9. 退出
```

### 2.1 控制命令

| 输入 | 作用 |
|---|---|
| `9` | 只在主菜单退出整个程序 |
| `0` | 只在支持返回的子菜单、字段或确认页返回上一级 |
| `clear` / `cls` | 清除屏幕并重新显示当前提示 |
| `help` / `h` / `?` | 显示当前入口帮助 |
| 留空 | 采用方括号中的默认值 |

`b` 与 `back` 永远是普通文本。服务商名称真的叫 `b` 时可以直接输入，不会触发返回。

主菜单不接受 `0` 退出，子菜单不接受 `9` 退出。子功能正常结束或用 `0` 返回后，会重新显示主菜单，不会静默结束程序。

### 2.2 数值 0 的例外

少数字段本身允许数值 `0`，例如“保留最近几份备份”中 `0` 表示删除所有符合条件的候选。此时提示会明确写出“0 是有效数值”，不能用它返回；需要返回时应先在上一层菜单操作。

### 2.3 返回和取消不同

- `0`：回到上一层，保留已经填写的其他内容；
- “取消本次向导”：放弃整个向导，不创建新计划、不执行远端模块；
- 主菜单 `9`：结束程序。

## 4. 支持的角色与协议关系

### 4.1 Reality 入口

使用 Xray VLESS + REALITY + Vision。公网主入口为 TCP 443，可选一个高位救援入口。

Reality target 有两种模式：

- 外部 target：使用经过严格审计的普通 HTTPS 站点；
- 本机 target：使用自有域名证书，nginx 只监听回环高位端口，Xray 回落到本机。

### 4.2 AnyTLS 入口

使用 sing-box AnyTLS、可信公共 CA 证书和 ECH，监听 TCP 443。隧道内部可以承载 TCP 和 UDP，公网不需要开放 UDP 443。

### 4.3 Shadowsocks 2022 落地

使用 sing-box Shadowsocks 2022 多用户结构，监听独立高位 TCP/UDP 端口。它应由受信入口 VPS 通过 `dialer-proxy` 或 `detour` 连接，不应作为受限网络中的直接伪装入口。

### 4.4 MonitorOnly 与 AuditOnly

- `MonitorOnly`：只建立管理入口、防火墙和可选 Komari，不部署代理协议；
- `AuditOnly`：只完成临时访问和只读审计，不进行正式部署。

### 4.5 共存规则

| 协议组合 | 能否安装共存 | 能否同时运行 |
|---|---|---|
| Reality + AnyTLS | 可以 | 不可以，二者都使用 TCP 443 |
| Reality + Shadowsocks | 可以 | 可以，端口不同 |
| AnyTLS + Shadowsocks | 可以 | 可以，端口不同 |

Reality 与 AnyTLS 的二进制、配置、凭据和客户端片段可以同时保留。切换时工具只启用一个 TCP 443 服务，并用 systemd `Conflicts` 和最终监听检查防止冲突。

## 6. VPS、Cloudflare 与 Komari 准备

### 6.1 VPS 必备资料

提前准备：

- Debian 12 或 Debian 13 amd64 VPS；Windows 是唯一正式控制端，Debian 只运行远端模块；
- 公网 IPv4，存在时再填 IPv6；
- 初始 root SSH 端口；
- root 密码或服务商私钥完整路径；
- 套餐标称带宽；
- 服务商网页控制台/VNC/救援方式；
- 计划开放的代理端口。

服务商面板显示的 CPU、内存、磁盘和带宽只用于参考。脚本会在远端审计实际内存、架构、系统、监听和防火墙，但不会通过一次测速猜测长期线路能力。

### 6.2 服务商安全组

脚本只能配置 VPS 内的 nftables，不能操作服务商网页安全组。正式执行前应按向导摘要临时放行：

- 初始 SSH 端口；
- 初始为 22/低位端口时放行新 SSH 主、救援端口；初始已是非特权高位端口时只需新增一个不同的救援端口；
- Reality 主 443 和可选救援端口；
- AnyTLS TCP 443；
- Shadowsocks 高位 TCP/UDP，来源限定为可信入口 IP。

全部验收完成后，仅在初始端口未被复用时从服务商安全组移除它。

### 6.3 Reality 外部 target 准备

候选应满足：

- 正常可访问的 HTTPS 网站；
- 端口 443；
- TLS 1.3；
- ALPN 返回 h2；
- SNI 与证书 SAN 匹配；
- 不跨洲或路径明显异常；
- 多次握手稳定；
- 普通、长期运营且相对小众；
- 避免 Apple/iCloud、热门 Reality 教程固定域名和大型共享 CDN。

工具默认进行 20 次 HTTPS 建连。邻近性自动门禁使用扣除 DNS 的 TCP 建连耗时：中位数约 10 ms 最理想，15 ms 是上限。完整 TLS 建连时间包含 DNS、TCP、TLS 服务端响应与证书握手，单独展示为参考，不再错误套用 15 ms 的网络门槛；TLS 1.3、h2、证书和 20 次成功率仍分别强制检查。

自动审计失败时会展示非敏感结果。你可以更换候选，也可以输入 `ACCEPT-TARGET-RISK` 并填写原因强制继续。非交互模式不允许人工覆写，后续真实 Reality 连接验证仍不能跳过。

### 6.4 自有域名、AnyTLS 与 Certbot

完整的 Cloudflare 面板操作、域名角色映射、API Token 权限、IP 白名单、Token 文件、迁移和排错步骤见：

- [Cloudflare、Certbot、AnyTLS 与 Reality 本机 target 配置手册](CLOUDFLARE-CERTBOT.zh-CN.md)

以下是部署前必须记住的摘要。需要可信证书时，在 Cloudflare 准备 DNS-only（灰云）记录：

- AnyTLS：一个内部证书/SNI 名称和一个不同的 ECH public name；
- Reality 本机 target：一个独立站点名称。

建议为每个名称创建适用的 A/AAAA 并指向实际 VPS。没有可用 IPv6 就不要创建 AAAA。不要开启 Cloudflare 代理，也不需要另建 HTTPS/SVCB 记录；本项目由 sing-box 生成 ECH key/config，并把 ECH config 直接写入客户端。

API Token 最小权限：

```text
Zone / DNS / Edit
Zone / Zone / Read
资源：只包含目标 Zone
```

不要使用 Global API Key 或 Origin CA Key。Token 应长期有效，不要设置早于证书使用期的到期日。若设置客户端 IP 白名单，必须包含实际运行 Certbot 的每台 VPS 出口 IPv4/IPv6；即使 DNS 只发布 A 记录，VPS 访问 Cloudflare API 时仍可能优先走自身 IPv6。不要使用当前 Windows 浏览器旁边的“使用我的 IP”。地址变化前要先更新 Token，否则续期会失败。

将 Token 作为唯一一行保存到实例私人资料目录，例如：

```text
cloudflare-certbot-token.private.txt
```

文件只能包含一行原始 Token，不要添加 `Bearer`、变量名、引号或 `dns_cloudflare_api_token =` 前缀。向导读取文件路径，不把 Token 值写进计划或日志。Certbot 是本项目使用的 ACME 客户端；“ACME”是证书协议名称，不代表另装了其他证书程序。

脚本会：

- 使用 DNS-01 签发 ECDSA P-256 证书；
- 执行 staging 模拟续期；
- 停用发行版可能重复的 `certbot.timer`；
- 启用 `mxh-certbot-renew.timer` 每日两次检查；
- 续期成功后原子更新服务证书，并重启 AnyTLS 或 reload 本机 nginx target。

### 6.5 AnyTLS padding

Padding 不是密码。它影响数据分段外观，不能代替加密和认证。

新部署会生成 `PerInstanceConservativeV1`：保留官方方案的基本结构，在受控范围内产生每实例不同且长期固定的数组。方案写入计划，继续未完成部署或重启不会重新随机。客户端首个会话使用协议默认方案，之后由服务端在加密连接内下发，所以 Mihomo/sing-box 客户端片段不需要重复填写 padding。

不要为了追求随机而使用极大包长或频繁轮换方案；这会增加开销、碎片和兼容风险。

### 6.6 Komari

安装 Agent 前准备：

- Controller 的连接端点；
- 当前节点 Token；
- 确认 Controller 可从该 VPS 访问。

Token 使用隐藏输入，只经 SSH 标准输入传输。Agent 默认低权限运行、关闭 Web SSH 和自动更新，不开放新的公网监听。

Controller/Agent 的固定版本以 `config/versions.json` 为准。不要把说明文档里的旧版本号当成当前事实；升级入口会按该文件的精确版本和 SHA-256 执行。

## 7. 新部署：逐项填写

### 7.1 私有归档根目录

这是保存所有实例资料的上级目录，不是源码目录。默认解析优先级：

1. 命令行 `-InstanceRoot`；
2. `MXH_VPS_INSTANCE_ROOT` 环境变量；
3. `config/app-defaults.local.json`；
4. `config/app-defaults.json` 的通用相对路径。

你可以在向导第一项修改。输入 `0` 返回主菜单。

本项目的本地路径输入同时接受全 `/` 和全 `\` 写法，例如 `D:/Private-VPS-Archive` 与 `D:\Private-VPS-Archive` 等价。为避免复制、拼接造成歧义，同一条输入不能混用两种分隔符；工具会先拒绝混用，再把合法输入规范化为当前系统的分隔符。该规则同样适用于计划、私钥、Cloudflare Token、客户端权威文件、输出目录和 Controller 备份路径。

### 7.2 服务商和实例名称

最终实例目录是：

```text
<归档根目录>\<服务商>\<实例>
```

服务商与实例名称不能包含 Windows 文件名禁用字符：

```text
\ / : * ? " < > |
```

服务商名称可以是公司简称，不需要等于工商全称。

### 7.3 客户端节点名称

这是 Clash/sing-box 中显示的节点名称，应包含足够的服务商、地区、套餐或角色信息，并在整个客户端配置中唯一。

不要在名称中放 IP、密码或密钥。

只填写 IPv4 时，最终客户端节点直接使用这里输入的名称，不附加地址族。若同时填写 IPv6，工具会生成两个节点，并分别附加 `-IPv4` 与 `-IPv6`；这样单栈名称保持简洁，双栈节点又能明确区分。节点名称不额外附加协议名，导入 Clash 或 sing-box 后可直接从节点协议类型查看。

### 7.4 IP、SSH 与初始认证

- IPv4 必填；
- IPv6 没有就留空；
- 初始 SSH 端口填写当前真实可登录端口；
- 密码模式由 `ssh.exe` 直接提示；
- 现有私钥必须是 OpenSSH 可读取的私钥文件。

使用服务商现有私钥时，默认策略是：

1. 复制到实例的 `May-VPS-Deploy\ssh`；
2. 改为规范文件名；
3. 从私钥推导公钥并复验；
4. 不修改源文件；
5. 不修改服务器已有公钥。

只有选择“生成新的实例管理密钥”时，脚本才将新公钥加入服务器；旧私钥仍保留作引导/救援。

### 7.5 部署角色

选择 Reality、AnyTLS、Shadowsocks、MonitorOnly 或 AuditOnly。初次不确定时建议只部署当前实际需要的主协议，以后可以通过协议管理增加备用协议。

### 7.6 端口

初始 SSH 为 22/低位端口时，使用两个不同的随机高位主/救援端口。服务商初始 SSH 已是可复用的非特权高位端口时，它直接成为主端口，只新增一个 20000–59999 内且不同的救援端口，不会再创建第三个 SSH 端口。Reality 主入口使用 443，可选高位救援入口；AnyTLS 使用 443；Shadowsocks 使用高位 TCP/UDP 端口。

不要使用已经被远端监听占用的端口。摘要会再次显示需要在服务商安全组放行的端口。

### 7.7 Xray 版本

Reality 可选择：

- 当前固定验证版：来自 `config/versions.json`，推荐；
- 官方最新稳定版：从 XTLS/Xray-core 官方 latest API 解析非草稿、非预发布的精确版本。

无论选择哪种，最终计划都会记录具体版本，不使用模糊的 `latest`。

交互界面会分两行显示“Xray 版本来源”和“本次实际部署版本”。如果官方 latest 当前恰好与项目固定验证版同号，界面会明确说明仍采用 `LatestStable` 来源，没有把选择改成固定验证版。安装脚本自身的固定校验属于供应链保护，不再混入版本选择提示。

### 7.8 Reality target

外部 target 填写站点域名，脚本从 VPS 端实测。不能仅凭本地浏览器延迟判断。

本机 target 需要填写：

- 证书域名；
- Cloudflare Zone；
- Certbot 邮箱；
- Token 私有文件路径；
- 回环 HTTPS 高位端口。

nginx 只监听 `127.0.0.1` 和 `[::1]`，不会开放公网 80/443 站点。

Reality 与 AnyTLS 入口默认开启“强制代理网站流量从 VPS IPv4 出口”。IPv4/IPv6 客户端节点名只表示连接入口时使用的服务器地址族；无论从哪种入口进入，同一个服务端仍须单独限制网站出口地址族。部署摘要会显示该策略；若选择“否”，摘要会提示网站可能看到 VPS 的 IPv6。落地机的独立出口策略不受此入口选项约束。启用强制 IPv4 时，最终验收会拒绝实际返回 IPv6 的网站出口。

### 7.9 AnyTLS

填写：

- 证书/SNI 域名；
- 不同的 ECH public name；
- Cloudflare Zone、邮箱、Token 文件；
- 是否强制 IPv4 出口。

AnyTLS 密码与 ECH 服务端密钥由服务器生成并进入私有归档，不应手工粘贴到聊天或源码。

### 7.10 Shadowsocks 落地

填写：

- 高位 TCP/UDP 端口；
- 允许访问该端口的入口 VPS 公网 IPv4/IPv6；
- 客户端使用的 transit/detour 组名；
- 是否启用第二个 IPv6 出口用户；
- 需要时指定 IPv6 地址与绑定接口。

可信入口白名单必须同时在服务商安全组和 VPS nftables 中生效。

### 7.11 网络调优

套餐标称带宽必填，因为服务商通常会明确给出。代表性 RTT 可留空：

- 入口机 RTT：主要使用地到入口 VPS；
- 落地机 RTT：常用入口 VPS 到落地 VPS。

没有 RTT 时使用 `BaselineOnly`，仅应用 fq、可用时 BBR、TFO、MTU 探测和保守队列下限，不计算 TCP 缓冲区上限。提供 RTT 后使用 `AdaptiveConservative`，结合实测内存与 2×BDP 计算受限缓冲区。

脚本不会运行公网测速，不会把虚拟网卡显示的 10G/25G 当作套餐带宽，也不会根据一次低峰测试写入激进参数。

### 7.12 摘要确认

摘要会显示角色、IP、端口、认证、协议、target/证书、网络调优、Komari 和模块顺序。

- 选择“确认方案并继续”：创建计划并准备执行；
- 选择“取消本次向导”：不创建任何新计划；
- 输入 `0`：返回最后一个有效字段继续修改。

确认计划后还会询问是否按模块顺序开始。此处返回主菜单时，已经确认的计划会保留，可稍后用主菜单 2 继续。

## 8. 继续部署与纳管现有 VPS

### 8.1 继续未完成部署

选择主菜单 2，输入已有 `deployment-plan.json`。脚本会显示摘要并让你确认。

不要拿另一台 VPS 的计划继续。计划中的服务器地址、归档目录、管理密钥和当前管理端口必须一致。

核对摘要后可选择：

1. “使用此计划继续”：成功模块默认跳过；失败或未完成模块重跑。协议变更发生回滚后，本次变更模块会全部重置，证书、协议、防火墙和真实验收按新事务重跑；
2. “放弃未完成计划并回滚到部署前”：输入精确确认短语后，恢复服务器并清理本次计划；
3. “取消并返回主菜单”：不做任何更改。

新部署在写入恢复公钥之后、其他修改之前建立统一基线。放弃时恢复受管配置、受管用户、服务启停、SSH、nftables 和脚本管理的 sysctl；恢复公钥特意保留，避免回到只能使用服务商密码的状态。为避免 apt 依赖级联卸载，部署期间新安装的软件包保留，但对应受管服务和配置会恢复；完成后界面会报告保留数量。

只有远端回滚成功且初始 SSH 复验通过后，工具才删除统一基线和本次新增的时间戳备份，再清理本地计划、状态、秘密和生成片段。若远端快照已经安全删除、但 Windows 端本地清理意外中断，再次进入放弃流程只补做本地清理。

协议变更采用相同原则：必须有“任何变更前已建立快照”的新状态标记。旧版已运行过远端模块但没有统一基线的计划会拒绝自动放弃，不能把不完整恢复伪装成干净回滚；这类计划应继续完成，或人工核对/服务商重置。

若状态显示自动回滚仍在进行，应先确认 VPS 已恢复，不要同时创建第二个变更。

### 8.2 导入没有计划的现有 VPS

选择主菜单 3。向导会收集归档路径、实例信息、当前 SSH、现有私钥策略和套餐带宽。

默认推荐：

- 复用当前私钥并复制为规范文件名；
- 保持现有 SSH 认证策略；
- 不改现有 SSH 监听端口；
- 不重装协议；
- 不覆盖防火墙。

导入器当前识别标准路径中的：

- Xray Reality；
- sing-box AnyTLS；
- sing-box Shadowsocks 2022；
- 受管 Certbot；
- Komari Agent/Controller 的已知服务。

配置布局无法安全解析时会停止，不会猜测凭据。导入只有一个 SSH 端口的实例仍可管理协议，但不具备新部署的双入口救援能力。

纳管成功后再选择主菜单 4、5 或 6。

## 9. 现有 VPS 协议管理

选择主菜单 4 后先选择并核对实例，然后进入：

```text
1. 安装并启用新协议
2. 安装备用协议（验证后停用）
3. 启用或停用已有协议
4. 卸载已停用协议
5. 清理旧备份（协议变更）
6. 更换 VPS
0. 返回上一级
```

### 9.1 安装并切换

目标协议会先安装、临时启用、完成真实测试，再提交最终状态。若 Reality 与 AnyTLS 冲突，原协议保留安装但停用；Shadowsocks 可保持并行。

### 9.2 安装为备用

备用协议也必须临时启用并完成和主协议同等的功能测试，然后恢复原有服务组合。最终状态为已安装、未启用、未运行。

### 9.3 切换与停用

不重新安装，只改变已安装服务的 enabled/active 状态。启用 Reality 或 AnyTLS 时会自动停止另一个 TCP 443 服务。

停用当前唯一入口协议后，公网 443 将没有代理监听；SSH 与独立 Shadowsocks 不受影响。

### 9.4 卸载

只允许卸载已经 disabled/inactive 的协议。卸载会删除该协议的受管运行时、systemd 单元和服务端配置，并把当前凭据/客户端片段移出活动状态。

变更前副本仍保存在 `migration-backups` 和 VPS 端回滚快照。证书、Certbot 和共享环境不会随单个协议自动删除。

### 9.5 清理协议备份

只处理：

- 本地 `<实例受管目录>\migration-backups`；
- 远端 `/root/vps-deploy-backups/<时间>/protocol-lifecycle`；
- 兼容旧版的 `protocol-migration` 目录。

存在活动回滚计时器或未完成变更时拒绝删除。保留数量 `0` 表示删除所有符合条件的候选，不表示返回。

### 9.6 协议变更的恢复保护

执行顺序是：

1. 校验计划和当前远端状态没有漂移；
2. 复制本地计划、状态、秘密和客户端/服务器快照；
3. 远端打包协议文件、systemd 状态、nftables 和网络调优；
4. 启用 20 分钟独立回滚 timer；
5. 安装或切换并进行真实功能测试；
6. 收口最终防火墙和服务状态；
7. 提交计划并取消 timer。

Windows 端失败时会优先立即回滚；即使 SSH 暂时被错误规则阻断，VPS 端 timer 仍会自行恢复。

## 10. 独立网络调优

主菜单 6 可直接对已纳管实例运行，不要求重新部署协议。

你需要提供套餐标称带宽；RTT 可留空。多协议实例会询问按哪个主要角色计算保守队列下限。

该操作：

- 不安装或切换代理协议；
- 不改变协议端口；
- 不调用防火墙应用模块；
- 应用前备份脚本管理的 sysctl；
- 使用 20 分钟恢复保护；
- 应用后复验系统与当前服务。

保守调优适合长期使用，不需要每天定时测速。线路质量、晚高峰丢包和三网表现应通过独立网络测试评估，不应直接驱动内核参数每日变化。

## 11. 现有 VPS 运维中心

主菜单 5 包含：

```text
1. 从备份恢复
2. 检查服务和配置（不改服务器）
3. 更换代理密钥／密码
4. SSH 登录设置（密钥、端口）
5. 管理防火墙规则
6. 更新服务版本
7. 客户端配置（Clash / sing-box）
8. Komari 监控管理
9. 停用或卸载服务
10. 更换 VPS
11. 处理未完成的维护操作
0. 返回上一级
```

这里的 `9` 是当前子菜单中的第九项“停用或卸载服务”，不是退出程序。只有最外层主菜单的 9 才表示退出。

### 11.1 从备份恢复

恢复点必须同时存在本地元数据备份与远端协议快照。可选择：

- 仅恢复协议配置和凭据，保持当前服务/防火墙状态；
- 完整恢复协议文件、服务启停、防火墙和 sysctl。

完整恢复不会恢复旧 SSH 登录设置。如果备份中的 SSH 端口与当前不同，工具会在变更前拒绝加载其历史防火墙；请选择兼容的“只恢复配置”，或使用换端口后的备份。恢复后还会重新验证当前主、救援 SSH 入口，验证失败不提交。仅配置恢复涉及本机 HTTPS target 时，也会检查并重新加载正在运行的 nginx。

恢复前仍会保存当前快照。执行需要输入 `RESTORE`。

### 11.2 只读健康审计与漂移检测

读取：

- sshd 有效配置和监听；
- 代理/Komari 服务状态；
- 端口监听；
- 证书剩余天数；
- 固定资产版本；
- 受管配置 SHA-256；
- 回滚计时器状态。

审计不回传配置正文或密钥。严重服务异常不能通过“更新基线”掩盖；只有确认合理的文件哈希变化才能纳入新基线。

### 11.3 代理凭据轮换

只允许轮换当前正在运行的受管协议，避免误激活备用协议。

- Reality：生成候选 UUID/Reality 密钥等，原子切换并真实验证；
- AnyTLS：轮换用户密码，默认保留证书和 ECH；
- Shadowsocks：轮换用户密钥，默认保留服务器主密钥。

候选测试通过后才提交并更新私有客户端片段。

### 11.4 SSH 独立维护

支持：

- 只读审计；
- 轮换实例专用 Ed25519 密钥；
- 重设双 SSH 高位端口并同时轮换密钥。

SSH 维护使用独立的 10 分钟回滚 timer。新密钥/端口在 root、admin 和 sudo 全部由新连接复验前，不删除旧密钥和旧监听。

`PreserveExisting` 防火墙模式下拒绝自动换 SSH 端口，必须先人工审计并决定是否接管规则。

### 11.5 防火墙独立维护

受管最小 nftables 实例可：

- 只读审计；
- 按当前协议清单重新生成规则；
- 修改 Shadowsocks 可信入口白名单。

`PreserveExisting` 实例默认只读。人工输入明确确认短语后可以接管为受管最小规则，但这会替换现有规则，装有 Docker、面板或第三方业务时不应使用。

### 11.6 更新服务版本

只对当前受管组件操作。固定版本与 SHA-256 来自 `config/versions.json`。

桌面版的 Reality/Xray、AnyTLS 与 Shadowsocks/sing-box、Komari Agent/主控及 cloudflared 均可选择应用固定版或官方最新稳定版。先查询并锁定具体资产和 SHA256，再审阅执行。旧命令行入口的选项按其原有流程保留。

选择“官方最新稳定版”后，界面显示实际版本、资产、SHA256 和查询时间；来源单独归档，查询材料变化或超过 24 小时时重新查询。同号提示无需升级；如需重新安装，明确选择固定版本并审阅。

升级先备份，再校验下载、配置、服务，并重新生成逐地址族测试配置，复用完整真实协议验收；不要把“二进制版本号改变”当成升级成功。

代理更新会显式重启目标服务，并核对运行进程是否使用刚安装的二进制。停用的备用协议不能直接更新：请先在协议管理中启用或切换到它，完成更新验收后再按需要切回。工具不会为更新备用协议而隐式抢占当前入口。

如果维护中断后服务器已自动回滚，请进入“处理未完成的维护操作”，同步恢复本地计划、凭据和配置；未完成的本地记录处理前，不能开始新的维护。

### 11.7 客户端权威配置候选

运维中心内的入口主要针对当前实例：把最新客户端片段合并为候选，或生成退役删除候选。默认不直接修改权威文件。

需要设计多个地区、入口和落地关系时，使用主菜单 7 的完整设计器。

### 11.8 Komari 监控管理

支持：

- 状态审计；
- 安装/修复/轮换 Agent Token；
- 固定版本升级 Agent；
- 卸载 Agent；
- 备份 Controller 数据、二进制和服务；
- 从本地备份恢复 Controller；
- 轮换 Cloudflare Tunnel Token；
- 固定版本升级 Controller，自动备份并保留数据库、主题和启停状态；
- 卸载 Controller 与 Connector。

Controller 操作会验证服务、回环监听、HTTP 和 Tunnel 状态。浏览器登录、TOTP 和主题视觉效果仍需人工确认。

### 11.9 停用或卸载服务

分为：

1. 只生成清单和最终健康报告；
2. 停止/禁用代理与 Agent，保留文件和 SSH；
3. 最终备份后删除受管代理/Agent 文件，保留远端恢复点；
4. 再清除远端恢复点；
5. 额外移除 Controller/Connector。

脚本始终保留 SSH、操作系统和服务商实例，不会撤销 Cloudflare 控制台 Token，也不会替你删除云服务器。

## 12. Clash/sing-box 客户端权威配置设计器

主菜单 7 包含：

```text
1. 生成配置
2. 查看或修改本机布局默认值
3. 查看可用节点数据源
4. 校验一对现有配置
0. 返回上一级
```

### 12.1 配置模型

推荐结构是：

```text
业务组
  └─ 地区入口组、具体链式落地出口或 Default Exit
       ├─ 入口节点
       └─ 落地节点（节点自身指定 dialer-proxy/detour 到某个地区入口组）
```

含义：

- 地区入口组：选择“客户端先连哪一台线路机”；
- 落地节点：决定最终公网出口 IP；
- `dialer-proxy`/`detour`：落地节点通过哪个地区入口组拨号；
- 业务组：可直接选择地区入口组，也可选择某个具体链式落地出口，从而自由决定最终落地节点；还可包含 Default Exit/直连策略。业务组不需要把同一入口组内部的每台物理入口节点重复展开。

因此不需要再创建含义含混的“US-West Landing Transit A”中间组。服务商信息由节点名体现，地区关系由地区入口组和落地节点映射体现。

### 12.2 基础来源

默认使用 `templates/client/` 中的通用 Clash/sing-box 骨架，不依赖你已有的主配置，也不绑定盘符。

也可选择一对现有配置作为只读基础，用于保留自己的规则和其他通用结构。现有配置不是设计器的强制依赖。

### 12.3 节点来源

- 已纳管 VPS：扫描实例归档，从 `client-exports` 提取；
- 未纳管 VPS：在生成流程中隐藏输入 VLESS Reality、AnyTLS 或 Shadowsocks 信息；
- 现有基础配置：可选择保留并重新分配其中的代理节点。

手动输入的秘密不会显示，但生成文件本身是私有配置，不能提交 Git。

### 12.4 地区入口与落地

入口节点必须分配到一个地区入口组，例如 `US-West-LA Entry`、`US-West-SF Entry`、`Hong Kong Entry`、`Europe Entry`。SF 是本项目对旧金山湾区的统一简称，包含 San Jose；实例原始名称不需要改写。落地的 IPv4 与租用 IPv6 出口可能位于不同城市，可以分别填写出口节点名；入口组描述连接经过的入口，不能据此推断最终出口位置。已保存的自定义组名保留，不按 IP 或服务商标签自动改城。

每个 Shadowsocks 落地节点必须选择一个地区入口组作为 transit/detour。它仍然是“落地节点”，只是拨号动作经所选入口组完成。

同一个落地以后可以复制出不同逻辑节点，分别使用不同入口组，但名称必须唯一。只有实际需要多条不同链路时才这样做。

### 12.5 修改真正的默认值

“查看或修改本机布局默认值”会维护未来运行设计器时使用的默认偏好，而不是只改本次选择。可修改：

- 地区入口组名称和显示顺序；
- 每个地区组内的节点优先顺序；
- 落地节点到地区入口组的默认映射；
- 默认出口组、直连组和候选顺序；
- 业务组名称、顺序和默认项；
- 默认基础来源与输出目录；
- 恢复项目通用默认值。

个人默认写入：

```text
config/client-layout.local.json
```

该文件被 Git 忽略。项目通用默认仍在 `config/client-layout.default.json`，不包含个人节点或路径。

### 12.6 保存方式

生成完成后可选择：

- 覆盖指定权威配置：先校验、建立时间戳备份，再成对原子替换；
- 生成一对新文件：不修改任何现有配置。

覆盖模式要求明确指定 Clash YAML 与 sing-box JSON。工具拒绝 Clash Verge AppData 路径。

### 12.7 校验内容

- 项目内置稳定版 Mihomo 和 sing-box 官方 Windows amd64 压缩包，先核对 SHA-256，再分别执行实际核心语法检查；
- 可选的 Mihomo Alpha 只做额外兼容检查，不替代稳定版；
- 内置核心缺失或损坏时可重试、手动选择，或输入确认短语明确跳过；跳过记为 `SkippedByUser`，不算通过，非交互模式不能自动跳过；
- sing-box 文件必须低于 4 MiB；
- selector 成员必须存在；
- 拒绝 selector 循环；
- Clash `dialer-proxy` 与 sing-box `detour` 必须同步；
- 两份配置的节点和组关系必须一致。

## 13. 部署过程与文件产物

### 13.1 新部署的安全顺序

典型顺序：

1. 建立临时 root 访问并确认恢复公钥；
2. 建立统一部署回滚基线；
3. 只读审计系统、服务、监听和防火墙；
4. 安装基础工具并创建 admin；
5. 写入/复用管理公钥；
6. SSH 过渡为主/救援双入口：低位初始端口临时保留并新增两个高位端口，服务商高位初始端口则复用并只新增救援端口；
7. 验证 root/admin 新连接和 sudo；
8. 审计 target/证书前置；
9. 安装协议并做本机和真实客户端测试；
10. 应用网络调优和最小 nftables；
11. 安装可选 Komari；
12. 生成客户端片段和服务器快照；
13. 最终验证；
14. 最终确认 SSH：未复用时从 sshd/nftables 移除初始端口，复用时保留它作为主端口；
15. 提交部署事务并删除统一回滚基线；
16. 写入最终归档和校验和。

任何新 SSH 路径未通过时都不会关闭旧入口。

### 13.2 主要文件

```text

├─ deployment-plan.json                 # 已确认的计划，不应手改
├─ deployment-state.json                # 模块状态、当前管理端口、基线
```

### 13.3 客户端片段

这些文件包含真实凭据。先用测试文件验证，再通过客户端设计器合入长期权威配置。

## 14. 部署后验收

### 14.1 SSH

在新的终端窗口分别验证：

```powershell
ssh -i '<管理私钥>' -p <主端口> root@<VPS地址>
ssh -i '<管理私钥>' -p <救援端口> root@<VPS地址>
ssh -i '<管理私钥>' -p <主端口> admin@<VPS地址>
```

再确认 `admin` 可以使用 sudo。若初始端口未复用，应已从 sshd 和 VPS 防火墙移除；若已复用，它应仍是计划内主端口。

### 14.2 Reality

必须同时满足：

- Xray 配置测试通过；
- 服务 active；
- 443/救援端口监听正确；
- 稳定版 Mihomo 和 sing-box 均按已配置的 IPv4/IPv6 地址族完成真实 Reality 认证；
- HTTPS 204 成功；
- 出口 IP 是目标 VPS；
- UDP 测试通过；
- 未认证 target 行为符合计划。

如果控制端没有可用的原生 IPv6 路径，程序不会要求把本机网络故障当成协议失败。交互模式会先推荐选择另一台已纳管、具备 IPv6 的 VPS 代为执行外部验收；如果当前确实无法提供任何 IPv6 验收端，也可以输入强确认短语跳过当前协议的 IPv6 项。跳过记录会绑定当前服务器 IPv6，保存在该实例的私有计划和状态中，并显示为 `SkippedByUser`，不会计入通过；服务器 IPv6 变化后必须重新选择或重新验收。非交互模式不能临时决定跳过，只接受事先写入且仍与当前地址匹配的记录。

### 14.3 AnyTLS

必须同时满足：

- 证书链可信且域名匹配；
- ECH 配置与服务端一致；
- AnyTLS 服务 active；
- Xray Reality 不同时占用 443；
- HTTPS、出口 IP 和 UDP DNS 往返成功；
- `mxh-certbot-renew.timer` 已启用；
- staging 模拟续期成功。

AnyTLS 的 IPv6 验收路径不可用时遵循与 Reality 相同的外部验收或显式跳过规则；IPv4、证书、ECH、HTTPS、出口 IP 和 UDP DNS 等其余项目仍必须真实通过。

### 14.4 Shadowsocks 落地

必须同时满足：

- TCP/UDP 端口监听；
- nftables 与服务商安全组只允许可信入口；
- 服务端回环自测通过；
- 从可信入口链式连接成功；
- TCP HTTPS 出口正确；
- UDP DNS 往返成功；
- 使用第二 IPv6 用户时出口确实为指定 IPv6。

### 14.5 Komari

确认 Agent 在 Controller 上在线，节点信息正确，无公网 Web SSH 监听。Controller 升级或迁移后还应人工检查登录、TOTP、主题、历史数据和 Tunnel 域名。

## 15. 失败恢复与常见问题

### 15.1 最先做什么

1. 不要立即删除本地归档或远端备份；
2. 不要并行启动第二次协议/SSH/防火墙变更；
3. 阅读最后一个 `[错误]` 和 `<实例受管目录>\deployment.log`；
4. 确认服务商控制台仍可进入；
5. 等待或检查 VPS 端自动回滚 timer；
6. 恢复后使用“继续未完成部署”，不要重新新建实例计划。

从交互主菜单进入的功能若运行失败，程序会保留计划与状态，并提示按任意键返回主菜单；不会再退出到 `Start-VPSDeploy.cmd` 的进程级暂停。显式命令行模式和非交互模式仍以非零状态退出，便于自动化识别失败。

### 15.2 SSH 失败

- `Permission denied`：检查用户名、私钥格式、口令和公钥是否仍在服务器；受管私钥会自动设置 Windows OpenSSH 所需的最低 ACL，复用模式不会修改服务商源私钥，若源文件因权限被 OpenSSH 拒绝会自动尝试受管副本；
- OpenSSH 密码提示不会回显字符或星号；Windows Terminal 通常可用鼠标右键或 `Ctrl+Shift+V` 粘贴。粘贴后看不到内容是正常现象，但应确认剪贴板不含首尾空格或换行；
- 初始密码认证失败后，向导允许重新打开密码提示。若已经显示 `VPSDEPLOY_BOOTSTRAP_OK`，说明密码登录成功；随后失败属于新管理公钥复验，不应继续反复修改密码；
- 部分服务商 Debian 镜像允许 root 密码登录，却在 sshd 有效配置中关闭公钥认证。新部署引导会用最小兼容 drop-in 恢复标准公钥入口，并依次执行 `sshd -t`、有效配置检查和 reload；失败会恢复原文件。此阶段不会提前关闭密码或旧端口；
- `REMOTE HOST IDENTIFICATION HAS CHANGED`：确认确实是重装后的同一 IP，再清理该地址对应的 known_hosts 条目；
- 新高位端口超时：同时检查服务商安全组、sshd 监听和 nftables；
- 导入时只有密码：可以用密码引导生成管理密钥，但密码不会写入计划；
- 带口令私钥：可以人工登录，不适合后续无人值守维护。

### 15.3 新机审计拒绝

发现 Docker、面板、已有代理或复杂 nftables 时，说明该机不符合干净新机边界。不要强制套用新部署；应人工清理、重装，或使用纳管模式保留现有防火墙。

### 15.4 Reality target 不通过

查看具体失败项：证书、TLS 1.3、h2、跳转、CDN、TCP 建连时延或稳定性。界面中的完整 TLS 完成时间仅供分析，不单独触发 15 ms 门禁。优先更换候选；只有理解风险时才人工覆写，覆写后仍要通过真实 Reality 测试。

### 15.5 Certbot/Cloudflare 失败

检查：

- Token 是否只有一行；
- 权限是否为 Zone DNS Edit + Zone Read；
- Zone 资源是否正确；
- 客户端 IP 白名单是否包含当前 VPS 访问 Cloudflare API 时实际采用的 IPv4/IPv6；项目会在安全错误中显示该次请求的源地址和地址族；
- DNS 记录是否为灰云并指向当前 VPS；
- 域名是否已经委托给当前 Cloudflare Zone；
- VPS 时间是否同步。

不需要开放 80 端口，因为使用 DNS-01。

### 15.6 BBR 未启用

云内核可能已经使用 BBR，也可能不提供对应模块。脚本会尽力启用并记录结果，但不会为了 BBR 更换内核。先看最终审计，不要只看某一条 sysctl 写入信息。

### 15.7 内置测试核心缺失或损坏

正常情况下不需要查找或首次下载：稳定版 Mihomo 与 sing-box 压缩包已在 `vendor/test-cores/windows-amd64`，经 SHA-256 校验后解压到 `.cache/client-cores`。失败时可重新校验、手动选择可执行文件，或在交互模式输入确认短语明确跳过；跳过会记录为 `SkippedByUser`，不能显示为通过。项目不会扫描 Clash Verge AppData、注册表或系统 PATH，也不会改变系统代理/TUN。

### 15.8 系统代理偶发断网

这是客户端运行时问题，不等同于服务端部署失败。先检查客户端日志、当前 selector、DNS、系统代理端口和实际链路。关闭再开启恢复，通常说明客户端监听或链路状态没有自行恢复；不要通过重装 VPS 解决。

## 16. 命令行与高级用法

### 16.1 各模式

```powershell
pwsh -File .\Start-VPSDeploy.ps1 -Mode New
pwsh -File .\Start-VPSDeploy.ps1 -Mode Resume -PlanPath '<计划路径>'
pwsh -File .\Start-VPSDeploy.ps1 -Mode Import
pwsh -File .\Start-VPSDeploy.ps1 -Mode Migrate -PlanPath '<计划路径>'
pwsh -File .\Start-VPSDeploy.ps1 -Mode Maintain -PlanPath '<计划路径>'
pwsh -File .\Start-VPSDeploy.ps1 -Mode TuneNetwork -PlanPath '<计划路径>'
pwsh -File .\Start-VPSDeploy.ps1 -Mode ClientConfig
pwsh -File .\Start-VPSDeploy.ps1 -Mode ValidateProject
```

`Migrate` 是兼容旧命令保留的模式名，界面含义是协议管理。

### 16.2 DryRun

```powershell
pwsh -File .\Start-VPSDeploy.ps1 -Mode New -DryRun
```

DryRun 用于预览计划和模块，不连接 VPS、不创建正式秘密、不执行远端修改。它不能代替真实测试。

### 16.3 NonInteractive

`-NonInteractive` 适合已经有完整计划的自动继续场景。它不允许需要人工风险判断的操作，例如不合格 target 强制通过。

### 16.4 OnlyModule

`-OnlyModule` 只运行指定模块，不自动补跑依赖。它面向维护和开发，不适合新人首次部署。错误跳过 SSH、防火墙、证书或最终验收顺序可能让 VPS 失联。显式模块按当前角色和状态重新判断可用性，不会被历史协议变更的模块清单静默过滤；如果模块不适用会直接说明原因。显式模块成功只表示本次所选模块完成，不代表整套部署已经提交。

### 16.5 本机个性化配置

通用文件可提交 Git：

```text
config/app-defaults.json
config/client-layout.default.json
```

个人文件被 Git 忽略：

```text
config/app-defaults.local.json
config/client-layout.local.json
```

`app-defaults.local.json` 可只覆盖需要的字段，例如本机归档根目录或可选 Mihomo Alpha 路径。稳定测试核心来自项目 vendor 目录。不要把真实节点秘密放入通用文件。
