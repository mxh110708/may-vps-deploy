# May Monitor 运维手册

适用范围：Windows 上的 May VPS Deploy 控制端、Debian 12／13 amd64 的独立 May Server／Agent，以及经过审查的 May Status 静态主题。仅交叉编译的平台不等于完成运行验收。本手册使用占位符；真实地址、端口、UUID 和凭据只保存于私人归档。

本轮状态与资产见 [M8／M9 实施记录](MONITOR-M8-M9-2026-10-26.zh-CN.md)，功能与验收边界见 [M4／M5](MONITOR-M4-M5-2026-10-25.zh-CN.md) 和 [M6／M7](MONITOR-M6-M7-2026-10-26.zh-CN.md)。在正式候选发布及配套 Deploy 安装前，旧桌面可能尚无文中新增动作，不能据此直接拼接远端命令绕过归属检查。

## 先辨认组件与归属

Server 保存节点身份、用户、历史、探测任务和告警；Agent 采集与回传，Deploy 是操作控制端，关闭 Deploy 不应停止采集。Tunnel／反向代理提供 HTTPS，属于独立恢复范围；Route 负责代理流量和自动故障切换，两者没有自动联动权限。

操作前核对实例、SSH 主机密钥、受管组件、实际版本、安装 UUID、运行状态和私有档案。显示名不是唯一身份。发现文件摘要变化、非受管布局、符号链接、已有待处理事务或回复不明，先执行只读核对，保留故障证据，不重复点击安装／应用。

默认关闭远程终端、任意命令、文件控制、SQL 控制台、插件／脚本扩展和 Agent 自动更新。日常查看指标不需要开放这些能力。

## 安装和 HTTPS 接入

1. 在选定实例维护页选择 Server，审阅固定版本、架构、官方 May 资产 URL、字节数和 SHA-256。端口只监听回环，凭据不写入公开参数或命令历史。
2. 应用前备份，等待服务启动与安装归属确认。初始化链接及口令由私有归档保管，不截图或贴入聊天。
3. 独立配置 HTTPS 入口，或明确选择已有入口接管。核对证书、域名、回环来源和服务身份；不禁用 TLS 校验。仅保存接入计划不等于改动 Tunnel／DNS。
4. 在 Deploy 的接入核对中同时确认 SSH 安装 UUID 和 HTTPS 返回 UUID，拒绝重定向、错误证书及错服务。此核对没有申请 CF 权限的需要；只有新增／修改 DNS 或 Tunnel 才另行确定管理权限。
5. 为每个 Agent 在目标 Server 创建独立节点与 Token，按节点绑定。安装后检查该 Client UUID、Server UUID 和连续推进报告，不能只看进程已启动。

监测默认约三秒采样。探测任务由管理员选定目标、协议和节点；TCP 建连耗时、ICMP RTT、HTTP 到响应头的耗时不同，不将服务端向广东的探测称为用户的完整代理延迟。

## 查看数据与只读授权

Deploy 使用限定节点、带到期时间的集成只读令牌，不保存管理员浏览器会话作为读取凭据。令牌放在受保护归档，不放 URL。保存连接时固定已核验的 Server UUID；来源改变时停止接受指标。

只读监测是显式启动的页面行为。离页、隐藏、最小化和关闭时暂停／取消读取；Server／Agent 仍独立运行。完整历史、探测与规则管理在 May Web 完成。

区分等待首次采集、在线、离线、报告过期、指标无效及服务不可读取。网络／鉴权失败时保留最近有效值但撤下当前在线判断；空洞不是零负载。先检查当前时间和授权范围，再检查 Token 截止时间、TLS、服务 UUID、Agent 报告推进及 Server 日志。

当前集成读取只有一份授权。Deploy 与独立 watchdog 共用时，轮换后两端都须更新；不能假设新增第二个令牌会保留第一个。续期按服务端限定范围与最长有效期执行，更新归档并通过 HTTPS 读回后才提交。撤销后确认旧令牌被拒绝。

## Agent 地址／凭据维护

使用「维护 Agent 配置」，明确选择新 HTTPS 地址及是否更换 Token。这不是版本升级，不为同版本伪造升级。写入前使用专用接口核对 Token 归属、Client UUID 和目标 Server UUID。

保留节点身份、采集参数、TLS 检查、关闭远程控制及自动更新的策略。先做同组件快照，再更新，等待真实连续上报后同步本地 DPAPI 归档。凭据核验请求有明确 May User-Agent，不能用浏览器能打开首页代替 Agent 凭据检查。

回退原文件前先核对旧 Token 是否仍有效。旧 Token 已撤销时，恢复文件不能算连接恢复；保留「凭据恢复待处理」状态，使用有效凭据显式修复原事务。确认丢失时只读检查任务身份、阶段和当前摘要，禁止自动重放。

## 升级、备份和恢复

升级顺序：Server → 配套 Agent → Web／主题 → 配套 Deploy。Web 通常嵌入 Server；主题是额外固定资源。核对兼容矩阵，尤其新 Agent 的专用请求头与新 Server 对应，不能直接搭配不支持它的旧 Server。

升级使用固定 URL、字节数和摘要。新版本必须高于当前版本，不能借升级更改端点或身份。操作有受管事务、一致性快照及自动恢复计时器；只在安装身份、服务、HTTPS 和新报告均核验后提交。服务重启会短暂影响 Web／采集连接，Agent 会重连。

备份的恢复范围仅限所选 Server 或 Agent。Server 一致性快照包含受管程序、配置及停止写入后的数据库；恢复不是只拷贝主数据库而忽略 WAL。恢复前核对该快照归属、摘要、源版本、目标文件及外部主题资源。没有新备份先不要覆盖当前状态。

恢复动作必须选明范围，不能影响 Tunnel、Xray／sing-box、SSH 或其他实例。恢复后确认服务、安装 UUID、Token 归属、HTTPS、数据读取、历史及新上报，才将状态改为恢复完成。旧监控接管备份与当前 May 快照分别保管，不运行已经提交的旧切换回退脚本。

## 启用和更新受审主题

主题说明见独立仓库 `docs/MAY-MONITOR-2026-10-26.zh-CN.md`。只使用已审阅来源和核对摘要的 ZIP：

```text
sudo bash scripts/install-may-theme-update.sh <package.zip> <package-sha256>
```

这一步只暂存不可覆盖的静态资源并输出锁摘要，不启停服务。文件位于固定的 `/usr/local/share/may-monitor/themes/<lock-sha256>`，root 归属，普通服务账户不可写。

在 Deploy 中选择 Server 的「应用已审查的静态主题」，填写锁摘要。应用先验证全部文件，再备份和重启。网页外观入口只可修改当前受审主题配置；不启用主题市场或通用扩展。管理、初始化和恢复入口继续用内置界面。静态 JavaScript 仍是受信代码，不宣称是浏览器安全沙箱。

恢复内置界面用正常维护动作，保留指标、外观设置及静态资源。被恢复点引用的旧锁目录不得随意删除。升级 Server 保留锁摘要；变更主题代码需要新修订和新锁，不能原地替换已固定文件。

若公网页面异常，分别检查主题能力、锁摘要／权限、静态资源的真实内容与 MIME、当前 Server 版本及管理入口。缺失资源应为 404，SPA 的 HTML 200 不是 JS／CSS 成功。网络型 Service Worker 不提供离线旧监控页面，不通过自动清除用户所有浏览器数据解决更新。

## 探测与告警维护

新告警默认关闭。按节点、地区和实际探测协议选择阈值、确认次数、恢复条件、窗口、冷却和静默；目标改变后旧样本不得混入新窗口。缺失、过期、无权限和无效值显示未知，不计成健康或真实丢包。

本次新发送器仅支持明确的字面回环接收地址；接收器留空则不发送。规则仍可记录事件。真实外部渠道须另行选择并验收；不要用本地转发器绕过未授权的外发范围。

独立 watchdog 是另一进程，可运行在另一台受管主机。用专用只读令牌核对 Server UUID、响应时间和新鲜度，先证明健康，再累计失联；鉴权、TLS 和身份错误各自记录。同机检查无法覆盖整台宿主机故障。本轮隔离进程验收不等于已经安装跨主机生产 watchdog。

## 数据保留和容量

保留策略按指标层级管理分钟、五分钟和小时汇总。不要用旧 `record_preserve_time` 的单一值推断全部保留窗口。变更前核对实际行数、DB／WAL 大小、最老和最新时间、备份需求及磁盘余量。

WAL 大小短期波动不自动等于泄漏；主 DB 和 WAL 要分别看，连同 checkpoint／清理时序、同阶段中位数与峰值比较。持久化失败时保留有界待写数据并显示失败，不能伪造为零样本；磁盘不足期间强制重启仍可能丢失未落盘内容。

## 日常检查与退役

检查实际版本、服务运行、报告年龄、历史推进、磁盘、读取凭据截止日、静默到期及通知失败。不要为证明监控正常而频繁重启服务。长测结果按真实墙钟和 monotonic 时长、计划故障、维护活动及清理证据审查。

退役先保存并验证恢复材料，明确是否需要历史。停用所选旧 Agent／控制端后确认新监测持续，再结束切换事务。删除旧数据和旧备份需单独确定保留要求，不因新页面显示正常就直接删除。上游更新只按需选定提交、审查差异和复测，不自动跟踪上游开发分支。
