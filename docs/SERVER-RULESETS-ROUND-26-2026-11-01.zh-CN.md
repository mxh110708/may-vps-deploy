# 第二十六轮：服务器分类规则集与版本恢复

日期：2026-11-01。按原定主线完善服务器分类分流、规则集版本、更新与恢复，并复核现有下一跳能力。本轮随 v0.9.40 发行，不代表已经更改服务器或更新本机桌面应用。相关来源同步见[第二十五轮](SOURCE-SYNC-ROUND-25-2026-11-01.zh-CN.md)。

## 适用位置

从实例页的「分类规则库」维护私人规则快照，在既有「配置出站」中选定规则集版本和去向。分类编辑接入固定 Reality／AnyTLS 角色的服务器出站流程：Reality 同时覆盖其原受管主／备用入口，AnyTLS 只处理对应受管入口，另一协议组件保持原样。

规则用于服务器收到的 **TCP 目标**，按顺序首条命中；未命中仍走已选默认落地。UDP 保持原固定下一跳，不将一个 UDP 会话中的各个数据包重新分类。独立多入站出站模型继续使用已支持的固定下一跳，本轮没有把分类编辑扩成任意入站的通用策略引擎。

**入口机直连使用 VPS 出口，不是本机校园网。** 学校购买数据库的 IP 授权必须在客户端选择本机校园网直连；不能期待服务器上的 Direct 动作获得校园网身份。分类名称与路由动作分别选择，不自动为“学术”或“校园”设置服务器 Direct。

## 初始分类

初始规则从仓库现有已审查的校园／学术、开发及 Google 服务策略中提取，固定为 `1.0.0`。它们是可审阅的种子清单，不宣称覆盖所有网站；用户可导入自己的版本。

| ID | 分类 | 边界 |
| --- | --- | --- |
| `campus-academic-cn` | 校园与境内学术 | 现有校园与境内学术后缀，包括学校子站与 CNKI。 |
| `academic-research` | 学术研究与数据集 | 现有学术出版／数据库、Hugging Face 数据与模型资源，以及列明的 Google Scholar 域名。 |
| `developer-tools` | 开发工具与框架 | 现有开发框架与工具域名，不把数据集下载一概归入 AI 服务。 |
| `google-ai-services` | Google AI 服务 | 排除已列为学术研究的重叠项；不把 Hugging Face 或 DeepMind 研究站误归入此类。 |

重叠范围由用户明确排序决定。例如精确例外应排在较宽分类之前；不偷偷插入高优先级“修正规则”。域名后缀包含本域及其子域，`papers.example.test` 不匹配 `badpapers.example.test`。CIDR 只匹配原始 IP 目标，不新增 DNS、嗅探或另一个常驻服务。

## 规则集格式

一个规则集只有以下五个顶层字段，规则项只有 `Kind` 和 `Value`：

```json
{
  "Schema": 1,
  "Id": "research-example",
  "Name": "研究资源示例",
  "Revision": "1.0.0",
  "Rules": [
    { "Kind": "Domain", "Value": "dataset.example.test" },
    { "Kind": "Suffix", "Value": "papers.example.test" },
    { "Kind": "Cidr", "Value": "192.0.2.0/24" }
  ]
}
```

示例均为保留测试域名／地址，不对应可实际访问的数据服务。`Domain` 为完整域名，`Suffix` 为本域及子域，`Cidr` 为规范 IPv4／IPv6 网段。ID 使用1–64个小写字母、数字或连字符，名称1–100字符，版本为三段数字，可带有限预发行后缀。

每集1–2048项；一项出站策略最多32条逻辑规则，展开合计最多4096项，生成的服务器配置仍须在既有1 MiB归档维护上限内，超限在写入前拒绝。拒绝重复规范匹配项、动作字段、嵌套规则集、正则、脚本、原生核心配置、未知字段及路径注入。动作属于出站策略，不属于可下载规则集，导入者不能通过清单偷偷改变去向。

## 导入、更新与恢复

1. 打开「分类规则库」，选择「导入／更新 JSON」，粘贴公开域名／CIDR 清单。预览显示名称、版本、内容摘要以及新增／删除的匹配项。
2. 确认后仅保存私人规则库。相同 ID、相同版本只能对应同一份内容；修改内容必须使用新版本。最多保留32个版本，达到上限时明确拒绝新增，不自动丢弃历史。
3. 也可为某个 ID 配置 HTTPS JSON 来源及下载方式，再手动获取和预览。URL 加密保存，下载使用与订阅相同的30秒、512 KiB、重定向及代理限制；来源返回其他 ID 或获取期间库已变化时拒绝。
4. 下载、导入和选择历史版本均不会自动改服务器。选择库的当前版本只影响后续选择；已经部署的策略继续持有其完整固定快照。
5. 在「配置出站」添加分流规则，匹配类型选择「分类规则集（固定版本）」，明确选择分类／版本，设置默认落地、附加落地、入口机直连或阻断。可展开核对完整匹配项，并用「TCP 试算目标」检查顺序匹配。
6. 审阅名称、版本、摘要、条目数、规则顺序、目标组件及各落地出口后应用。执行继续使用既有真实协议、HTTPS 出口与必要 UDP 验收；试算只证明匹配，不等于路径可达。
7. 要恢复旧策略，在规则编辑器明确选择保留的旧版本并重新审阅应用。仅把私人库的“当前版本”改回旧版，不会回滚服务器。若要恢复整个组件配置，使用其专用恢复点，不能用不相关组件的备份。

策略归档嵌入完整规则集快照、版本和摘要，核心使用展开后的原生规则。库头变动不改变正在运行的策略，删除或修改原下载地址也不改变已归档匹配项。原生配置摘要与嵌入快照不一致时拒绝接管，先核对漂移。

本轮复核并继续使用现有已实现的下一跳矩阵：

原计划对新下一跳写的是“按真实需求增加”。本次没有新的具体协议需求，因此不虚增协议或引入另一个核心。下一跳继续使用显式 IP，域名端点及任意封装仍需另立解析／环路与真实路径验收范围；详细参数见[第十七轮](SERVER-QUIC-ROUND-17-2026-10-28.zh-CN.md)。

## 失败与恢复边界

更新规则仍通过原服务器出站事务，不新增另一套远端写入脚本。只备份、改写和恢复所选组件；SSH、防火墙的无关范围、监控、Tunnel 和另一入口协议不在本轮变更范围。

执行前复核服务器配置、节点来源和所有附加落地。默认出口验收目标必须仍走默认落地，分类不能使它被阻断或绕过；可调整显式规则顺序后重新预览。IPv6 规则与仅 IPv4 的落地／直连不兼容时拒绝，不在运行时尝试另一个出口。

失败、取消、部分写入和提交响应丢失按既有组件快照恢复或先核对事务身份。确认丢失不会重放应用。落地不可用不会回退直连。私人规则库中的新版本仍可保留用于修正后重试，不代表服务器已更新成功。
