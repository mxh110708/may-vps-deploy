## 目的与入口

从侧栏打开“线路诊断”，选择一个已保存方案、一个具体入口，以及可选的同地区客户端落地，再点击“审阅并诊断”。配置设计的连接页也提供工作台入口；有草稿改动时应先保存。该入口使用方案中的明确节点，不读取或更改正在运行的 Route／Mihomo 的组选择。

一次结果集中展示本机连接、受管远端分段、协议与网站出口、失败阶段、监测旁证和历史质量。它是一次主动检查，没有定时任务、驻留探针或新服务器组件。诊断不修改 VPS 配置、系统代理、TUN、客户端导出文件或方案的校验候选。

已有的“轻量链路诊断”及其旧记录仍可阅读；旧记录没有新的观测环境及检查版本身份，不混入新工作台统计。

## 选择路径与范围

| 项目 | 行为与限制 |
| --- | --- |
| 方案 | 读取 Deploy 私人归档中已保存的方案。多个方案彼此隔离保存历史。 |
| 具体入口 | 显式选择节点，不自动把一个地区的第一个节点当成当前使用节点。 |
| 客户端落地 | 可选同地区节点；检查入口自身出口和经落地的完整路径。额外未知上游依赖及不能由固定核心还原的组合会拒绝。 |
| 受管远端分段 | 默认勾选；仅对能够从转发／跨实例来源追溯的目标执行有限检查，需要现有 SSH 管理密钥。取消勾选保留“未测量”，不使用过去的成功记录补作本次证明。 |
| May Monitor | 默认勾选；仅使用已有专用只读连接和明确的实例→UUID绑定，单次读取。没有连接或未绑定时如实展示，不自动配置监控。 |
| 超时 | 整项150秒；单个远端段30秒，其中读取及连接脚本各有10秒控制端上限，远端套接字最多等待8秒。核心检查沿用75秒总预算，业务请求各阶段12秒；核心版本及配置校验分别最多15秒、20秒，仍受总预算约束。清理自有进程另有有限等待。 |
| 取消 | 任务栏可取消；停止后续检查，保留已完成阶段和取消阶段，关闭自有核心并删除临时明文配置。取消不算业务失败样本。 |

审阅列出整条路径及各受管分段的实例、目标地址、端口与传输，再确认是否开始。实际请求包括固定 ipify HTTPS 出口接口，以及适用路径的有限 UDP DNS；没有吞吐下载、无限重试或自动换节点。

## 分段来源与证据

独立受管转发从所选节点的 `ForwardedOrigin` 找到已应用规则。显式主备分别作为主目标、备用目标检查；备用连接通过不表示运行中的转发器当前选中了备用。

跨实例节点从 `TcpChainOrigin` 追溯前置、中转、落地，逐段使用已应用规则中的实际目标。规则中的地址已经反映所借用的 WireGuard 内层地址；不把它改回公网地址绕过通道。诊断不重新安装、重建或重启通道，也不把一次连接当成新的 WireGuard 双向应用验收。

远端步骤先用现有 SSH 信任机制连接，读取对应转发组件并核对已应用摘要，再调用既有有限分段检查。管理连接、摘要核对或目标连接失败分别保留说明；失败不会触发写入、恢复、直连兜底或变更重放。当前仅使用管理密钥；缺少密钥时提示完善连接，不自动使用保存的 root 密码。

| 标识 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 配置推断 | 归档中的入口、转发段、落地及依赖关系。 | 当前客户端选择、当前连通性或延迟。 |
| 实测：本机 TCP | 本机到入口的 TCP connect 及其耗时。 | 代理认证、网站出口、纯 ICMP RTT。 |
| 实测：远端 TCP | 已核对组件的来源实例到目标端口能建立 TCP 连接。 | 独立代理鉴权、整条业务、纯远端 RTT。 |
| 仅路由：远端 UDP | 内核能为该目标选择 UDP 路由。 | 收到任何响应、UDP 协议通过或UDP延迟；不显示毫秒数。 |
| 实测：协议与 HTTPS 出口 | 隔离固定核心通过所选协议请求网站，得到出口地址，按已配置的预期核验地址族及地址。 | 不能将合并阶段拆成独立握手时间与远端 RTT，不能证明任意网站都可用。 |
| 实测：应用 UDP DNS | 适用入口通过真实协议完成有限 DNS 往返。 | 任意 UDP 应用、吞吐或所有分类规则都正确。 |
| 未测量 | 当前没有该项独立实测。 | 不填0，不从两次短连接相减“估算”远端 RTT。 |

VLESS XHTTP 使用参数可等价表达的固定 May Core／Mihomo路径；普通受支持协议继续使用固定 sing-box。协议、传输、TLS／Reality 和下载身份沿用原模型，本轮没有扩展协议支持矩阵。Hysteria2／TUIC 入口在工作台额外要求应用 UDP 回程。

## 读懂结果和失败阶段

“所选业务路径通过”指本次业务检查通过；分段未勾选仍明确显示未测量。“业务路径通过 · 分段有待核对”表示业务通过而一个独立管理／分段检查失败，不能反过来将它写成业务完全中断。

“业务路径未通过”会标注 DNS、本机 TCP、核心准备、TLS／协商、入口协议与出口、应用 UDP、客户端落地等阶段。协议与 HTTPS 出口是合并阶段：认证错误、目标服务不可用、出口地址不符都可能在此失败，阶段定位并非根因诊断。错误详情只归纳为固定安全文本，不把核心输出、SSH原始错误、凭据或完整节点配置写入历史。

| 现象 | 建议核对 |
| --- | --- |
| 本机 DNS／TCP 失败 | 入口地址、当前网络、地址族及目标监听；不要据此直接改服务器配置。 |
| 核心准备失败 | 配套核心版本、归档摘要、合法配置和隔离监听；未执行成功的协议阶段没有连通证明。 |
| 入口协议与出口失败 | 身份、SNI、证书信任、实际目标服务和预期出口；无直连兜底。 |
| 分段管理／配置失败、业务成功 | 单独检查 SSH 或归档漂移，保留业务成功事实。 |
| UDP只有路由 | 继续看实际入口协议及应用 UDP 回程；不要把路由结果解释成“UDP正常”。 |
| 来源或观测网络变化 | 本次记录标记失效，不计入质量统计；重新保存／选择来源后重测。 |
| 未确认或旧事务 | 诊断不能替代恢复；回原维护入口先核对真实事务。 |

## May Monitor 旁证

工作台复用 May Monitor 的专用只读快照接口，不用管理员 API Key，也不新增监测任务。只显示所选路径涉及实例的显式 UUID 绑定，不能凭名称或 IP 相似自动对应。

同时展示上报时间、接收时间、在线／离线、CPU、内存与流量快照。安装身份或凭据无效、时钟异常、未绑定、缺少节点、读取失败和过期状态保留区别。快照／上报超过90秒时不会作为当前在线；历史卡片显示的是诊断当时所取的旁证，不能当作现在的实时状态。

节点在线不证明此线路正常，CPU高也不证明它造成了延迟。监测读取失败不会抹去已经成功的协议和出口检查。

## 历史与质量比较

每个方案最多保留64次记录，单次最多24 KiB、32个本机阶段和8个远端段。新记录超限时移除最早记录。历史写入独立的加密文件 `private/route-diagnostics/<scheme-id>.private.json`，使用应用既有账号保护，不写入方案的节点或候选，不作为订阅／导出的内容。

历史条件可以在界面按记录选择。统计同时要求以下内容一致：

1. 路径身份：连接、认证、预期出口、受管来源、实际分段及已应用组件摘要。
2. 观测环境：当前设备、活动接口、源地址、网关和 DNS 的摘要；只存摘要，不存接口名、本机地址或网关原文。网络变化保守地开始另一个序列，不把跨网络数据拼在一起。
3. 检查配置：固定核心、版本与发行归档摘要、检查接口、应用UDP范围和诊断格式版本摘要。即使版本名相同，换了核心归档也不合并统计。

显示同条件业务完成样本数、其中通过数，以及各成功阶段的中位数、P95、峰值和样本数。P95使用排序后向上取整的最近秩；少量样本的P95常等于峰值。失败样本保留在完成数量中，但其失败等待不混进成功耗时分布；取消、失效和缺少检查版本的记录不进入质量统计。

分段 TCP connect 单独统计；UDP路由、未测量和推断不产生延迟序列。统计描述这些主动短连接，不提供连续可用率、带宽或网络SLA，也不自动驱动 Route 的故障切换。

重开工作台会按当前来源标记旧记录是否失效，改显示名称不会改变连接身份，改认证、落地、分段或出口会使旧结果不能代表新配置。写入结果前重新读取已保存方案；其他进程在诊断期间改了连接参数，本次记录会标记来源变化，不能拿开始时的表单快照继续声称当前成功。“清空此方案诊断历史”须审阅当前文件摘要；审阅后出现新记录则拒绝删除。清空只处理本机此方案记录，保留实例、客户端和May Monitor数据。格式损坏、未知版本或超大历史不会被新结果覆盖。
