# 第七轮：分享链接导出

本轮补齐配置设计器的分享出口。已保存或正在编辑的方案可以按当前输出筛选、命名和顺序生成节点分享列表，逐项显示支持情况，选择可分享节点后复制或保存为新的文本文件。支持纯文本和整份列表的 Base64 编码，不提供在线订阅托管、二维码或自动推送到客户端。

## 使用方式

1. 打开「配置设计 → 生成与导出 → 分享节点链接」。
2. 核对可分享和无法分享的数量、每个节点的说明。只有能够保留完整连接参数的节点可以勾选。
3. 选择纯文本或 Base64 列表；已启用的输出名称、排除条件和排序同样生效，原节点不改名。
4. 点击「复制已选链接」，或填写 `.txt` 文件名、点击「保存已选链接」并选择文件夹。关闭对话框不复制、不保存，也不修改方案或候选配置。

链接含连接凭据，Base64 只是编码。预览只显示名称、协议和能力说明，不直接展示完整 URI；结果不进入任务历史或日志。由用户点击复制后才写入剪贴板。

## 范围和限制

| 类型 | 支持情况 |
| --- | --- |
| Shadowsocks AEAD | SIP002，Base64URL 用户信息，完整保留方法与密码 |
| SS2022 | 按 SIP002 使用百分号编码的 method/password，保留多用户身份链，不把用户信息整体 Base64 化 |
| VLESS | TCP 的 Reality + Vision，保留 UUID、SNI、TLS 指纹、公钥、short-id 和受支持 ALPN 列表 |
| AnyTLS | 基础 TLS、SNI、密码，保持证书校验开启 |
| 连接端点 | IPv4、带方括号的 IPv6、DNS / IDN；显示名与凭据按 URI 字段编码 |
| 列表 | 最多 200 个节点，解码内容最多 256 KiB；输出顺序由方案决定 |

客户端依赖入口的落地节点、`detour` / `dialer-proxy` 不转换为独立直连链接。ECH、证书文件或证书固定、无法表达的 TLS 版本约束、插件、额外拨号参数和未支持传输也会被阻止。不会为了得到一个能导入的链接而删除这些设置。Deploy 自身部署的 AnyTLS 带 ECH，因此仍需使用完整客户端配置导出。

服务器已经应用的落地和目的地分流在服务器端生效，入口链接可以分享，但不会携带服务器配置。预览明确说明其依赖服务器当前状态；客户端分组、DNS 和业务规则也不包含在链接中。

同时存在 Clash 与 sing-box 原生参数时，先核对两者的完整可表达连接是否一致；不一致则阻止该节点分享。仅有其中一种原生配置的受支持节点也可处理。每个生成的链接都会通过现有导入器重新解析，并与规范化的原连接逐项比较，不能只靠 URL 语法通过就导出。

## 来源和文件保护

打开预览时锁定方案摘要。复制或保存前若节点、筛选、命名、格式来源或候选等方案内容已经变化，需要重新预览。受管实例在部署、恢复或凭据变化后，原节点来源校验同样阻止导出；不会查询外部订阅或自动同步服务器。

选中不支持、重复、未知或已移除的节点会报错，不静默丢弃。没有选择可分享节点时复制和保存禁用。混合列表会明确显示无法分享节点，用户能看清当前只选择了哪些节点。

文件导出只创建新的 `.txt` 文件，不覆盖原文件，不把 URI 列表伪装成客户端 JSON / YAML。写入前检查应用和私人归档保护目录、链接路径及来源；同目录私有临时文件写完后再次核对，再以不覆盖方式原子移动到目标。出错时清理本次临时文件，不修改用户已有文件。

## 验证

- 61 项 .NET 专项断言通过，包含四类链接的重新导入比较、Unicode 和保留字符、IPv6、SS2022 身份链、原生配置一致性、链路和 ECH 等高级设置拒绝、格式和数量限制、筛选命名排序、来源变更、受管凭据变化、路径保护和不覆盖文件。
- 完整 .NET 回归共 1529 项断言通过，包含前六轮真实 AnyTLS／Reality 多落地回环、逐落地 TLS / 出口探针及真实 Python 客户端生成；Windows 缺少链接权限的既有检查明确跳过。
- 原生分享界面 11 组检查通过隐藏合成实例验证；复制使用隔离接收器，保存只使用合成目录，不写用户剪贴板，不使用鼠标或激活前台窗口。具体最终结果见本次发行验证记录。
- 完整 `ValidateProject` 执行成功，未重复运行其内部的 `Run-Tests.ps1`。本轮同步将前几轮新加的两组远端 Bash 行为测试接入 Linux CI。

测试不代表所有第三方客户端都理解同样的 URI 扩展，也不替代真实网络连接验收。分享的实现没有连接生产 VPS、修改系统代理、关闭 TLS 校验或安装应用。
