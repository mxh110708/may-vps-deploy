# 第四轮：Reality 固定下一跳与链路维护

本轮把第三轮的服务器固定下一跳扩展到 Xray Reality，并补齐来源提示、升级、凭据轮换和恢复的链路保护。仍使用按需 SSH 和既有任务事务，不增加后台 Agent、定时同步或监控数据库。

## 支持范围

客户端继续连接原来的 Reality / AnyTLS 入口。入口服务器连接保存的 Shadowsocks / SS2022 落地，再由落地访问网站。这里只修改服务器出站，不要求客户端增加 `detour` 或 `dialer-proxy`。

| 入站组件 | 本轮覆盖 | 固定下一跳任务重启范围 |
| --- | --- | --- |
| Xray Reality | 受管的主、备用端口，以及已有 IPv4 / IPv6 监听；全部用户、TCP 与 UDP | `xray.service` |
| sing-box AnyTLS | 原有 `anytls-in` 单入站；全部用户、TCP 与 UDP | `sing-box-anytls.service` |

Reality 的所有受管监听共同使用一个下一跳，不支持每个端口设置不同落地。保留原 UUID、Reality 密钥、目标站点、Vision、监听地址及端口；不会重新生成整份入站配置。

下一跳仍限于已保存方案中的完整 Shadowsocks 原生节点：AES-128-GCM、AES-256-GCM、ChaCha20-IETF-Poly1305 和三种 SS2022 方法。SS2022 的服务端密钥与用户密钥组合完整保留。必须使用明确的 IP 端点；插件、域名端点、客户端链式拨号和其他高级字段尚不支持。

服务器必须已经纳管并启用所选协议，且具有配置归档与摘要。自定义路由、额外入站、缺失监听、端口漂移、无归属的保留标签和被外部编辑的受管规则都会阻止执行。可用范围由当前实际布局决定，不能仅凭归档中的协议名称判断。

## 桌面操作

1. 在「配置设计」保存落地节点，核对来源和连接参数。
2. 打开「实例 → 日常维护 → 服务器固定下一跳」，选择 Reality 或 AnyTLS 的「配置出站」。
3. 表单显示「目标入站组件」、当前下一跳、来源状态和受影响范围。当前节点仍存在时会自动预选；切换组件会显示对应组件的独立设置。
4. 选择保存的下一跳，填写或核对「预期网站出口 IP」。这是落地访问网站的出口，不是入口机的地址。非法地址会保留表单并提示修正。
5. 进入审阅，核对主备／双栈范围、落地端点、出口地址族、服务中断与恢复行为。确认并执行后才连接远端。
6. 移除时单独审阅「恢复原出口策略」。原策略是直连的，明确移除后恢复直连；链路故障本身不会触发这一行为。

表单和最终审阅中的返回都不启动远端任务。切换组件不修改来源方案，也不更改另一个组件的设置。

落地防火墙需预先允许入口 VPS 的来源地址。此任务不登录落地、不修改其白名单，也不接管服务商 ATT IPv6 的地址租约或脚本。

## 来源状态与同步

服务器使用执行时审阅过的参数快照。方案、订阅和受管来源的变化不会自动写入服务器。

| 状态 | 展示与处理 |
| --- | --- |
| 与快照一致 | 当前保存节点的完整摘要和受管来源均匹配 |
| 名称、参数或出口标注变化 | 提示服务器尚未同步；重新审阅并执行后更新 |
| 节点或方案删除 | 提示服务器仍使用原快照；可另选下一跳或移除固定链路 |
| 受管连接、凭据或状态变化 | 提示先重新提取受管节点，再审阅更新；旧来源不能用于新变更 |
| 来源歧义、不可读或无引用 | 显示明确状态，保留服务器现状，不自动猜测替代节点 |

状态检查只在打开相关页面或表单时读取本地加密方案和受管归档，不访问订阅 URL、不轮询服务器。已有服务器路由不因本地来源删除而被清除；如果落地实际凭据已轮换，旧快照可能失效，需要人工审阅更新。

## 配置与执行边界

Reality 原有路由必须是受支持布局：`direct` / `block` 出站、`AsIs` 策略和可选的 IPv6 拒绝规则。应用增加归属明确的 `may-fixed-next-hop` 出站和两条规则：先拒绝所选网站出口的相反地址族，再将全部受管 Reality 入站交给下一跳。原有规则和出站顺序保留；移除时只删除摘要匹配的受管部分。

SS 连接使用的地址族与网站出口地址族独立。例如用 IPv4 连接落地，仍可选择经其 IPv6 访问网站。域名的最终解析与出网由落地决定，必须通过实际代理出口和 UDP 验收，不能仅凭标注判定成功。

任务沿用六阶段：只读核对、组件恢复点、应用候选、独立验收、归档、提交。远端脚本按显式组件选择固定路径和服务，未知组件立即拒绝；候选由远端实际核心校验。写入前再次核对原文件摘要，原子替换后只重启所选组件。

Reality 候选使用 Xray 自身的配置检查；AnyTLS 使用对应 sing-box 检查。服务命令、启用及运行状态、文件类型和路径链接均需匹配。Xray 配置组权限沿用服务运行用户对应的组。

实际验收继续使用固定版本的 sing-box 与 Mihomo，核验 HTTPS、预期公网出口及 UDP。固定下一跳变更不允许将跳过或部分完成当成成功。失败或取消按本次组件恢复；写入或提交回复丢失先核对任务身份和事务状态，不自动重放写入。

操作选项和归属元数据只记录引用、摘要、显示名称、端点与预期出口，不保存明文下一跳密码。实际参数从加密方案读取，服务器配置留在既有私人归档；审阅及任务历史不显示凭据。

## 升级、凭据轮换与恢复

- 升级或入站凭据轮换前，若该组件已有固定链路，先核对远端实际配置摘要和路由归属；发生漂移时，在建立变更前停止。
- 维护保留已有下一跳及其参数，只修改目标组件的内核或入站凭据。轮换 Reality UUID 或 AnyTLS 密码不会把落地凭据一起轮换。
- 归档前重新检查受管出站及规则。如果升级丢失下一跳，不能将损坏配置作为新基线提交。
- 维护涉及的固定链路须完成实际协议验收；不完整时触发既有恢复流程。
- 协议备份恢复同步恢复对应路由元数据及验收记录。组件范围的失败恢复只还原该组件的路由记录，保留同实例其他组件的记录。
- 卸载一个组件只清理它自己的路由记录；不会连带删除另一入站的固定下一跳。

新增固定下一跳任务建立单组件恢复点。既有升级、轮换和通用协议备份恢复仍沿用原来的 `Protocols` 事务范围，本轮没有把这些旧维护流程全部改成单组件事务。恢复仍受原有备份兼容和外部编辑保护约束。

## 本地验证结果

- Tests 与 Desktop Release 构建通过。完整 .NET 回归通过 **1201 项断言**，较第三轮新增 **67 项**。包括两类入站的固定链路、来源凭据变化、升级、轮换、手动配置恢复、配置漂移、丢失回复、取消及失败恢复。
- 真实 Xray **26.3.27** 与随应用固定的 sing-box 在回环地址上建立 Reality 主／备入口 → SS2022 多用户落地。TCP 与 SOCKS UDP 转发通过；停止落地后请求失败，目标未收到绕过下一跳的请求。原有 AnyTLS → SS2022 真实回环也在完整回归中通过。
- Reality 主备双栈配置的四个监听和规则范围由行为测试覆盖；实际回环使用主、备 IPv4 监听，没有把它记录为公网或 IPv6 连通验收。测试用本地 Go TLS 1.3/H2 目标；初始 Schannel 目标的握手不兼容已在测试夹具中替换，没有放宽产品的 TLS 验证。
- Bash 行为测试 **19 项，17 项通过、2 项跳过**。跳过项是本机无符号链接创建权限的两类组件链接检查，保留给支持该权限的平台。其余覆盖配置替换、摘要冲突、校验期间漂移、核心拒绝、停用服务、服务命令不符、未知组件和 Xray 服务组权限。systemd 和核心命令使用临时替身，没有操作系统服务。
- 原生 WinUI 隐藏回归 **12 组通过**：既有 AnyTLS 六组，以及当前 Reality 节点预选、组件范围切换、主备双栈审阅、来源变化提示、来源删除提示和取消隔离。截图已检查；退出证明显示 0 次窗口激活、0 次前台采样、无托盘注册、无全局输入注入、无未完成任务；测试实例已关闭。
- NuGet 漏洞元数据服务不可达的 `NU1900` 警告仍存在，在线依赖审计未完成；本轮没有更换依赖或锁文件。
- 两个远端脚本的 `bash -n` 检查、452 个文本文件的秘密扫描、`git diff --check` 和新增源码的尾随空白检查通过。本机未提供 ShellCheck，因此未执行其静态规则检查。

真实 Reality 回环是可选本地测试：Windows 下将 `MAY_TEST_XRAY` 指向经过摘要校验的官方 26.3.27 核心后，完整 .NET 回归或 `--reality-outbound-only` 才执行它；缺少环境变量时明确跳过。该二进制仅放在忽略的开发缓存中，不随应用新增分发。默认 CI 的可移植配置和事务测试仍执行，不能将其等同于真实 Reality 回环已经在所有 CI 平台运行。

本轮没有连接生产 VPS、变更现用配置、安装、推送或发布应用。本地回环与模拟维护不证明真实公网、落地白名单或生产升级成功；这些仍需在明确授权的目标上完成实际验收。
