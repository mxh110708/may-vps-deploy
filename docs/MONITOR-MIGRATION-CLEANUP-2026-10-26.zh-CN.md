# May Monitor 迁移后清理与配套发行

当前状态：本文保留当时的实施和候选发行历史。2026-10-27 的正式组件、生产升级、跨主机检查及邮件范围修订见[首阶段收尾记录](MONITOR-CLOSEOUT-2026-10-27.zh-CN.md)；不把下文旧版本或“尚未”描述当作现在的运行状态。

本轮目标：Deploy 0.9.37、Server 0.1.0-rc.8、Agent 0.1.0-rc.4、Web 0.1.0-rc.4、May Status 2.2.2-may.17。它们是新的、互相锁定的发行资产；不覆盖生产 RC6／RC3 和 M5 冻结资产，也不以发布动作代替生产升级。

## 清理前确认

读取本机已保存的加密只读连接，只输出校验结果：六个节点均明确绑定，服务安装 UUID 已固定。读取现有冷备份的内存副本：账号全部为 May bcrypt-SHA256 格式；配置库使用当前 key/value 结构，没有旧 client_infos、负载、GPU、ping 历史表。检查过程没有写入私人归档或生产服务。

## 删除与保留

| 范围 | 删除的迁移兼容 | 现在的行为 |
| --- | --- | --- |
| Deploy | 只读连接及接入计划允许空服务 UUID 的早期路径、相应可选字段提示 | 保存时必须明确核验服务身份；每次读取都比较响应身份；旧的未绑定记录拒绝使用，保留原文件供操作者核对。 |
| Server | 固定盐 SHA256 旧密码校验和登录后自动转换 | 只接受 May 自适应密码格式；密码重置仍可使用，拒绝的登录不改原密码记录。 |
| Server | Komari 旧配置、通知设置、时间戳、节点及历史表导入引擎、导入目标配置和进度分支、未使用的旧通知模型 | 不再扫描或导入旧记录；遇到明确不支持的旧库结构，在 AutoMigrate 前拒绝启动，不静默丢弃历史。 |
| Web／Server | Komari 1.x 升级通知、读取旧启动版本的专用 RPC、旧导入页面和翻译 | 新管理员进入正常引导；不再等待旧升级提示。 |
| Agent | 启动时扫描并删除旧 Komari update-motd 脚本的桥接 | 不再触碰旧产品的登录脚本；当前监测、重连及安全边界保留。 |
| May Status | 已由上一轮移除的旧 HTTP／RPC 回退；本轮再移除按返回延迟样本估算丢包的回退及旧兼容类型名 | 探测失败率只用 May 的计数加权指标；接口失败／缺数显示缺失，不把抽样比例当成真实探测失败率。 |

以下属于正常使用或数据身份，继续保留：当前 May 数据库结构升级、升级前备份、选定组件恢复、事务归属／丢失确认复核、主题设置 short、归档加密标识及 Go 模块来源信息。它们不是一次性迁移导入器。Deploy 的独立 Komari 组件维护能力也没有被当作迁移补丁整体删除；历史归档仍可核查，恢复范围仍受组件边界约束。

## 验证与证据口径

- Deploy 完整 Core 边界／工作流回归，包含未绑定／错误身份、凭据范围、真实回环 HTTP／TLS、取消和归档保护；正式包另验证原生运行时启动。未触及安装器实现，不重复安装本机应用。
- Server 完整回归及受影响包 race 检查；新测试覆盖新库／当前库允许、旧结构只读拒绝、弱密码拒绝后可以正常重置、数据库结构升级路由仍需管理员身份。首次清理后暴露的测试夹具初始化依赖已经纠正，不以删除失败测试代替修复。
- Agent 全量回归与连接相关 race；Web 编译、lint、监测／引导／安全／Service Worker 检查；主题类型、lint、构建、打包契约及缺失统计行为复核。
- 本机 NuGet 漏洞元数据请求出现 NU1900，不能把该步骤称为依赖漏洞扫描通过。Web 保留原有 lint 警告；发行门禁还检查 GitHub 上对应提交的工作流结果。
- Server 与 Agent 的 Linux amd64 进行本机隔离启动；arm64 仅交叉编译，Server 检查静态链接；Windows Agent 仅编译，不安装服务。
- 每项发行记录提交、版本、构建工具、附件长度和 SHA-256。Server 固定 Web 的确切提交；Deploy 固定正式 Server／Agent 的实际附件散列。公开后重新校验下载、tag 和源提交。

M5 的 24 小时资源结论只适用于原冻结 RC4／RC2。历史 NeedsReview 和单点证据限制保留，后续取时边界复现及当前修正见 [异常复核](MONITOR-SNAPSHOT-ANOMALY-2026-10-26.zh-CN.md)。本轮不把新候选包宣称为已完成另一轮 24 小时长测。真实告警外发与独立跨主机 watchdog 仍待选定接收端和实际验收。

## 更新顺序与范围

源码和发行附件分别公开；先发布 Monitor 依赖，再发布引用其散列的 Deploy。现有 May 配置和主题设置继续使用。用户手动更新桌面应用；生产 Server、Agent、主题的升级是另一个明确操作，不由 GitHub 发布自动触发。旧 Komari 数据仅作为离线恢复材料，不再提供应用内自动导入入口。
