## 真实安装、启动与回退

在 BERO 上分别使用 Debian 12（bookworm）和 Debian 13（trixie）完整用户空间的独立 KVM 虚拟机，每台 1 vCPU、512 MiB 内存、6 GiB ext4 磁盘、BIOS GRUB，无外部网卡。两者均使用 `6.12.111+deb13-amd64` 作为原内核种子，再安装本轮同一份固定包。没有把 BERO 宿主切换到测试内核。

| 安装预检：磁盘、内存、GRUB、当前启动镜像 | 通过 | 通过 |
| 固定包 SHA256、Debian 身份及仅新增一个内核的 APT 计划 | 通过 | 通过 |

512 MiB 客体由原内核识别的 `MemTotal` 为 475,232 KiB。预检原先把 480 MiB 作为系统识别量门槛，会误拒绝这种正常预留内存的客体；已改为建议 512 MiB 实体内存，系统识别总量至少 384 MiB、当前可用至少 256 MiB。两台实际安装时可用内存均超过门槛。它不保证任意业务负载下的资源余量。

测试驱动屏蔽客体串口登录服务，使用 journal 与 console 输出，避免登录程序重置同一终端中断 QA 进程。此调整仅用于隔离客体。所有客体安装、重启、验收和回退都调用当前 `kernel-runtime.py`、`kernel-engine.py` 与 `bbr-runtime.py`，没有替换安装逻辑或放宽摘要、包身份、GRUB 检查。

## 应用和回归验证

- Windows 与 Debian 13：内核运行时 22 项、维护者构建工具 3 项均通过，覆盖来源和包摘要拒绝、私有上传、跨文件系统复制、防重放及限定构建资源。
- .NET 核心：934 条边界与工作流断言通过；真实本机 SSH/SFTP 验证二进制流式上传、私有权限和取消清理。Windows 缺少符号链接权限的两项按原规则跳过。
- `ValidateProject` 主回归通过：893 条主断言及交互、工作台、审计、更新、GUI、可用 Python/Bash 检查；Linux 权限回归单独执行。
- 真实 Windows QA 安装、升级、重启验收及保留/清除数据卸载通过 45 条断言。原生界面确认 v3 只有固定预编译包，所有下拉选项继续禁止滚轮改值。
- 安装后的 `kernel.deb` 大小和 SHA256 与固定清单完全一致。旧浮动版本脚本未进入安装目录。完整对应源码作为单独附件发布，并纳入 SHA256SUMS，不放入每个客户端安装目录。
- BERO 宿主运行内核、启动身份及 Komari、Komari Agent、cloudflared 状态均另行核对；本轮未安装宿主内核或重启宿主。

## 验证边界与维护

客体 canary 是隔离的测试服务，不等同于真实 Komari/Xray 业务验收。无外部网卡的 KVM 验证不证明公网吞吐、丢包改善、客户 VPS 的主/救援 SSH 恢复，或 Hyper-V/VMware 的实际驱动启动；Debian 12 原生 6.1 内核切换也未在本轮重新实测。没有测试硬件失效等极端故障。生产升级仍须通过应用的独立检查、安装和重启审阅，以及真实管理连接验收。

EFI/Secure Boot、DKMS、容器、LVM/加密启动及无法明确识别的 GRUB 布局继续拒绝自动安装。当前固定提交不是发行版安全维护的替代品。后续升级固定包须重新完成来源锁定、预编译、校验和适用环境验证，维护流程见 [预编译包维护](GOOGLE-BBR-PREBUILT.zh-CN.md)。
