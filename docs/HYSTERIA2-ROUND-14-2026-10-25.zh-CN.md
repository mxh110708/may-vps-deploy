# 原计划第十四轮：Hysteria2 部署与维护闭环

日期：2026-10-25。本轮沿用第十三轮的独立入站模型，补齐 Hysteria2；May Monitor M1–M3 仍是独立支线。本轮不推送发布、不安装桌面更新、不操作生产实例。

## 已实现

实例页「通用多入站 → 管理入站」可创建 Hysteria2 入站。每个入站有稳定身份、UDP 监听、共享或独立密码用户、证书引用和出站引用，使用仓库固定版本及摘要的 sing-box 核心。现有 Reality、AnyTLS、SS2022 服务和配置仍按各自范围管理。

| 部分 | 行为 |
| --- | --- |
| 部署 | UDP 地址／端口检查、独立 systemd 服务、root 私有配置、固定核心、TLS 与 SNI 检查、多用户认证。 |
| 维护 | 启用、停用、移除、用户轮换、证书替换、Salamander 开关与密码轮换、显式固定核心更新、同范围失败恢复及丢失确认核对。 |
| 客户端 | 按用户、连接地址族和地区组生成 Clash/Mihomo、sing-box 节点；保留密码、SNI、速率、混淆设置与来源身份。 |
| 验收 | 固定核心使用真正的 Hysteria2 出站完成鉴权及 HTTPS 请求；不要求服务端开放 TCP，不以 UDP connect 或普通 TCP 成功代替。 |
| 防火墙 | 主机受管规则只为 Hysteria2 放行 UDP；保留 SSH 和其他入站。停用／移除时更新本次受管范围。 |
| 来源保护 | 凭据、证书、参数或核心身份改变后，旧客户端来源失效；停用或未完成恢复的入站不能作为有效来源导出。 |

Hysteria2 采用 TLS 1.3。证书需匹配 SNI，私钥需匹配证书；启用时检查证书有效期。证书申请与续期仍使用已有外部流程，本轮支持导入和替换，不静默修改 DNS 或其他服务的证书。

## 配置与操作

1. 在已受管且没有未完成事务的实例中添加 `Hysteria2 / QUIC`。填写本机监听地址与独立端口。停用状态也保留端口，不能被其他受管组件抢占。
2. 在「用户与凭据」添加密码用户，在入站中勾选引用。每个用户分别实际验收；一名用户通过不替代其他用户。
3. 在「证书」导入证书链及私钥，选择对应证书和 SNI。服务端材料保存在加密私人归档及远端 root 0600 配置中；systemd 单元不写密钥，通过 `LoadCredential` 提供运行配置。
4. 默认上、下行均为 `0`，使用自适应 BBR；正数模式须同时填写上、下行，范围为 1–100000 Mbps。界面速率统一按**客户端视角**：客户端上行对应服务端接收上限，客户端下载对应服务端发送上限。界面中的数值不会直接当成测速结果；固定值应按实际线路保守填写。
5. 可开启 Salamander，混淆密码与用户鉴权密码分开保管。客户端生成时同步，改变后需重新生成或更新相关节点。
6. 选择本轮已有出站模型支持的直连或代理来源；检查影响范围后确认。新监听的来源范围由监听地址和防火墙决定，访问由协议用户鉴权控制；不自动继承旧落地的来源白名单。
7. 「审阅」显示 UDP/QUIC、SNI、速率模式、Salamander 状态、用户、证书、出站及受影响入站，不显示认证密码。执行预检、快照、应用、用户验收与提交五阶段。
8. 在配置设计中使用「添加独立入站节点」，选取已启用并完成用户验收的来源。构建两种客户端候选并通过固定核心检查后，再按既有流程导出或发布到权威配置。

系统内的受管防火墙放行不代表服务商控制台的安全组已放行。外部安全组须由维护者允许相同 UDP 端口；本轮不修改服务商面板，也不改变控制端系统代理或 TUN。

### 固定核心更新

「更新当前包内固定 sing-box 核心」是显式任务，使用当前应用包中已有的固定版本与 SHA256，不查询或自动安装上游 latest。相同版本不重复更新，也不接受降级或同版本的摘要替换。

该核心由独立 Hysteria2、AnyTLS 和 SS2022 入站共享，审阅会列出实际影响范围；Xray 核心固定身份保留。配置先校验，再按范围切换核心和服务，完成各用户验收后提交。失败恢复旧核心引用及配置；已校验的新缓存可保留为不活动文件，不代表运行服务。旧固定角色核心不在此次更新范围。

本轮核心更新的范围计算、来源失效与失败恢复通过模拟事务测试；没有把未发行的后续核心版本在生产或虚拟机中安装后宣称验收通过。虚拟机实际使用的是仓库当前固定核心。

## 真实验收与故障边界

服务启动就绪检查核对 systemd `MainPID` 对应的 UDP 监听，其他进程占用相同端口不能充当就绪证据。应用验收再启动固定 sing-box 客户端，限定生成的 Hysteria2 出站及相应路由，禁止诊断配置含直连回退。只有协议请求成功才记录匹配的 `ValidatedProtocol=hysteria2`；失败不保留成功来源资格。

测试补齐了：UDP-only 服务、双用户、Salamander、真实 HTTPS、经加密协议的 UDP nonce 回显，以及错误用户密码、错误混淆密码、不受信证书和 UDP 阻断反例。UDP 被阻断且同端口存在可连接 TCP 服务时仍须失败。应用 UDP 回显是本轮隔离测试的证据，日常部署验收仍是经 QUIC 的 HTTPS，未声称每次部署都测过全部 UDP 应用。

窗口取消或验收失败恢复本次入站及主防火墙范围，不重启无关入站。收到不了提交确认时核对同一事务身份；已提交则报告确认丢失后的已完成，不能重放写入。最近检查失败、证书或凭据变化、停用、删除以及未确认恢复会阻止旧来源继续使用。

Hysteria2 不能作为既有**仅 TCP 透明转发**的目标。QUIC 不会因一个 TCP 端口可连接就变成可用协议，本轮对此显式拒绝；UDP 编排、端口跳跃、Realm、Gecko、外部认证及分享链接导入另行安排。

### Windows／WSL 虚拟机测试通道

当前主机不能直接可靠地把 Windows UDP 测试流量送到 WSL 内的 QEMU 映射端口。虚拟机测试因此仅在 Windows→WSL 的隔离测试边界使用带随机令牌的回环 TCP 数据报封装；WSL 到 QEMU 客体仍使用真实 UDP，客体 Hysteria2 不提供 TCP 监听。该测试通道有固定目标白名单、连接数量、帧长度和超时限制，随测试停止，不修改主机路由、系统代理或防火墙。

这验证了协议、服务、客体防火墙及生命周期，不代表 Windows→公网的原生 UDP 路径、运营商网络、IPv6 WAN、吞吐或长期运行均通过。Windows 原生 UDP/QUIC 正反例由独立的回环测试覆盖。模拟证据、原生回环和虚拟机证据不能相互替代。

## 后续评估：TUIC 与服务器出站

| 方向 | 本轮评估与后续条件 |
| --- | --- |
| TUIC | 固定客户端／核心具备协议基础，但服务端模型仍需独立 UUID+密码用户、证书、QUIC 参数、拥塞控制和会话策略，以及与 Hysteria2 同等级的实际正反例和恢复测试。没有把已有客户端字段当成已实现部署。 |
| Hysteria2／TUIC 服务器下一跳 | 需先补来源引用、真实 UDP 下一跳及失败时不回直连的验证。当前入站可选择既有出站类型；本轮没有扩大服务器代理出站类型。 |
| 其他 Xray 下一跳 | 现有 Xray 适配以 Shadowsocks／SS2022 为明确边界；VLESS、AnyTLS 等要独立完成参数转换、目标认证和链路恢复，不以 sing-box 可解析代替。 |
| 在线订阅托管、配额与计费 | 仍按原计划，在明确需求后实施，不因本轮协议接入自动加入范围。 |

后续协议扩展建议先做 TUIC，再补 sing-box 的 Hysteria2 服务器下一跳，最后按实际目标增加其他 Xray 下一跳；这属于评估顺序，尚未自动启动新一轮。TUIC 需要 UUID 与密码并存的身份模型，不能直接复用本轮单密码用户；验收须覆盖错误 UUID、错误密码、不受信证书、UDP 阻断、应用 UDP 和局部恢复。若后续接入，0-RTT 保持关闭，拥塞控制、鉴权等待及保活分别显示有效配置，见 [sing-box TUIC 服务端说明](https://sing-box.sagernet.org/configuration/inbound/tuic/)。其他服务器下一跳需单独映射鉴权、TLS、Reality 与传输参数，参照 [Xray VLESS 出站结构](https://xtls.github.io/config/outbounds/vless.html)并以届时固定核心实测，不从上游新文档推断当前版本已兼容。
