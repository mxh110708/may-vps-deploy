# 网络调优（WinUI）

部署和协议安装不隐式调优。在“网络调优”选择已纳管实例，先审阅诊断对象、关键方向和流量预算，再只读采集，依据证据试调并原路复测。生产操作仍需通过应用的审阅与恢复流程。

## 角色、方向与路径

| 场景 | 实际测量 | 配置边界 |
| --- | --- | --- |
| 入口代理 | 本机 → Reality / AnyTLS → 测试目标 | 按关键方向比较；具备充分证据时才能试调发送缓冲上限 |
| 中转代理 | 本机 → 所选入口 → 已纳管 SS 落地 → 测试目标 | 读取落地归档构造真实双跳；仅调整入口，不登录或修改落地 |
| 落地代理 | 本机 → SS 落地 → 测试目标；另查 VPS 自身出站稳定性 | 只读诊断；仍只启用 fq 与可用 BBR |
| 纯 TCP/IP 转发 | 只读观察本机转发开关和网络状态 | 不以本机 BBR 解释转发 TCP，不做精细推导或公网吞吐测试 |

入口/中转默认“双向均衡”，也可选择下载优先或上传优先。所有模式均测双向、分别验收；均衡模式允许任一方向取得充分证据支持的收益，另一方向仍须通过退化保护。优先模式只把选中方向的收益用于保留候选，但另一方向仍受保护。下载看匹配入站连接的发送侧，上传看下一跳连接的发送侧。Xray、sing-box 应用代理通常会终止一段 TCP，再发起下一段 TCP，不能与透明 IP 转发混为一谈。

入口连接可同时选 IPv4 + IPv6。“落地访问网站使用的 IP”独立控制落地到目标网站的出站，可选仅 IPv4、仅 IPv6 或两者都测；只有已经部署 IPv6 出口时才提供后两项。双出口落地的新表单默认两者都测，已有保存偏好保留。具有原生 IPv6 地址不等于已经部署 IPv6 出口。

两项均选择双栈时展开为 4 条路径：IPv4 连接/IPv4 出站、IPv4 连接/IPv6 出站、IPv6 连接/IPv4 出站、IPv6 连接/IPv6 出站。结果分别展示，不合并速率或平均重传率。共用的发送缓冲/拥塞控制/队列只调整一次；入口/中转应用后复测所有所选路径，任一退化、未完成或证据不足均恢复共享配置。IPv6 不通不会自动用 IPv4 冒充通过。中转的“入口→落地连接地址族”仍使用用户明确选择的单一地址族。

中转可分别选择入口连接地址族、入口到落地的连接地址族和落地出口地址族；最终出口必须与所选落地归档匹配。不能选自身、未受管或待恢复实例。落地归档变化会使已审阅操作和待执行计划失效；应用不会为测试修改对端、防火墙或 SSH。

VPS 直出测速不等于用户线路，也不能证明中转瓶颈在本机出口。网页目标返回慢、对端限速、国际路径拥塞与本机缓冲不足必须区分；不从单个异常对端生成全局限速配置。

## 采集与参数证据

只需填写套餐标称下载/上传带宽、共享/独享/突发类型；未知可留空。RTT 自动采集，标称带宽不会用测速峰值或虚拟网卡速率替代。

测量使用隔离 sing-box 回环代理，不改变系统代理/TUN、不控制全局鼠标、不激活窗口。下载分别使用 Cloudflare、Hetzner 两个独立提供方，每个做三轮单连接和四连接测试；上传使用 Cloudflare 公共端点。另对两个提供方各做三次新 HTTPS 连接，从发起到读到前 1024 字节，包含连接/TLS/响应的启动代价，不伪称纯 TCP RTT。传输期间采集响应时间和 VPS 资源。

`ss -tinOe` 按选定入站端口与 SSH 来源，或明确的下一跳地址/端口筛选连接。以 socket cookie/身份、相同 boot ID 配对计数。采样连接消失、重建、计数重置、列表截断和缺失值不会当作零重传。SSH 与代理入口来源不同、短流太快而采不到连接，可能只得到基础建议，这是证据边界。

每个方向的发送字节差量须覆盖本轮请求载荷的 70%–150%；覆盖不足或混入大量其他流量时不用于精细判定。IPv6 从实际连接到所选入口的本地 TCP 连接观测来源，并同时筛选地址族；无法唯一确认来源或采不到同一 socket 时不猜测。IPv4 SSH 的来源不能直接代替 IPv6 测试来源。该校验不能消除所有同对端业务干扰，因此结果仍称重传参考。全机 SNMP/接口丢弃计数仅作诊断，不决定新版精细调优。

只有关键方向覆盖至少两个目标、多数匹配样本确认发送缓冲受限时间占比至少 10%、重复短连接完整、负载延迟稳定、真实 TCP RTT/内存/现有上限/套餐齐全，才生成试调候选。发送缓冲限制占比使用本轮 `sndbuf_limited` 与 `busy` 时间差量，不能使用连接整个生命周期的百分比冒充本轮证据。

候选仅提高 `tcp_wmem.max` 与 `net.core.wmem_max`，按匹配路径的保守速率、RTT、内存预算确定上限。接收缓冲、最小/默认分配、初始窗口、TFO、TCP 内存与连接策略保持原值。不依据一个测试端点调整三十项 sysctl，不默认设置 `initcwnd 32` 或全局 HTB 限速。

**当前公共上传仅一个提供方，不能证明全局上传收益。** 上传优先时保留基础建议；均衡或下载优先时，可依据多目标下载证据生成发送上限候选，同时用已有的重复上传样本核对当前上传路径的退化。上传证据缺失则不生成精细候选，不宣称上传已全面优化。落地机始终只应用 fq+BBR。

实际 fq 队列以 `tc` 为准。`mq` 根队列可保留，其发送叶队列使用 fq。已有 fq 参数保留；遇到 cake、htb、netem 或无法完整恢复的布局时，写入前停止。BBR 原有版本/v3 的选择及独立内核升级机制保持不变。

## 比较和恢复

比较政策为 `LossFirst.v3`，证据版本 `Directional.v2`；旧报告需重新采集：

1. 前后匹配相同路径指纹、关键方向、协议、地址族、套餐、测试档位、内核/boot ID 和高峰窗口。单轮跨越高峰边界、对端变化或旧版证据不能用来保留新参数。
2. 关键方向前后各至少 1000 个有效发送数据段。重传变化容差为 `max(0.2 个百分点, 基线比例 × 20%)`。任一独立目标明显恶化，不能被其他目标的改善掩盖。
3. 重传明显改善须在多个目标、多数同轮配对中重复；只在一个目标变好或单轮尖峰不足以归因于参数。
4. 重传差异接近时，均衡模式任一方向、优先模式选中方向的吞吐须提高至少 10%，且每个独立目标至少 2/3 的同轮样本支持。上传/下载重传分别检查，任一方向或目标恶化均不能被另一方掩盖。
5. 短连接启动按目标分别检查 p95：高于原值 15% 且超过 15ms 的容差时不自动保留。负载减空闲的附加延迟超过 `max(原排队延迟 × 1.25, 原排队延迟 + 10ms)` 也不保留。单/多连接速度下降超过 30% 属严重代价；轻微差异的速度收益仍检查其他方向 20% 的速率退化及原有延迟门槛。
6. 所有模式都保护另一方向：任一目标单/多连接速率下降超过 20% 均不保留。双栈分别核验，允许某路径没有同一缓冲瓶颈，但它仍须完成双向、短连接和排队退化检查。未确认收益或信息不足时，恢复原运行值、文件和实际队列；保留前后报告与具体理由。

## 流量预算与覆盖

| 档位 | 整个流程的总预算 |
| --- | --- |
| 快速 | 128 MiB |
| 标准（默认） | 1 GiB |
| 深入 | 4 GiB |
| 扩展 | 10 GiB |
| 最大 | 20 GiB |
| 自定义 | 64–20480 MiB |

同一个总预算覆盖选中的全部连接/出站组合、上传/下载及应用前后两轮。约 20% 预留给探测与协议开销，其余前后各半，再按路径数平分。即最大档单轮单路径有效载荷最多 8 GiB，2 条路径各最多 4 GiB，4 条路径各最多 2 GiB；整个流程有效载荷最多约 16 GiB。总时限也按路径数平分。一次只采集不应用时，复测的一半不会自动追加到基线。

实际计费还取决于 TCP 重传、加密封装、读取预收、业务干扰及服务商单/双向口径；20% 预留不是网络计费硬限额。界面和审阅均显示这一边界。应用只严格限制自己的有效载荷请求预算；不静默重试或提额，不把每条路径都当作拥有独立 20 GiB。中断、再次手动采集或重新应用属于新的明确操作。

标准档本轮总路径时限约 360 秒，快速 120 秒、深入 900 秒、扩展/最大 1800 秒；双栈共享该时限，另加有限 SSH 采集。预算与时间先到即停止。下载和上传使用最多 8 MiB 的有限请求分块；上传只保留 64 KiB 流式生成缓冲，不按总预算申请内存。Hetzner 必须遵守 Range，否则停止；不自动重定向或无限下载。

档位名称不保证“完整测试”。传输阶段少于 1 秒不算持续样本，高速线路、小预算或高 RTT 仍可能覆盖不足。多个方向、独立目标和时间样本分别检查；不能因为耗完预算就标为通过。UDP 只取五个可用性样本，不估整条线路丢包率。

新版不直接导入或执行第三方脚本。方法参考 [tcpfit 源码固定提交](https://github.com/Kylin010/tcpfit/tree/38fbf5af30daf87735f2ffbc5e0905033ee2b86e) 的实测、重复验证和原值恢复思路；该提交使用固定 150ms RTT、宽范围 sysctl 与初始窗口策略，我们未采用这些默认值。网络参数语义以 [Linux 内核说明](https://www.kernel.org/doc/html/latest/networking/ip-sysctl.html) 和 [ss 手册](https://man7.org/linux/man-pages/man8/ss.8.html) 为准。

## 测试时间

主要使用地时区提供中国、日本、新加坡、美国东西部、德国、英国和 UTC 等常用选项，也可选择自定义并填写 IANA / Windows 时区 ID。高峰说明实时显示所选时区及开始、结束时间；无效或空白时区、时间会立即提示，执行前再次校验。

字段标为“24 小时制”，按整点填写小时数；旁边明确说明开始为 0–23、结束为 0–24，结束 24 表示次日 00:00。例如 20–24 为 20:00 至次日零点，22–2 为 22:00 至次日 02:00；开始与结束不能相同。测量与安排补测均按主要使用地计算，并遵循所选时区的夏令时规则。

早间数据不会转换为预测的晚间数据。没有同路径、同协议、同地址族、同使用地时间窗口的近 7 天晚高峰证据时，建议明确标记“未覆盖晚高峰”。有历史证据时，将保守容量用于建议，原始实测速率仍单独保留。

“审阅晚高峰补测”安排下一次窗口开始时的一次性测量；可以关闭到托盘，但应用必须运行。它不自动应用建议、不新装 Windows 服务、不打开凭据或身份确认弹窗。应用关闭而错过时间会记录“未执行”，中断的计划不自动重试；需要用户重新安排。归档协议变化时停止旧计划。其他任务占用超过开始后的 30 分钟窗口也会记为错过，避免后来突然开始测速。

## BBR 版本与恢复

“BBR 版本”默认选择 **VPS 原有内核自带版本**。应用沿用它启用 fq 与可用 BBR，不强制更换内核。选择 **BBR v3** 后出现独立检查、安装和重启入口；选择本身只保存本地偏好。

BBR v3 只使用随应用提供的固定预编译包。由 MXH 在开发机从官方固定提交构建、验证，应用发布时更新。当前提交为 `90210de4b779d40496dee0b89081780eeddf2a60`，日期为 2025-03-18，基础内核为 6.13.7。没有最新提交选择，也不会在 VPS 下载完整源码或安装编译工具。

[Google 官方仓库](https://github.com/google/bbr/tree/v3)提供源码；预编译产物属于 MXH 构建，不称为 Google 或 Debian 官方二进制发行。v3 源码分支也不等于最新 Linux LTS 或最新安全维护内核。界面显示真实提交日期和基础版本，目标基础版本低于当前运行内核时拒绝安装；不把第三方内核或自行拼接的补丁冒充官方 v3。

来源校验包括 HTTPS 官方地址、完整 Git 提交和源码树、`git fsck --strict`、实际 Makefile/BBR 文件 SHA256，以及源码中的 BBR v3 标记。当前固定提交没有上游签名，不声称存在 Google 包签名链。构建记录保存输入/最终内核配置摘要、源码身份、产物大小与 SHA256；安装前再次核对 Debian 包名称、版本、架构和依赖计划。

预编译安装要求根目录至少 2 GiB、启动目录至少 512 MiB 可用空间，建议至少 512 MiB 内存；考虑内核预留后，系统识别总量需不少于 384 MiB、当前可用不少于 256 MiB。这是预检门槛，不是任意服务负载下的资源保证。包通过流式 SFTP 上传，私有临时目录权限 0700、文件 0600。远端先核对文件与父目录所有权、普通文件、字节数和 SHA256，再复制到独立事务目录；跨文件系统也不依赖 rename。安装前再次验证包身份、摘要及 APT 模拟计划，仅允许新增该内核。断线不重放安装。

维护者在本机 Linux/WSL 或 BERO 构建并随应用更新固定包，参见 [预编译维护说明](GOOGLE-BBR-PREBUILT.zh-CN.md)。源码构建程序只用于开发机；服务器仅接收固定包、校验、安装与重启验收。

操作步骤：

1. 检查实际 BBR、系统、虚拟化、驱动、GRUB 布局、当前内核配置、内存与磁盘空间。
2. 审阅源码提交、基础版本、材料和安装包 SHA256、实际安装方式及资源要求。固定版上传内置包，经远端再次验证后独立安装，原内核继续运行。没有全局升级、长期第三方仓库或自动删除旧内核。VPS 不执行源码构建。
3. 安装成功后单独审阅重启。使用单次新内核启动项，验收前默认仍为旧内核。
4. 新内核启动后，核验真实 BBR v3、原服务以及主/救援端口的 root 和管理用户 sudo 连接，通过后才设新内核为默认。
5. 已验收的 Google 源码受管 v3，可在应用提供更新的固定包后审阅升级，安装与重启分别确认；保持上一内核和最初系统内核。目标较旧时拒绝隐式降级，外部安装且没有受管记录的 v3 不自动覆盖。
6. “回退上一内核”回到本轮升级前的版本；“回到 VPS 原有内核”回到最初记录的系统内核。二者分别核对启动镜像和管理连接，保留内核包与服务配置。从原有内核重新启用已保留的目标也不重复安装。

`bbr` 名称本身不能证明 v3。应用同时检查已加载模块版本，以及回环真实 TCP 连接的 `TCP_CC_INFO` 版本证据；没有足够证据或两者冲突时显示“版本未确认”，拒绝当作 v3 验收。选择 Google 源码 v3 调优还须有本应用的 Google 来源、对应内核镜像摘要及已提交验收记录，不能把预装第三方 v3 当成 Google 来源。沿用 VPS 外部已有内核可选择原有版本；若仍运行本应用升级的内核，会要求先审阅回退。

内核事务独立于协议、网络调优和监控恢复，只处理受管 Google 源码预编译包，不提供旧第三方内核事务的兼容处理。应答丢失、退出、取消后保留事务，通过核对状态沿用远端结果，不重发安装、重启或提交。VPS 不具备在线查询和编译流程；开发机编译工具不注入远端执行载荷。

当前自动升级支持 Debian 12/13 amd64、完整虚拟机的 BIOS GRUB、可明确识别的 ext2/3/4 环境块。EFI/Secure Boot、容器、DKMS 驱动、LVM/加密启动环境及不明确的 GRUB 布局会拒绝自动升级。已验收的 Google 来源 v3 可直接核验并应用网络配置。

新系统已进入用户空间但 5 分钟未提交时，独立保护任务会重启回旧内核。内核未能启动到用户空间时，服务无法执行：需在服务商控制台重启，单次项消耗后的默认仍是旧内核。这个边界在重启审阅中明确显示。

写入前保存受管 sysctl 文件、实际运行参数、接口队列及受管持久化服务，启用限时回滚。写入时使用事务身份与锁；结果不明确时先核对状态，不重复执行。恢复既还原文件，也还原内核运行值；发现外部更改或链接则停止覆盖并保留材料。网络恢复不包含协议、SSH、防火墙和监控数据。

精细建议绑定测量文件摘要与实例协议身份；超过 24 小时、记录变化、运行内核/参数/队列漂移后需重新测量和审阅。传统 PowerShell CLI 的历史调优模式仍按其原有计划运行；本页自动采集流程属于新的 WinUI/.NET 实现。
