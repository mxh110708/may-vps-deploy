## 适用场景与前提

用于服务商已将同一台受管服务器的现有 IPv4／IPv6 替换为新地址后，同步 Deploy 管理的依赖。实例目录、组件身份、用户、凭据和业务用途保持原归属。本功能不调用服务商 API，不配置网卡、路由或安全组，不修改 Cloudflare DNS，不切换本机代理，也不重载客户端。

开始前需要：

1. 原实例已完成部署或接入，私人计划、状态、凭据及必要服务器配置归档齐全。
2. 原管理地址已有独立核对并保存的 SSH 主机指纹。新地址必须呈现同一指纹；SSH 与 SFTP 的每次连接均核对，包括已受信的新地址。握手不符时拒绝，不用换址确认接受重装后的新密钥。
3. 服务商已分配新地址，SSH 可从新 IPv4 管理地址进入，所需地址与端口已放行；关联实例也可管理。只替换已有地址族，不通过此入口新增或删除 IPv6。
4. 参与实例和相关线路没有待恢复事务。地址归属不唯一、新地址属于另一实例，或受管来源已被本地修改时，先解决冲突。
5. 先备份完整私人数据集。换址记录与主机信任、方案、节点组、隧道及线路记录应一起保留。

同一台机器改地址和重装系统是不同操作。主机指纹变化时，应独立核验新系统并按接入流程处理，不能编辑信任文件绕过校验。

## 使用入口与审阅

在「实例」中选择原实例，打开「修改地址」，填写新 IPv4；IPv6 未变时保留原值。地址未变或输入不是规范单播地址时保留表单和输入，不创建事务。「检查并审阅」会显示地址前后差异、实际参与实例、受管组件和本地来源范围，以及只报告的外部节点。

确认前核对下一跳、独立入站、TCP／UDP 转发、运行与持久白名单、WireGuard 两个槽位及其相邻线路。执行顺序为身份核对、备份、新旧来源并存、应用和验收、移除旧来源、再次验收及提交。

预览使用隔离私人影子归档推导来源，不写原实例或创建待恢复事务。影子目录在结束时清理。取消审阅保留原归档。

审阅固定参与计划、状态、凭据文件摘要、相关来源、原主机身份和远端程序。确认前发生变化，旧审阅失效。建立恢复点前再次核对；同步后到移除旧来源、提交之前继续核对本地文件，避免采用后续外部编辑。

## 自动发现与同步范围

| 对象 | 本轮处理 |
| --- | --- |
| 实例计划 | 更新已有 IPv4／IPv6；保持原目录和稳定身份。 |
| 固定协议配置 | 限定替换已有受管 Reality、AnyTLS、SS2022 配置中的连接／绑定地址，归档实际远端字节与摘要。 |
| 服务器下一跳 | 更新默认去向、附加落地、分类规则引用及原生配置；继续实际协议验收。 |
| 独立入站 | 重新投影受影响绑定和来源摘要，保留原核心、入站／用户身份、凭据及启停状态；不新增或删除身份。 |
| TCP／UDP 转发 | 更新目标、主备目标、来源白名单和验收来源；主备组重新采集实际健康证明。 |
| WireGuard | 同步受影响端点或源地址，覆盖两个独立槽位；保留密钥、内层地址、端口与受管程序身份。 |
| 双端隧道／跨实例线路 | 纳入相连拓扑的完整参与集合，重算相邻加密段依赖摘要，重新进行双向挑战和整链验收。另一端未改地址也参与核对。 |
| 客户端方案／节点组 | 更新受管来源与连接摘要、组成员摘要及版本引用；保留自定义名称、节点 ID、布局和导出位置，清除旧候选。 |
| 外部节点与导出文件 | 报告归档中可识别的外部节点影响；不接管无受管来源的节点，不扫描改写任意外部文件。完整配置仍须单独生成、校验、审阅差异并导出。 |

只改连接和来源字段，不对所有文本做查找替换。TLS SNI、证书名称和展示名保持原意；来源列表只替换明确地址或 `/32`、`/128`，不推断扩大网段内某台机器的归属。线路中的前置源地址及显式客户端来源列表也纳入处理。

WireGuard 最终资源摘要在远端预检时从实际固定程序与目标材料推导，据此重算线路依赖和客户端来源。应用后真实摘要必须与预测一致，不能沿用换址前的旧证明。

非受管防火墙、外部单元覆盖、链接、缺失归档、外部文件修改或不支持的布局都会阻止执行。特别是 `PreserveExisting` 下受影响的 SS 来源白名单不能由本事务自动改写；须另行安排受管接入或维护，不能假定外部规则已经同步。

May Monitor／Komari 的服务地址、Tunnel、Cloudflare DNS 和证书域名不在此次自动替换范围，通过各自维护入口独立核对。

## 执行阶段

| 阶段 | 行为与完成条件 |
| --- | --- |
| 身份 | 从目标管理地址连接，每次保持原 SSH 主机指纹；不符不进入写入。 |
| 预检 | 核对 Debian 12／13 amd64、实际资源、运行状态、受管单元和防火墙；推导目标摘要并复核依赖闭包。 |
| 备份 | 加密记录本地原字节、当前摘要、参与集合，锁定参与实例；远端保存组件文件、权限、属主与启停状态。 |
| 过渡 | 所有受影响来源白名单同时容纳新旧地址，目标地址保持原值。 |
| 应用 | 同步连接目标和端点，保留过渡白名单；同步私人计划和来源，读取实际远端摘要。受影响连接可能中断并重建。 |
| 验收 | 检查管理入口、协议 HTTPS／出口及适用应用 UDP、附加落地、独立入站策略、转发／主备、WireGuard 双向挑战和跨实例整链。 |
| 收敛 | 移除旧来源，再做适用验收及运行／持久规则核对。 |
| 提交 | 复核本地来源及实际资源，确认各远端提交；仅此时记录新管理地址的已核对主机身份，清除待恢复标记。 |

相邻地址可能被 nftables 合并为等价网段。本轮按来源地址范围比较，接受等价显示，额外放行地址仍属于漂移；对比逻辑没有扩大实际白名单。

失败、取消或确认丢失不能按成功继续。变更请求不会在异常后自动重发；先读取事务阶段与一致性，仅在实际阶段已完成且材料相符时接纳丢失确认，其余进入原事务统一恢复。

## 恢复、确认不明与外部编辑

原实例和参与实例会显示「恢复换址」，从原事务拥有者统一核对。参与实例的其他运维任务在待恢复期间被阻止；不要删除标记、换入口或重复执行原任务。

本地记录在私人根目录 `address-changes/<事务ID>.private.json`，加密保存原字节、当前摘要、目标来源、参与集合和已尝试快照的主机。远端在 `/root/vps-deploy-address/<事务ID>/`，目录 `0700`、文件 `0600`；含敏感快照，不可作为公开附件。

远端恢复点固定建立事务时的完整程序及嵌入模块。后续状态、应用和恢复从固定程序运行，核对原摘要与权限；应用更新后不借用新脚本解释旧快照。大程序和私人文档经私有临时文件传输，避免进入环境变量、命令参数和进程列表。

恢复先检查全部本地文件，再反向恢复已尝试的远端，最后恢复本地原字节。只接受原前态、本事务已写入态或已记录目标态；外部内容、权限／属主变化、链接、未知版本或越界路径都会阻止恢复。不覆盖外部编辑来解除待恢复状态。

建立远端快照中断时，只有实际资源仍全部等于原材料才能确认未发生变更；删除已应用事务的日志不能使其变成“未执行”。恢复确认不完整时保留记录和标记，修复可管理性／冲突后从同一入口续做。

恢复只回退本事务受管配置与私人材料，**不撤销服务商已经完成的公网地址分配**。即使原计划字节恢复，服务器仍可能只有新地址；原事务保留新管理地址和原主机指纹用于核对。确认材料已恢复并解决失败原因后，可重新审阅新换址任务，不重放旧事务。
