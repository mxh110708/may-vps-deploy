# 第二十轮：完整 XHTTP 客户端与配套流程

2026-10-29 建立，2026-10-30 收尾。本文适用于本轮开发源码，当前正式发行基线仍为 v0.9.38；本轮源码随第二十一轮统一提交推送，不代表已发行、安装桌面更新或修改生产节点。第十九轮的 HTTP/2／stream-one／Mihomo 是当轮历史范围，不能继续当作当前源码的能力边界。

本轮联动 May Core、May Route 和 Deploy。服务端仍使用固定 Xray 26.3.27；客户端使用配套 May Core 或可等价表达的 Mihomo 1.19.32。上游 sing-box 1.14.2 没有 May 的 XHTTP 扩展，仍用于其他协议及服务器服务，不被偷偷替换。

| 项目 | 本轮行为 |
| --- | --- |
| 模式 | stream-one、stream-up、packet-up、auto；TLS auto 选择 packet-up，Reality auto 在无独立下载时选 stream-one，有独立下载时选 stream-up。 |
| TLS | HTTP/1.1、HTTP/2、HTTP/3；前两者可使用 TLS 1.2 及以上，HTTP/3 为 QUIC／TLS 1.3。 |

| 高级字段 | 固定 Xray extra 清单、填充、请求头、会话／序号、上传数据位置、分片与 XMux；未知字段及无效组合在审阅前拒绝。 |

| 导入与输出 | 完整原生来源、标准 VLESS XHTTP URI、订阅预览和合并；分享时重新导入比对，无法完整还原则要求完整配置输出。 |
| 来源与维护 | 连接参数、下载身份、用户、证书和固定核心变更使旧来源失效；只验收和恢复所影响的独立入站。 |
| 运行方式 | 使用同一个 May 核心，无第二常驻转换进程；地区／业务组、按需探测及故障切换继续使用完整出站。 |

新建入站仍默认 TLS／HTTP/2／stream-one，避免无意改变既有模型。用户可以明确选择其他合法版本／模式；导入来源按原值保留，不把所有节点强制改成新默认值。

服务器下一跳和客户端 XHTTP 落地编排不在本轮新增范围；本轮受管 VLESS XHTTP 入口使用直连出站。后续编排按第二十一轮单独设计，不从单入口连接成功推断任意多跳已验证。

## 新建受管 XHTTP 入站

1. 选中已接入的受管实例，打开「通用入站」，新建 **VLESS / XHTTP**。独立入站不会覆盖原固定角色或其他实例服务。
2. 设置监听地址／端口、用户引用、启用状态、SNI 和直连出站。监听地址必须属于该实例，端口须与对应 TCP／UDP 服务无冲突。
3. 选择 **TLS 证书** 或 **Reality**。TLS 引用覆盖 SNI 的有效证书链与匹配私钥；Reality 使用专用密钥、short ID 和握手目标。两类身份不混用；切换 Reality 时清除证书引用，并归回唯一适用的 HTTP/2。
4. 选择 HTTP 版本和模式，填写 Host／路径；需要高级参数时编辑固定 extra JSON。无效 JSON 保留原输入并显示错误，不丢弃后继续保存。
5. 审阅协议、安全、版本、模式、Host、路径、用户／证书引用、影响入站和防火墙范围。查询参数值、UUID、私钥和自定义头的内容不进入任务摘要。
6. 执行应用。流程安装或核对固定核心、验证配置、限定影响服务／防火墙，并逐用户及地址族执行真实代理 HTTPS 与应用 UDP 回程。只看到进程 active 或 UDP 监听不能作为最终成功。
7. 在「配置设计」按用户和地址族添加已验收入站，选择 May 原生（界面格式名 SingBox）、Clash，或双输出；生成候选、对应核心校验、审阅后再导出到自己的权威文件。

外层 HTTP/1.1／2 监听 TCP；HTTP/3 监听 UDP，远端就绪检查会核对对应服务 MainPID 拥有的 UDP socket。它不要求同端口的 TCP 监听，也不会把其他进程的 UDP socket 当成功。服务商侧防火墙须按实际传输另行确认。

## 高级字段与默认行为

受管入站的高级对象为 `Options.Transport.Extra`，使用 Xray 的 camelCase。客户端原生对象为 `transport.extra`，下载端点单独放在 `transport.download_settings`。字段定义和完整原生示例见 [May Core 指南](https://github.com/mxh110708/may-route-core/blob/custom-main/docs/MAY-XHTTP.zh-CN.md)。

| 类别 | 固定字段 |
| --- | --- |
| 请求头 | headers、noGRPCHeader |
| 填充 | xPaddingBytes、xPaddingObfsMode、xPaddingKey、xPaddingHeader、xPaddingPlacement、xPaddingMethod |
| 元数据 | uplinkHTTPMethod、sessionPlacement、sessionKey、seqPlacement、seqKey、uplinkDataPlacement、uplinkDataKey、uplinkChunkSize |
| 上传与服务端 | scMaxEachPostBytes、scMinPostsIntervalMs、scMaxBufferedPosts、scStreamUpServerSecs、noSSEHeader、serverMaxHeaderBytes |
| XMux | maxConcurrency、maxConnections、cMaxReuseTimes、hMaxRequestTimes、hMaxReusableSecs、hKeepAlivePeriod |

范围接受整数、min-max 字符串或 from／to 对象。拒绝类型错误、倒序、超出资源限制、无效位置以及冲突的并发／连接数设置。GET 上传及 header／cookie 上传数据须明确选择 packet-up。保留服务端专用字段不等于客户端也执行这些服务端功能。

May 默认一个共享惰性连接池，空闲 30 秒回收，不主动周期 PING；显式 XMux 值控制其上限、轮换与保活。这是本地资源策略，省略／全零不照搬 Xray 的随机轮换默认。实际 HTTP 请求次数与逻辑 VLESS 会话分别计数，轮换不打断仍有响应体的旧连接。

### 独立下载的正确位置

受管入站表单不会把 `DownloadSettings` 当成另一项服务器安装任务。独立下载描述的是客户端连接关系，应从完整客户端来源或标准 URI 中导入。标准 Xray URI 把它放在 `extra.downloadSettings`，其中是地址、端口、安全与 xhttpSettings；转换后是 May 的结构化 `transport.download_settings`。

上下行必须到达同一个后端会话系统；两台互不关联的 Xray 不会因客户端指定了两个地址而自动共享会话。每侧单独验证 SNI、证书或 Reality 密钥，下载侧错误不能沿用上传侧身份。

### 与 Mihomo 的差异

Mihomo 使用 kebab-case `xhttp-opts`／`reuse-settings`，其下载对象只独立覆盖所支持的地址／TLS、Host、路径、请求头及 XMux。May 可单独设置更多下载元数据；若无法等价投影，保留 May-only 节点并在能力预览中说明未选客户端缺少原生配置，不能删字段生成双输出。

Mihomo 的 session-table／session-length 是其客户端扩展，保留为 Clash-only 原生来源，不伪造 May 配置。显式 TLS 版本约束、UDP 编码、额外拨号选项等不能被目标格式等价表达时，也应选择完整原生输出。外部来源的 XHTTP 编辑保留连接数据，名称／分组可独立修改；连接改变后重新读取完整来源，受管来源则从入站重新生成。

## 导入、分享与候选校验

1. 从完整 May／Mihomo 来源或 `vless://...type=xhttp` 导入，在预览中确认地区组、模式、版本及能力；错误行不会混入候选。
2. 双来源同时存在时核对两份连接语义，包括独立下载身份。存在冲突则要求重新读取，不任意选一份。
3. 分享生成后会立即重新导入并比较完整连接指纹。只有完整往返等价时才提供 URI／订阅内容；额外 TLS／拨号字段无法进入标准链接时，完整原生配置仍可保存和输出。
4. 候选使用对应验证核心：普通原生配置用官方 sing-box，包含原生 XHTTP 时用具有 `vless-xhttp-round20` 能力记录的 **may-core**；Clash 输出仍用固定 Mihomo。缺少 May 核心、来源证明、版本或归档摘要不匹配时直接失败。
5. 参数解析成功只证明格式；受管来源仍须经过真实连接验收。配置生成、导出、安装和生产切换是不同动作，不会因为本轮测试自动执行后续动作。

### 配套验证资产

`vendor/test-cores/windows-amd64/checksums.json` 分开记录官方 sing-box、Mihomo 和 May 验证核心。May 条目包含版本、能力、二进制归档 SHA-256、源码提交、源码树摘要、完整对应源码 ZIP 摘要、工具链、构建标签及选项。本次统一推送将来源固定到 [Core 提交 9e40d486a](https://github.com/mxh110708/may-route-core/commit/9e40d486a0cb58d411ebaa2196d853b2aafa1dce)，构建时工作树干净；资产仍标为未发行开发版本，不等于应用 Release。

开发者使用 `scripts/Build-MayXhttpValidationAsset.ps1 -CoreRoot <MayCoreSource> -GoExecutable <Go1.26.8>` 重建。脚本先复制公开源码，再从该快照编译并一同归档，避免构建期间的工作树修改令二进制与源码不符；CLI 不使用的独立客户端 Git 子模块不放入快照。构建需要固定 Go 依赖或已验证的模块缓存，不修改系统 PATH。

`Sync-ClientValidationAssets.ps1 -Offline` 校验现有资产；缺少 May 核心时只能从匹配的固定资产或源码构建恢复，不能改用上游核心“通过”XHTTP 校验。此资产不是第二常驻服务，也不会安装到 Route。

## 维护和恢复

| 变化 | 执行与保护 |
| --- | --- |
| 用户／UUID | 重验引用用户的入站，旧用户来源失效。 |
| 路径、Host、版本、模式、extra | 更新受影响入站和监听协议；原来源摘要失效，重新生成候选。 |
| TLS 证书 | 只更新引用它的 TLS 服务，Reality 和无关 SS2022 不重启。 |
| Reality 密钥／short ID | 更新该 Reality 服务和来源，不重启 TLS 服务。 |
| 下载身份 | 属于客户端完整连接指纹；改名不改变指纹，下载地址／SNI／元数据变化会改变。 |
| 失败或取消 | 恢复本次受影响配置、服务及防火墙，保留无关服务；只凭 HTTPS 但缺少要求的 UDP 证据不能提交。 |
| 提交响应丢失 | 先核对事务／身份与状态，不自动重放变更。 |
| 重启与移除 | 重启后重新做实际验收；移除后核对自有服务、事务和监听清理。 |

网络重置／重载会关闭旧连接与受限上传队列，新的连接重新鉴权。XMux 到限轮换与整个出站重载含义不同：前者保留旧活动响应，后者应中断旧活动连接。两者分别验证，不能为“不断流”保留已经失效的核心连接。

## 后台资源优化与取舍

2026-10-30 按用户最新要求，本轮以功能交付为主，只保留有明显资源收益或其他明确正向贡献的调整。所有新增测试必须后台执行、有总超时并清理自有进程；不显示或激活窗口，不用强制 GC、工作集修剪或关闭硬件加速改变结果。

此前 16 项串行的显示／隐藏四场景测试调用了 `showInactive()`，违反后台要求，已中止并作废；不能用其未完成样本宣称改善或验收。900 秒正式观测未执行，对应未使用脚本已删除。保留原始中止记录，不把等待时间当作长测证据。

本次只实施一项局部优化：packet-up 的 POST 缓冲从默认逐次 append 扩容改为按需倍增，容量以该请求的已校验上限封顶。小会话不预分配完整 POST，不缓存已确认的大缓冲，队列、请求内容和回压上限保持一致。

| 负载 | 修改前分配／操作 | 修改后分配／操作 | 分配变化 | 构造耗时中位数变化 |
| --- | --- | --- | --- | --- |
| 4 KiB 小请求 | 8,754.5 B | 8,753 B | 基本不变 | +1.3%，不作为收益 |
| 1 MiB 上传，32 KiB 分块 | 5,497,841 B | 2,100,585.5 B | −61.8% | −65.5% |
| 8 MiB 上传，32 KiB 分块 | 43,675,364 B | 19,657,076.5 B | −55.0% | −54.5% |

方法：同一 Go 1.26.8、`GOMAXPROCS=2`、同一 benchmark；修改前后各四次，交换执行顺序，按各项中位数比较；每项自动校对接收字节数。命令行进程全部隐藏，总预算 90 秒，实际约 11 秒。`BenchmarkPacketUpload` 将模拟确认延迟设为零以测量分配／复制成本，不含 TLS、网络 RTT 或应用前端。其运行命令为 `go test -tags with_utls,with_quic ./transport/v2rayxhttp -run '^$' -bench BenchmarkPacketUpload -benchmem`；版本对比须分别构建改动前后测试二进制。

保留此项，因为大上传分配和构造耗时均有明显下降，且调整后真实连接矩阵通过。没有据此宣称整应用常驻内存、CPU 占用或 WAN 吞吐下降相同比例；它们未在本次重新测量。未实施额外常驻采样、跨界面的资源调优或无收益的兼容分支。

## 外部环境与后续边界

受控反代覆盖 HTTP/2／3、独立 Host／路径／元数据，以及 TLS／Reality 的混合下载身份；错误下载身份或反代故障不能静默回退。公网服务商、特定 CDN、Cloudflare 普通代理和 Tunnel 未在本轮验收；需要分别确认 TLS 终止、协议、端口、缓冲和超时，不能把受控测试当成任意 CDN 承诺。

协议／客户端字段、局部资源对比、源码推送、应用发行和生产验证分别跟踪。本次统一推送不创建 Release 或安装更新，不能沿用过去某次安装授权自动执行。
