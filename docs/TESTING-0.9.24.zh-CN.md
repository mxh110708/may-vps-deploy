# v0.9.24 双向、双栈与总预算验证

日期：2026-10-14。

本轮调整网络调优页面和测量/验收边界，未重新调优生产 VPS。沿用 v0.9.23 的角色划分、双跳构造、发送上限证据和网络组件恢复范围。

## 本地验证

- .NET 回归包括双向均衡默认值、下载优先仍保护上传、均衡允许一方有重复收益但禁止另一方明显退化、单目标上传不宣称全局收益、持续样本不足回到基础建议。
- 真实工作流调用分别生成 IPv4、IPv6 测量报告；合并报告不平均速率。共享参数只应用一次，复测信息不足时恢复 Network 范围，不扩大到协议或监控。
- 验证所有预设和自定义总预算，双栈与前后复测共同分摊；拒绝超过 20 GiB、负数、小数和溢出值。最大有效载荷合计约 16 GiB，20% 为开销预留，不能当作计费硬限额。
- 流式传输使用本地 HttpMessageHandler 接收约 17 MiB 的合成上传，检查请求分块、精确总量与 64 KiB 写入上限。端点失败和取消不会重发已预留的数据；没有发起公网测速流量。
- Python 执行真实 network-audit 脚本的采集代码，加入 IPv4 SSH 与 IPv6 探测来源不同的用例，防止把同端口无关 IPv4 连接算进 IPv6 样本。
- WinUI 原生 B 接口检查均衡默认、双栈预算联动、20 GiB 上限和普通审阅；测试窗口不激活、不控制系统鼠标、不切换代理。

## 仍然保留的边界

这些检查证明代码路径、界面和恢复条件，不证明某台 VPS 的 WAN 已降重传或提速。本轮未进行生产路径的公网双栈吞吐验收；环境不具备直连 IPv6 时也不会用替代地址族冒充完成。IPv6 来源不唯一、NAT 改写或 socket 样本缺失不会猜测。

公共上传仅一个提供方，均衡模式可依据充分的下载证据试调，并用重复上传样本防止已测上传路径退化；不宣称全局上传优化已经通过。落地机依旧只应用 fq+BBR。

编译使用锁定的已有依赖；本地 NuGet 漏洞数据源不可用的 NU1900 提示不代表漏洞扫描通过。实际版本、运行检查和发布附件以本轮验证记录为准。
