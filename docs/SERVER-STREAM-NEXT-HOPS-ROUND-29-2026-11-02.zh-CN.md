# 第二十九轮：常用服务器下一跳与核心支持矩阵

发行更新（2026-11-03）：本轮随 v0.9.41 汇总发行；下文保留实施当时的未发行状态和测试边界，发行验证见 [v0.9.41](TESTING-0.9.41.zh-CN.md)。不代表已安装或应用到生产。

日期：2026-11-02。承接[第二十八轮独立入站策略](INBOUND-POLICY-ROUND-28-2026-11-02.zh-CN.md)，扩展已有节点作为服务器默认及分类去向的能力。当前为未发行源码；已发行基线仍为 v0.9.40，本轮没有推送、发布、安装或应用到生产服务器。

## 范围与入口

本轮将 VLESS TLS／Reality、Trojan TLS 和 AnyTLS 接入既有服务器出站流程，统一校验完整原生参数、选择来源、审阅、实际路径、来源失效及恢复。没有新增 Trojan 部署角色，也没有把传输名称当作新代理协议。

| 入口 | 本轮行为 |
| --- | --- |
| 固定角色「配置出站」 | Reality 使用 Xray 投影，AnyTLS 使用 sing-box；默认与附加 TCP 落地按实际核心筛选。 |
| 「通用多入站 → 管理入站 → 出站」 | 复用同一支持检查，新增 Trojan 来源，保留 VLESS／AnyTLS 的受支持参数。 |
| 独立入站的分类例外 | 引用已有出站资源；继承第28轮的顺序、固定规则版本、依赖及证据绑定。 |

选择来源和生成审阅不修改服务器。实际应用仍通过原组件事务；默认路径与额外 TCP 去向的验证范围不同。

## 支持矩阵

以下指 **入口服务使用的核心**，不是桌面客户端类型。客户端是 Mihomo 也不意味着服务器能够使用它的全部下一跳。

| 下一跳连接 | sing-box 入口 | Xray 入口 |
| --- | --- | --- |
| Shadowsocks／SS2022 | 保留既有支持。 | 保留既有支持。 |
| Hysteria2 | 保留既有支持。 | 保留可完整投影的既有支持。 |
| TUIC v5 | 保留既有支持。 | 不提供转接进程。 |
| VLESS + Reality + Vision／原始 TCP | 支持。 | 支持。 |
| VLESS + TLS／原始 TCP | 支持无 flow 或 Vision。 | 支持无 flow 或 Vision。 |
| Trojan + TLS／原始 TCP | 支持。 | 支持。 |
| AnyTLS + TLS | 支持，保留受支持的 ECH 与会话参数。 | 不提供投影或转接进程。 |
| VLESS／Trojan + TLS + WS／gRPC | 保留受支持的原生传输字段。 | 本轮不投影，明确拒绝有损转换。 |
| TLS 节点的公开 ECH 配置 | sing-box 原生保留；本轮实际 ECH 对端验收为 AnyTLS。 | 不删除 ECH 后转换。 |
| XHTTP 下一跳 | 未新增。 | 未新增。 |

VLESS／Trojan 的 WS、gRPC 来自已经实现的客户端来源模型；服务器只使用原生参数，没有把它们改成原始 TCP。XHTTP **入站**可以选择本表中的 Xray 下一跳；这不代表已经实现 XHTTP **下一跳**。

本轮实际矩阵中的 Reality 与 TLS Vision 使用固定 Xray 对端。曾在 Xray 入口 → sing-box 1.14.2 TLS Vision 对端的合成链路观测到 HTTPS 数据解密失败，未计为通过；换用固定 Xray 26.3.27 对端后通过。该观察不足以确定根因，不能宣称所有服务端实现互通。外部 TLS Vision 节点仍必须通过自己的真实业务验收，不能仅凭协议名或解析通过授予可用资格。

## 参数与来源要求

所有来源须先保存在配置方案中。保留方案／节点身份、完整来源摘要和已有受管来源资格；引用本实例、形成监听回环、来源消失或参数变化时阻止继续。缓存刷新不自动改服务器。

固定角色继续要求原始代理来源。独立入站保留原先支持的受管转发来源，但须先核对转发身份、当前连接摘要与资格；出现在候选列表不等于已经通过来源验收。伪造、失效或变更的来源仍在生成配置前拒绝。

本轮端点继续使用明确 IPv4／IPv6。域名端点需要独立的解析与环路范围，未在本轮增加；SNI 仍明确填写域名，与连接 IP 分开保留。

| 参数 | 规则 |
| --- | --- |
| VLESS | 有效非零 UUID，空 flow 或 `xtls-rprx-vision`，使用受支持的 XUDP 语义。其他编码／旧 flow 不猜测转换。 |
| Trojan／AnyTLS | 完整密码，1–4096字符，不接受控制字符。 |
| TLS 身份 | 必须启用验证并保留 SNI；不能使用 `insecure`、路径式证书或私钥材料。 |
| 信任证书 | 可使用公开内联 PEM，最多64 KiB；Xray 显式信任投影保留其信任范围，不混入私钥或随意关闭验证。 |
| TLS 版本／ALPN | 支持显式 TLS 1.2／1.3及最多8项有限 ALPN；矛盾版本拒绝。Vision 不能限定到 TLS 1.2；AnyTLS 的显式版本须符合 TLS 1.3范围，缺省字段保留核心默认语义。 |
| Reality | 保留启用状态、公钥、short ID、SNI 和受支持的 uTLS 指纹；不把它改为普通 TLS，也不混入证书／ECH／WS／gRPC。 |
| AnyTLS 会话 | 可保留5–3600秒的空闲检查／超时，0–32个最少空闲会话，以及最多512字符的客户端元数据。缺省值不靠删除显式字段制造。 |
| ECH | 只接收 `ECH CONFIGS` 公开 PEM配置；拒绝文件路径、ECH密钥、混合 PEM 或未知字段。它不是服务器私钥。 |
| WS | 保留路径、有限请求头及受支持的早期数据；不能覆盖底层握手字段。保留原生路径，不借本轮重新生成有损分享链接。 |
| gRPC | 保留受支持的服务名，不改成另一个服务或自动开启多路。 |
| 拨号／嵌套 | 不接受客户端 detour、网络强制为 TCP／UDP、插件、接口绑定、multiplex 或未知字段；明确拒绝，不静默删掉后应用。 |

默认出站需要承载并验收应用 UDP，所以不能把 `network: tcp` 的来源悄悄当作完整默认链路。本轮仍不扩展服务端 UDP 分类；分类例外是 TCP，未匹配及应用 UDP使用原默认去向。

## 使用步骤

1. 在配置设计导入或添加实际节点，核对认证、SNI、公开信任、Reality／ECH、流控与传输参数，保存方案。受管节点需先完成对应入站的验收。
2. 固定角色从实例「配置出站」选择目标组件。独立入站从「管理入站 → 出站」新增或选择资源，再将其设为默认或分类去向。
3. 查看当前核心支持范围。切换 Reality 与 AnyTLS 组件会重新筛选来源并分别保留草稿，不把 sing-box 专用来源自动替换成其他节点。
4. 固定角色填写实际网站出口 IP；独立资源可明确填写预期出口，留空时只观测地址族与实际出口。入口 IP、下一跳连接 IP和网站出口 IP是不同字段。
5. 需要分类时引用已有额外资源或附加落地，选择固定规则版本并排序。不要把服务器 Direct 当作校园网 Direct。
6. 审阅协议、SNI、公开信任摘要、指纹、Reality身份摘要、传输路径／服务名、会话设置、预期出口和受影响组件。认证内容及客户端元数据原值不在审阅中展开。
7. 确认执行，等待完整实际验收及提交。取消／错误／来源漂移按原事务停止或恢复；完成后重新生成、校验客户端候选。

### 切换核心后节点不可选

先看支持矩阵。例如 AnyTLS、带 ECH 的 TLS 来源以及本轮的 WS／gRPC 原生来源需要 sing-box。不能通过移除字段、修改本地归属摘要或额外常驻核心绕过筛选。当前已部署配置不会因打开表单就被转换。

## 实际验收与失败恢复

- **默认路径**：控制端通过真实入站验证 HTTPS、实际出口及应用 UDP；独立入站引用新协议时也明确要求 UDP 回程。HTTPS 成功但 UDP失败不会提交。
- **附加 TCP 落地**：入口 VPS 使用已选择核心的原生出站完成 TLS验证和出口检查，结果必须包含正确协议与 TCP／QUIC传输类型，不能拿其他协议或只连端口的结果替代。
- **独立分类**：保留第28轮的实际配置／策略／出站摘要绑定、默认 UDP回程和逐去向检查；业务分类命中仍按收到的原始域名／IP核对。
- **失败恢复**：沿用组件专用快照。配置应用失败、认证／TLS／出口／UDP错误及取消按受影响范围恢复；确认丢失先核对事务，不重放写入。
- **作用范围**：更改固定角色只重启其组件；独立出站的共享引用变化列出全部受影响入站。另一入站、SSH、监控、Tunnel及无关防火墙不在本轮范围。

临时出站探测继续只监听回环并有总超时，不增加正常运行的常驻核心。探测请求改由0600临时文档传入，带多个较长公开证书时不再受单个环境变量长度限制；正常或错误返回后由外层 shell清理。Python验证文档必须是有限的普通文件，不能是符号链接，最大1 MiB。协议凭据不放入进程参数或结果标记。

若真实验收失败，先区分入口认证、下一跳认证、SNI／证书／Reality、传输及应用 UDP 阶段，保留脱敏错误和版本。不要用关闭 TLS验证、删 flow、改成直连或换成 TCP端口检查掩盖失败。必要时选择已有已验收来源重新审阅；当前失败来源不能继续沿用旧资格。

旧回归的进程清理检查曾只记录 PID，可能把后来复用 PID的进程认作残留。本轮相关夹具改为同时核对创建时间，并验证仍在运行的本进程不会被误判退出；没有放宽真正自有进程的退出要求。旧TLS Vision互通失败和并行回归的清理断言失败不计为成功记录。

以上均为合成归档、本机回环协议、模拟组件恢复和原生后台界面证据。本轮未重新执行 Debian整机重启、生产应用、WAN吞吐或长时资源测量，不把已有轮次证据当作本轮新增验证。正常使用不需要另外启动一个转换服务。

本轮实际协议矩阵使用IPv4回环。IPv6字段继续复用既有地址族模型和实际出口检查，不能把这些IPv4结果写成新增协议已完成公网IPv6矩阵。

维护入口：`.NET --server-stream-only`（完整专项）、`--server-stream-model-only`（模型／事务子集）、`--server-probe-input-only`（私有文档传输）；完整专项也纳入 `--group server-stream`。缺少固定核心或Python时按日志跳过，不记为已验证。详见[开发与验证](DEVELOPMENT.zh-CN.md)。

参数设计核对[sing-box VLESS](https://sing-box.sagernet.org/configuration/outbound/vless/)、[Trojan](https://sing-box.sagernet.org/configuration/outbound/trojan/)、[AnyTLS](https://sing-box.sagernet.org/configuration/outbound/anytls/)，以及固定[Xray 26.3.27传输定义](https://github.com/XTLS/Xray-core/blob/v26.3.27/infra/conf/transport_internet.go)与[VLESS定义](https://github.com/XTLS/Xray-core/blob/v26.3.27/infra/conf/vless.go)。最新网站说明不自动扩大本轮固定核心的支持范围，实际能力以本轮参数约束及连接验收为准。
