发行更新（2026-11-03）：本轮随 v0.9.41 汇总发行；下文保留实施当时的未发行状态和测试边界，发行验证见 [v0.9.41](TESTING-0.9.41.zh-CN.md)。不代表已安装或应用到生产。

日期：2026-11-02。源码功能及隔离验收记录；尚未提交推送、打包或发行。当前已发行基线仍为 v0.9.40，不能据此推断已安装应用或服务器具有本轮功能。

## 目标与适用位置

将第二十六轮已有的分类规则、固定版本及多去向接入第十三轮的独立入站模型。从实例「通用多入站 → 管理入站」打开单个入站，在默认出站下编辑分流例外；不再只能通过固定 Reality／AnyTLS 角色的「配置出站」设置分类。两个入口复用同一规则语义与规则库，各自保留原组件的应用、验收与恢复范围，不自动转换旧配置。

本轮覆盖 Reality、AnyTLS、SS2022、Hysteria2、TUIC v5 和 VLESS XHTTP 的独立入站。一个策略属于一个入站，适用于该入站的全部用户。多个入站可引用同一出站资源；修改共享出站会列出全部受影响入站，修改某个入站的规则不会重启其他无关入站。

不配置例外时不增加策略字段，已有运行配置、客户端身份与验证判断保持原路径；不是为了迁移新增一套兼容模式。

## 先分清客户端与服务器分流

| 层面 | 负责的选择 | Direct 的含义 |
| --- | --- | --- |
| 客户端业务组 | 请求是否进入代理、从哪个地区入口进入 | 当前客户端所在网络的出口。 |
| 本轮独立入站策略 | 进入该 VPS 后，TCP 请求走哪个已引用出站 | 入口 VPS 的直接出口，遵守该入站默认出站的地址族。 |

学校购买的数据库如需校园 IP 授权，应在客户端选择校园网络直连。服务器上的「直连」不能获得校园出口身份。分类库名称只描述目标集合，不暗含任何路由动作。

## 匹配与去向

规则按显示顺序首条命中；未命中继续走所选默认出站。每条可选择完整域名、域名后缀、规范 IPv4／IPv6 CIDR，或规则库里的固定版本快照。

| 去向 | 行为 |
| --- | --- |
| 默认出站 | 使用入站的 `OutboundId`，可作精确的高优先级例外。 |
| 指定出站资源 | 使用出站页已有的资源身份；资源可为服务器直连或已保存的受支持代理节点。 |
| 入口机直连 | 明确绕过默认代理出站，从入口 VPS 发出。 |
| 阻断 | 由当前核心拒绝匹配的 TCP 请求，不换其他出口。 |

最多32条逻辑规则、展开4096项；每集最多2048项，单入站默认及显式引用出站合计最多8个，生成配置最多1 MiB。直连动作需要的内部出站不占这8个资源名额。超过上限在写入前拒绝。

本轮例外**只匹配 TCP**。即使 Hysteria2／TUIC 用 QUIC 承载连接，其中的应用 TCP 仍可分类；其中的应用 UDP 保持默认出站。不能把传输层的 UDP 与应用 UDP 混为一谈，也不将 TCP 阻断规则描述为全部协议封禁。

域名规则依赖入站实际收到的原始域名。若客户端先解析并只发送 IP，服务器看不到原域名，该请求只能按 IP 规则或默认出站处理。本轮没有新增 DNS 反查、嗅探、隐藏规则或常驻辅助核心。已知固定 Mihomo 的 SS2022 路径可出现这种本地解析；需要对该流量分类时，核对客户端 DNS／元数据行为或使用明确的 IP 规则，不能仅凭域名试算宣称真实命中。

## 操作步骤

1. 在「出站」建立默认资源及需要的额外资源。代理来源须是当前已保存、允许作为服务器下一跳的节点；保留认证、TLS／SNI、证书及受支持的 QUIC 参数。出站预期 IP 可留空，此时验收观测出口并检查地址族；需要固定出口时明确填写。
2. 回到目标入站，选择默认出站，展开分流例外。选择类型、值及去向后添加，按实际优先级排序。分类规则集同时选择名称、版本和内容摘要，可展开检查完整清单。
3. 使用「TCP 试算目标」检查顺序语义。它只做本地匹配，不联网，也不证明域名元数据会被客户端保留或目标可达。
4. 切换资源类别或入站继续编辑，已有草稿规则会保留。取消离开不应用服务器；删除仍被规则引用的出站会被阻止，必须先解除引用。
5. 进入审阅，核对受影响入站、固定版本、顺序、全部默认／例外出站、TCP 与 UDP 范围，以及客户端来源重新验证要求。
6. 执行后等待默认路径和每个引用出站完成验收。失败、取消、来源变化或远端摘要漂移不会提交成功；从任务与待恢复入口核对结果。
7. 成功后重新生成并验证客户端候选。即使客户端的连接凭据未变，也不能拿旧策略下的验收资格继续导出。

精确例外宜放在较宽分类之前。默认路径的固定 HTTPS 验收域名必须仍走默认去向；若宽泛分类覆盖它，需自行增加明确的默认去向例外。程序不偷偷插入高优先级规则。IPv4／IPv6 网段与去向地址族矛盾时提前拒绝，不尝试备用出口。

## 模型与固定版本

独立入站沿用现有目录版本，新增可选 `Routing` 字段：

```json
{
  "Version": 1,
  "Rules": [
    { "Kind": "Domain", "Value": "login.papers.example.test", "Action": "NextHop" },
    { "Kind": "Suffix", "Value": "papers.example.test", "Action": "Direct" },
    { "Kind": "Cidr", "Value": "192.0.2.0/24", "Action": "Reject" }
  ]
}
```

这是 `Routing` 对象的示例，不是完整入站或可部署配置。`NextHop` 不含 `Target` 时使用默认资源；指定资源时 `Target` 必须是本目录已有的32位资源 ID。没有规则则规范化为不含 `Routing`，不保存空策略或空引用。

分类项复用[第二十六轮格式](SERVER-RULESETS-ROUND-26-2026-11-01.zh-CN.md)，在规则中嵌入完整 `RuleSet` 快照、版本及摘要。更换私人规则库的当前版本或下载新版不会改写已部署策略；更新和恢复都需在入站明确选择版本并重新审阅应用。同版本不同内容、嵌套规则、脚本、未知字段、原生配置注入和缺失目标均拒绝。

策略身份包含规则及引用资源；资源显示名称不参与策略身份，但节点来源仍按原有完整来源摘要检查。默认及规则引用的代理来源都会复核，失效源不会被默认去向替代。源节点变化、自身引用或监听回环会阻止继续。

### 出站与核心边界

桌面复用现有下一跳选择范围：sing-box 入站使用 Shadowsocks／SS2022、Hysteria2、TUIC v5；Xray 的 Reality／XHTTP 使用可完整转换的 Shadowsocks／SS2022 或 Hysteria2，以及服务器直连。不为固定 Xray 不支持的 TUIC 增加转接进程，无法转换在写入前拒绝。

本轮解除 XHTTP 独立入站此前的服务器直连限制，接入同样的默认／例外资源与验收。它仍然是 **XHTTP 入站 → 已支持出站**，没有新增 XHTTP 下一跳、任意多跳、自动容灾或 UDP 分类。每个正常运行入站继续使用原来的独立核心服务；有限验收阶段的临时核心会关闭。

## 验收、来源与恢复

执行沿用独立入站事务：来源及归属复核 → 组件快照 → 受影响配置检查与应用 → 实际验收 → 摘要再核对 → 提交。

- 默认路径从控制端通过真实入站、用户认证及 HTTPS 验收；非空策略同时要求默认应用 UDP 回程，不以 TCP 成功代替。
- 每个默认／额外资源及显式直连，从入口 VPS 使用已安装、摘要固定的原生出站发起 TLS 验证的 HTTPS 出口检查。请求绑定入站、实际配置摘要、策略摘要及各原生出站摘要。
- 逐去向检查的范围为 `NativeOutboundHttps`。它证明对应出站认证、TLS、地址族和所填预期出口，**不证明任意业务域名的分类命中或该额外出站的应用 UDP**。实际分类业务需结合运行请求验证。
- 探测只读取已安装配置，临时文件私有、监听限回环、自有进程有总预算并在结束／失败／取消时关闭。探测前后重新检查已安装资源，漂移则拒绝成功。
- 完整结果缺失、重复、旧配置／策略／出站摘要、错误来源／协议／范围或出口不符均不能取得导出资格。
- 更新一条入站策略只操作其服务；共享资源变化按全部受影响入站处理。失败恢复原目录及本次服务范围，不触碰监控、Tunnel、SSH 或其他入站。确认丢失继续使用原事务核对，不自动重放。

要撤回策略，可删除其例外并重新审阅应用；要返回旧分类，可明确选择旧快照；要撤回整个本次写入，使用该事务的恢复点。私人规则库的新版本和已应用远端状态是两回事。
