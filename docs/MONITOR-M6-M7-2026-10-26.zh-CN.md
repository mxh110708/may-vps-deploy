## M6 已实现的行为

### 探测口径

管理员明确选择节点、目标与 ICMP／TCP／HTTP。任务范围上限 100 个节点，新建／修改任务间隔为 10–3600 秒，任务总数上限 128；批量修改先核对全部身份，再用事务应用，失败不会只改一半。

| 类型 | 数值含义 | 特别处理 |
| --- | --- | --- |
| ICMP | 单次 ICMP RTT | 无原始套接字权限显示 `permission_denied`，不写成丢包 |
| TCP | DNS 完成后的 TCP 建连耗时 | 保留实际连接失败／超时，不用 HTTP 成功代替 |
| HTTP | 从发起请求到取得响应头，包括 DNS／TLS | 校验证书、不跟随重定向；2xx／3xx 为响应成功，4xx／5xx 保留状态码 |

方向始终是“受监测节点 → 选定目标”。不能据此声称已经测得广东用户到代理入口、代理完整业务或下载吞吐。广东三网的实际目标、地区阈值与公网可达性仍在 M8 上线前核对。

调度探测超时为 3000 毫秒，延迟规则上限不能超过它。地区字段作为人工标识；管理员按目标地区及协议填入明确阈值，没有把美西、香港等地区套用一个默认延迟，也没有加入自动基线学习。延迟规则使用成功样本；超时、DNS／TLS／HTTP 失败应另外配置失败率规则。

删除了旧实现中对高延迟结果的隐藏重试。实际 1.1 秒 HTTP 响应会保留为约 1100 毫秒，连续确认交给告警规则，不再被改写成一次失败。Agent 首次收到探测任务时才创建固定工作池：4 个测量工作者、32 个等待位置，以及有界结果队列；不为每条任务任意创建新协程。同一任务版本尚未完成时不重复排队。队列拥挤会跳过任务并记录，不能凭空记为一次丢包。曾经使用的工作池在进程内空闲等待，退出 Agent 时释放。

### 规则与事件

规则支持离线或上报中断、持续高延迟、探测失败率、CPU、内存和磁盘使用率。新规则默认关闭，明确保存后才应用。

- 规则上限 32，合计授权节点上限 100；各规则可分别选择节点、地区标识、探测与绝对阈值。
- 连续异常／恢复确认均为 1–10 次；相同证据时间重复读取不会累计确认。失败率窗口为 3–20 个样本。
- 延迟恢复需低于触发值的 80%；失败率恢复值为触发值的一半；资源恢复比触发值低 5 个百分点。中间波动不会立即来回切换状态。
- 缺失、过期、无权限、无效数值和目标版本变化均保留未知状态，不按健康的零值处理。首次没有上报时等待采集，不凭空报离线；启动后缺少报告还有约两分钟保护期。
- 可按规则静默，最长七天；界面提供一小时静默及结束静默，保存后生效。静默期间继续评估，已发送过的故障恢复后可在静默结束时补发恢复通知。
- 每个事件有独立 ID；持续的同一故障不反复通知。冷却、维护静默、确认中、恢复中、等待发送、重试、失败和接收器关闭分别展示。
- 原有离线通知已经管理的节点标记为由原通知管理，避免同一离线事件双发；本轮不会替用户打开或重配旧通知。

发送队列上限 128，通知历史上限 200。每个事件最多尝试三次，初次失败后约 5 秒、30 秒再试；不保存或显示接收器响应正文。接收器可用 `X-May-Event-ID` 去重。进程在“接收器已接受、回执尚未写回”之间退出时，仍可能重送相同 ID，不能宣称严格仅送一次。

规则及事件状态保存在已有配置存储中，发送前保存事件 ID，定期及正常退出时保存状态。发送失败、来源读取失败和状态持久化失败均可核对。恢复原有进程时不会重新创建已经耗尽重试的事件。

结构化探测缓存最多 4096 个“节点／任务”组合，每组 20 条；已配置告警窗口优先保留，近期预览不能挤掉有效窗口。任务目标、类型或间隔变更会改变版本，旧结果不能混入新窗口。历史指标仍由原指标存储和保留策略管理，缓存上限不等于历史保留期。

### 本次通知边界

用户本次选择先完成本地接收器验收。新发送器只接受字面回环 IP 的 HTTP(S) 地址，例如 `http://127.0.0.1:<port>/events` 或 `http://[::1]:<port>/events`；不接受域名、URL 凭据、查询参数或重定向。配置校验和实际连接均检查回环地址，禁用系统代理，不通过 DNS 别名放宽范围。

接收器留空时不发送，规则状态仍可查看。实际外部通知渠道没有接入新引擎，也没有执行真实外发。通用外发接线曾被自动审批拒绝，原因是本次只授权本地验收；本轮已收窄到上述回环边界，没有用本地转发器规避限制。原有通知渠道代码不是本轮新增发送路径的替代入口。

### 独立的 Server 存活检查

新 Server 二进制提供独立 `watchdog` 子命令。它运行在另一进程，用只读快照核对服务安装身份和响应时间；不依赖被检测 Server 的告警工作者。实际停止 Server 后，独立进程确认失联并向本地接收器发送事件；重启后确认恢复。

配置文件不放令牌：

```json
{
  "endpoint": "https://<monitor-origin>",
  "server_instance_id": "<已核验的服务安装UUID>",
  "local_receiver": "http://127.0.0.1:<receiver-port>/events",
  "interval_seconds": 30,
  "confirm": 3,
  "recover": 2
}
```

通过受保护的进程环境提供 `MAY_MONITOR_WATCHDOG_READ_TOKEN`，然后运行：

```text
<server-binary> watchdog --config <watchdog.json> --state <owned-state-directory>/state.json
```

先验证正确身份和健康响应，之后才把失联计为故障。凭据被拒绝、TLS 校验失败及安装身份变化单独记录，不能直接当成服务离线或恢复。独立状态文件只含状态和事件，使用 0600 权限及原子替换；同一状态文件只运行一个检查进程。

现有只读接口仍是一份授权配置。Deploy 与 watchdog 同时使用时，要保持该授权值／范围一致；轮换或续期后两端都应更新，不能假设另发第二个令牌会保留第一个。需要多份独立授权时另行扩展，不用管理员 Key 替代。

本轮验收的是独立进程发现 Server 进程失联。同机 watchdog 无法覆盖整台宿主机或机房失联；独立主机、真实 HTTPS 和外部通知的生产演练属于 M8。本轮没有在生产主机自动安装 watchdog。

## M7 已实现的日常流程

### May Web

默认 Web 显示 May Monitor 标识和新图标，保留 Komari 与依赖版权。界面语言只打包简体中文及英文；其他浏览器语言回退到英文，中文标签归入简中。

新增“监测与告警”页面，可以按规则编辑范围、探测、阈值、确认次数、失败窗口、冷却和静默，查看当前状态、最近 20 个探测证据及通知历史。HTTP 错误保留具体状态码。配置验证失败会停留在当前表单；后台刷新不会覆盖未保存的编辑。

节点概览和详情区分在线、离线、等待首次上报、报告过期、指标无效和当前状态不可读取。缺少有效当前报告时不制造零负载记录；服务读取失败会撤下当前在线判断，鉴权失败要求重新登录。私有站点在移除会话后重新核对权限，不保留前一视图的私有节点。

概览保留既有的可见页面刷新；新告警页按 15 秒刷新。切换到真实后台标签后停止告警轮询，页面关闭后不保留该页轮询；恢复可见后重新读取。读取失败退避，重复请求不叠加。历史页面仍使用已有的历史与时间序列接口。

默认菜单根据 Server 实际开放能力显示。未启用的远程终端、任意命令、扩展及调试入口不会作为可用功能引导；没有为显示菜单而打开后台能力。更新来源改为 May Server 仓库，May 的预发布版本不再误触发旧 Komari 版本迁移提示。说明文档只在选择查看时加载，离开会取消未完成读取。

没有把 URL 中的临时分享参数提升为长期 cookie。管理员规则接口不能被普通访客、Agent 或专用只读令牌调用；普通设置接口也不能绕过专用规则校验去修改告警状态。

### Deploy 摘要与维护

受管实例的只读摘要增加活动告警、静默和发送失败计数；只返回当前授权节点的计数，不带规则名称、目标、接收器或其他节点。旧 Server 未返回扩展时不假造计数。

只读快照可以返回本次凭据的截止时间。界面显示有效期及临近到期／到期提示，自然到期会更新显示而不发起网络请求。读取失败、超时、TLS、凭据被拒绝、重定向及安装身份不匹配使用不同的可操作信息。

本机连接可显式固定已核验的服务安装 UUID；匹配失败的快照不进入当前视图。未固定的旧连接仍可读，并提示补充核验，没有静默相信一次新来源。该字段是正常的持续来源校验，并非改名迁移补丁。

“打开 May Web”只打开已保存且已验证格式的基础网址，URL 不带令牌，不复制管理员会话；完整规则、历史及管理在 Web 中完成。Deploy 的自动读取继续由用户显式开启，离页、隐藏、最小化和关闭会取消／暂停，重新打开该页默认不自动刷新。

监测 Agent 的报告、基础信息、结果回传及 WS 握手改用独立 `X-May-Agent-Token` 请求头；普通 HTTP 请求不会随重定向转发该凭据，也不修改共享客户端的全局重定向策略。默认禁用的终端／文件操作没有因本轮开启。

## 验收与复用

### 实际行为证据

使用真实本地候选 Server／Agent、本地 HTTP 目标、本地接收器和独立 watchdog 进程完成：

- TCP／HTTP 成功；本环境 ICMP 原始权限不足时收到独立的受限状态，不生成丢包历史。
- 真实约 1100 毫秒 HTTP 响应、连续确认、单一事件、静默中恢复及解除静默后的恢复通知。
- 接收器返回失败，最多三次同一事件 ID；Server 重启后不重新发送耗尽的事件。
- 修改探测目标后拒绝旧版本结果；只读快照只含授权摘要；只读令牌不能管理规则。
- 停止真实 Server 进程，由独立 watchdog 告警；启动后产生独立恢复事件。
- 私有站点拒绝匿名读取，全部测试自有进程最终关闭。

可复用脚本为 [verify_may_monitor_alerts.py](../tests/verify_may_monitor_alerts.py)。在 Linux 上指定新配套二进制和一个不存在的输出目录：

```text
python3 tests/verify_may_monitor_alerts.py --server <new-server> --agent <new-agent> --output <new-local-fixture-directory>
```

脚本创建回环服务和合成凭据，写入受限的独立目录；不导入实例密码、不连接生产 VPS，不调用主机服务管理、代理或 TUN。结果在输出目录的 `checks.json`，诊断文件保留在本地。失败时同样关闭自有服务；原输出目录不会被覆盖。完整流程需要等待真实确认、冷却及重启条件，不以快进时钟代替。

真正的 WinUI 隐藏合成会话通过配置、取消、三实例显示、告警计数、自然到期、失败提示、无并行读取、离页停止、重开不自动轮询、拒收旧连接响应及本机移除等流程。会话证明显示零前台激活、零全局输入注入，进程已退出。

独立的真实 Edge 会话通过中文保存／参数拒绝、英文展示、未上报节点不显示零负载、节点历史、禁用能力入口、真实后台标签停止轮询、重新登录、断网未知状态、移动宽度及页面关闭检查。没有使用用户浏览器配置；测试浏览器的外部请求被阻断。构建与九项 Web 状态／安全／缓存／引导测试通过，静态检查零错误；保留既有警告，不为消除警告改动无关功能。

### 短时资源记录的边界

本轮测量的是功能及页面切换短测，包含页面初始化、截图、标签切换和调试开销；不能作为稳定常驻内存下降的证明。

| 阶段 | 时间／样本 | 私有内存中位数 | 单核 CPU 中位数 | 说明 |
| --- | --- | --- | --- | --- |
| Edge 概览 | 12 秒／6 点 | 368.86 MiB | 25.60% | 整个独立浏览器进程树，不是单页独占；JS 堆约 6.80 MiB |
| Edge 历史 | 14 秒／7 点 | 381.13 MiB | 3.84% | 含初次加载；JS 堆约 17.01 MiB |
| Edge 告警页 | 18 秒／9 点 | 294.65 MiB | 0% | 真实状态读取，未打开外部通知 |
| Edge 后台标签 | 18 秒／9 点 | 307.23 MiB | 1.54% | 全浏览器树含新空白标签；该页告警轮询为零 |
| Edge 页面关闭 | 10 秒／5 点 | 326.90 MiB | 0.77% | 浏览器仍开着，JS 堆约 0.42 MiB，不宣称浏览器缓存即时归还 |

## 保留与后续边界

本轮没有新增改名目录扫描、旧安装身份桥接或迁移兼容复制。保留的是持续需要的来源验证、只读授权、既有 Agent 协议入口及受控的维护状态。

真实外发、真实广东目标、生产 HTTPS、跨主机故障和生产分批迁移均未验收。M8 需重新选定实际目标、渠道和主机，再做并行对照。M9 再整理最终发行矩阵及长期维护交接。本轮没有触碰 Route 的分流／自动切换、系统代理／TUN、Cloudflare 或现有 Komari 服务。
