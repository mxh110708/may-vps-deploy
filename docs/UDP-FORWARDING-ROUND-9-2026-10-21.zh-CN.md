# 第九轮：独立 UDP 端口转发

本轮为受管 Debian 12／13 实例增加独立 UDP 转发组件。来源数据报进入指定监听端口，经独立会话送到一个明确的目标 IP 和 UDP 端口，目标响应再返回原来源。它与第八轮 TCP 转发分别管理，不要求重新安装代理或监控。

源码与以下本地验证已完成，后续随 v0.9.35 整合发行；未安装或应用到生产 VPS。第十轮另补[Shadowsocks／SS2022 UDP 验收](UDP-PROXY-ROUND-10-2026-10-23.zh-CN.md)，不将其追记为第九轮已完成项；整合结果见[发行验证](TESTING-0.9.35.zh-CN.md)。

## 操作流程

1. 在已部署／接入、无待恢复事务的实例详情打开「独立 UDP 端口转发」。
2. 选择保存，添加规则，在竖排卡片填写名称、启用状态、监听地址族与端口、目标 IP 与端口、允许来源、会话限制和验收方式。
3. 选择审阅，核对监听、目标、来源、会话中断影响与恢复范围，再提交统一任务。只编辑或取消审阅不会连接服务器。
4. 任务核对 SSH、资源归属及实际 UDP 监听，固定恢复点和回退程序后应用，逐条完成真实 UDP 往返验收，再复核资源摘要与管理连接后提交。
5. 后续可编辑、停用、移除单条规则；「只读检查已保存转发」只核对已保存规则并更新本地证据。「移除全部受管 UDP 转发」移除本组件及相关受管防火墙放行。

检查不应用表单中的未保存修改，也不重启工作进程。全部规则停用时只核对停用及资源一致性，不将其标作转发可达。

## 参数

| 字段 | 范围与含义 |
| --- | --- |
| 规则 | 每台实例最多 16 条，每条有稳定 ID；名称为 1–80 个可打印字符 |
| 监听 | IPv4、IPv6、双栈；相应地址族所有本地接口。IPv6-only 与 IPv4 分开，避免隐式跨族占用 |
| 监听端口 | 1–65535，规则之间不重复；停用仍保留配置中的端口 |
| 目标 | 明确的单播 IPv4／IPv6 与 UDP 端口；不支持域名目标、广播或组播 |
| 允许来源 | 每条 1–32 个 IP／CIDR，规范化网段；回环来源豁免外部白名单 |
| 会话无流量超时 | 默认 120 秒，可设 10–600 秒；到期关闭该会话的目标套接字 |
| 最大会话数 | 默认 256，可设 1–1024；每条规则独立计算 |
| 验收 | 目标实际提供的 DNS A／AAAA 查询，或 UDP 原样回显 |

`0.0.0.0/0` 和 `::/0` 是显式允许整个地址族的来源；程序不会自动追加。双栈需要实例归档中的两种公网地址均有效，控制电脑的两种来源均被允许。目标看到的是转发实例的地址，目标侧访问控制须允许该实例。

## 会话与数据报

会话按来源 IP、来源端口和收到数据报的本地目的地址／接口区分，各自使用连接到目标的独立 UDP 套接字，避免不同客户端收到彼此响应。支持 IPv4→IPv6、IPv6→IPv4 和同族转发。

Linux `IP_PKTINFO`／`IPV6_PKTINFO` 记录本地目的地址与接口，回包使用原来被访问的本地地址，避免多地址／多接口监听时选错源地址。上游套接字只接收所配置目标的响应。支持空数据报；本地测试另覆盖约 60 KiB 数据报，不表示公网路径的 MTU 或分片一定允许此大小。

已有会话达到数量上限后继续工作，新来源数据报直接丢弃；不建立无界队列。空闲会话周期回收，每次就绪事件限制连续读取数量，避免单一来源长期占住循环。没有会话持续 60 秒后工作进程退出，systemd 保留监听，后续数据报重新激活工作进程。

**保存规则会重建本组件，清空原 UDP 会话，期间可能丢包。** 修改目标后不会把旧会话继续送往原目标。UDP 本身无连接交付保证，程序不承诺重传、顺序或零丢包。

## 引擎与资源

复用 Debian 的 Python 3、systemd 套接字激活和 nftables，不增加第三方转发二进制或常驻控制面。每条启用规则按需运行一个 Python 工作进程，以独立动态用户、空能力集、禁止提权和只读系统目录运行。预检缺少依赖时停止，不在后台安装。

会话上限、清理和无会话退出是资源约束设计；本轮没有内存、CPU 或公网吞吐基准数据，不能据此宣称比其他引擎更快或更省内存。

## 验收范围

验收由运行 Deploy 的控制电脑直接向实例监听端口发送 UDP，经过完整转发路径等待实际响应。它不使用 HTTP 系统代理，也不以 TCP 可连或 UDP `send` 成功替代往返证据。每个监听地址最多尝试三次，每次两秒，整体验收最多两分钟，可取消。

| 方式 | 成功条件 |
| --- | --- |
| DNS | 每次新查询 ID；问题名称和类型匹配，响应位／操作码／错误码合法，未截断，问题与记录边界可解析，并包含所选 A／AAAA 类型答案 |
| 原样回显 | 每次新的 32 字节随机内容，经转发收到完全相同的数据报 |

双栈逐个验证已归档的 IPv4 和 IPv6；提交检查记录数、规则 ID、实际监听地址、验收类型、控制端发起标识和响应匹配证据，缺一项即拒绝提交。

**当前应用验收仅支持提供 DNS 或原样回显的目标。** 普通 QUIC、Shadowsocks 或其他 UDP 服务通常不会响应这两类请求，本轮尚无对应专用适配器，不能将它们作为已支持并完成应用验收的目标。协议转换、UDP-over-TCP、PROXY protocol、原客户端 IP 保留、流量配额和自动改写客户端方案也不在本轮范围。

## 归属、防火墙与恢复

组件独占 `/etc/may-udp-forward/`、`may-udp-forward-*` systemd 单元及 `inet may_udp_forward` 白名单表。白名单在独立 nft 表与新会话入口均核对。配置、实际文件、运行白名单及套接字启用状态共同形成远端摘要；工作进程按需退出不作为资源异常。

- Deploy 管理主防火墙时，只同步启用规则的 UDP 放行；保留既有防火墙时不修改它。服务商安全组也不会被修改。
- UDP 端口与 TCP 可以同号；已安装 Shadowsocks 占用的 UDP 端口或其他实际 UDP 监听冲突时拒绝应用。目标指回本组件监听会被拒绝。
- 拒绝未知同名资源、链接、额外文件、systemd 覆盖以及未归档的外部改写。审阅固定本地来源、程序与远端摘要，执行及快照再次核对，避免拿陈旧审阅覆盖新内容。
- 已由本应用管理的旧 UDP 工作程序可以保留，但其实际字节摘要必须匹配私人归档；更新程序只能通过明确审阅的保存操作完成。外部改写不会被自动接管。
- 快照保存实际旧文件和独立恢复程序。TCP 与 UDP 分别使用配置路径、摘要与恢复日志；未来应用更新不会更换已固定的旧事务恢复代码。
- 失败或取消恢复本组件和本次受管防火墙范围；不会改动 TCP 转发、代理、SSH、监控的配置。回复丢失先对账，禁止自动重放写操作。
- 恢复拒绝未知外部内容；记录恢复意图，允许恢复过程再次中断后继续。目标变更失败时恢复原配置／工作程序，不能恢复已经消失的 UDP 内存会话。

实例健康检查只读核对配置和归属，不自动重启或发应用探测。退役实例前须先独立移除 UDP 转发。既有代理恢复和追加安装也核对 UDP 端口，并保留本组件的防火墙规则。

最后一次完整回归前，既有服务器链路探测测试曾在等待本地客户端监听时超时；没有保留当时的子进程输出，原始触发原因未证实。测试已增加子进程提前退出检测、单次连接等待上限和失败 stderr 记录，不放宽总体预算；该专项 34 项及最终完整回归均通过，没有跳过失败断言。

Windows 不能执行 Linux 工作进程会话测试，会明确跳过这些条目；本轮已在恢复可用的 WSL 中实际补测。资源／恢复测试使用模拟 systemd 与 nft 命令，真实工作进程测试使用隔离回环及继承套接字；它们不等于 Debian 12／13 整机安装、重启、真实 nft 调度和完整回退生命周期验收。CI 已加入相应测试，但源码未推送，不能声称本轮远端 Actions 已通过。尚无生产公网验证或 WAN 性能数据。
