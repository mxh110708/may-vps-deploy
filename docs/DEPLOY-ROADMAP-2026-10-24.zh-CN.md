## 第二十轮：XHTTP 完整客户端适配

本轮联动 May Core、May Route 与 Deploy。目标是完整支持所选固定上游版本的 **VLESS XHTTP 客户端能力**，让已有 XHTTP 配置按真实参数使用；不再把「一个模式可用」写成「完整适配」。服务端继续使用 Xray，不因此扩展 sing-box 的 XHTTP 入站或重新引入已排除的旧协议。

固定版本为 Xray 26.3.27、Mihomo 1.19.32、May Core 1.14.2-may.xhttp20.0 和 Go 1.26.8。客户端字段、合法组合、默认策略及已验证边界见第二十轮记录；上游 sing-box 1.14.2 继续用于未含 XHTTP 的验证。

| 范围 | 交付与完成标准 |
| --- | --- |
| 传输模式 | 实现 `stream-one`、`stream-up`、`packet-up` 和 `auto`；覆盖会话标识、分片序号、上传排队与背压、双向流及断开清理。`auto` 按固定上游语义选择模式，不能简单改写成 stream-one。 |
| HTTP 版本与安全 | 补齐 HTTP/1.1、HTTP/2、HTTP/3 在上游实际支持的 TLS／Reality 组合；分别验证协商、认证、证书／SNI、错误响应和重连。Reality＋HTTP/3 等上游本身不成立的组合明确标为协议不适用，不伪造支持。 |
| 上下行分离 | 支持独立下载设置及其连接地址、TLS／Reality 身份、Host、路径与传输配置；上下行分别验证来源和回程，任何一侧失败、取消或配置变更均能清理会话。 |
| 高级配置 | 按固定版本字段清单补齐 `extra` 中的请求／响应头、填充及其位置、会话元数据、上传分片／缓冲／并发参数，以及 XMux 连接复用与生命周期设置。普通路径、查询串和转义必须按实际语义保留；不再以静默删除字段通过导入或输出。 |

| 直连与代理接入 | 覆盖直连、受控反向代理及可明确验收的 CDN 场景；分别说明 Cloudflare 普通代理和 Tunnel 的边界，不互相套用结论。没有实际验证的公网／CDN 组合保持未验收状态。 |
| 功能回归与局部资源优化 | 各合法模式／版本完成真实 HTTPS、应用 UDP、并发、长连接、错误身份／参数、取消、服务端中断与恢复；同时回归既有协议、用户／证书轮换、来源变化和局部恢复。按 2026-10-30 用户最新要求，功能为主；资源对比全部后台、有总超时。无明显资源收益且无其他贡献的调整放弃，不能把未执行的长测或微基准说成整应用常驻内存改善。 |

### 完成门槛

1. 固定版本客户端字段清单和合法组合矩阵逐项闭合；未完成的功能不能借「暂不支持」列入完成清单。上游不适用、客户端差异和外部环境尚未验收分别注明原因。
2. Core、Route、Deploy 之间完成真实生成、加载和连接验证，包含身份、配置来源与配套核心检查；保留原始参数，不伪造另一客户端的兼容配置。
3. 受控反向代理及已约定公网／CDN 组合有实际验收，剩余环境缺口明确保留；存在缺口时不能报告「所有 CDN／所有 XHTTP 节点通用」。
4. 取消、重载、网络切换、错误响应及异常断开能解除阻塞并清理自有连接、队列与测试进程。资源优化独立记录收益和限制；先前会显示窗口的四场景测试作废，未执行的 900 秒观测不作为完成功能的依据，也不宣称长期内存稳定性已验证。
5. 同步教程、支持矩阵、示例及测试入口。轮次完成、提交推送、打包发行和安装更新分别记录，不由计划更新自动执行。

## 偏离原因与更正

用户追加的 Komari fork、安全审查和逐步迁移到 May Monitor 的要求，是有效的监控工作授权。实施时错误地把它当作替换原主线，并把三个监控阶段标成了第十二至十四轮；未先核对原计划，也未说明替换。这是任务跟踪和完成状态报告错误。

此前“第十二／十三／十四轮已完成”的监控记录，只能证明相应监控支线功能已完成，不能作为跨实例编排、通用多入站或 Hysteria2 的完成依据。
