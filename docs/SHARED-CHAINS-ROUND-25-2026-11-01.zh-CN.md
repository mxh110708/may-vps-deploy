# 追加功能：共享实例的多线路管理（此前误标第25轮）

日期：2026-11-01。此前因错误宣称原计划未定义，又让用户选择并完成此功能，误将其作为第25轮。原25轮是「节点来源与同步完善」，本记录不能代替它。多线路共享按后续明确选择保留为追加功能；文件名暂留作追溯。本功能与第二十四轮随 v0.9.40 发行，不代表本机已安装或应用到生产。

## 能做什么

同一台实例可以参与多条三实例线路，既可以复用前置／中转，也可以在不同线路中交叉承担前置和中转角色，或共同使用同一个原始落地。每条线路仍有独立身份、名称、监听端口、白名单、落地来源、可选 WireGuard 段及实际验收结果。

| 项目 | 行为与边界 |
| --- | --- |
| 拓扑 | 每条线路仍是三台不同的实例，不生成任意深度图，也不把另一条线路的派生节点当作原始落地。 |
| 角色边界 | 前置和中转可交叉复用，落地可作为多条线路的落地；本轮不将活动落地与其他线路的转发角色混用。原落地在事务期间继续使用原有严格来源与维护保护，不放宽该保护来绕过检查。 |
| TCP／UDP | 沿用原生 TCP 代理及固定端口 Hysteria2／TUIC v5 的 UDP 范围；可以在共享实例上并存。各传输组件最多 16 条规则，独立转发也占规则数；每台实例最多 32 个线路依赖。 |
| 端口 | 同一传输组件内规则使用独立监听端口，仍执行协议、管理端口、隧道端口及真实系统占用检查，不以不同线路名称绕过冲突。 |
| WireGuard | 多条线路可借用同一已验收相邻通道；仍是一台实例一个通道、一条线路一个加密段。删除一条线路不会删除通道；只要还有活动／待恢复引用，通道仍不能移除。 |
| 来源 | 客户端节点继续固定该线路配置、原落地鉴权和本线路连接。合法增删其他线路不会使存续节点因为共享组件整体摘要变化而失效。 |
| 检查 | 选择某条线路只检查这一条并保存它自己的检查结果；一条检查失败不把其他线路标成失败或通过。 |
| 变更 | 新建／移除时列出共享前置／中转的受影响线路，锁定这些线路的全部参与实例和来源，修改后逐条完成实际业务复验。 |

共享的是服务器和转发组件，不共享用户的代理凭据。对未验证的来源、未知规则、缺失依赖和待恢复任务继续拒绝写入；不会把缺失节点改成直连。

## 新建和选择线路

1. 在任意受管实例进入「跨实例线路编排 → 管理线路」。列表同时显示参与的各条线路及传输、状态。
2. 选择「新建线路」，当前实例作为前置。中转可以选择已经参与其他线路的实例；落地仍选择已保存且符合所选地址族／传输的原始受管节点。
3. 为本条线路选择独立监听端口和白名单。借用 WireGuard 的要求见[第二十四轮](CHAIN-WIREGUARD-ROUND-24-2026-11-01.zh-CN.md)。
4. 审阅本线路和需要保留、复验的其他线路。共享实例已有其他待恢复任务时，先从原线路恢复入口处理，不能靠新建线路绕过。
5. 整链业务、共享线路业务及实际资源复核均通过后才提交。配置设计中继续分别添加各线路节点，各节点身份互不覆盖。

从中转或落地打开同一页面也能选择对应线路。在线路之间切换查看不会覆盖新建草稿；取消审阅不创建任务或依赖。

## 移除、检查与故障处理

选择某条活动线路后，可单独检查或移除。移除只从前置、中转的共享配置中删除该线路的两条规则，并从三台实例的依赖集合中删除该身份。其他规则、白名单、落地协议及独立隧道继续保留。最后一条规则移除后才移除对应转发组件。

共享组件应用会重启该组件，现有 TCP 连接或 UDP 会话可能短暂中断并需要重连。本轮保证规则、身份和恢复范围隔离，不宣称连接永不中断；零停机热更新未纳入本轮。

| 情况 | 处理 |
| --- | --- |
| 新线路业务失败或取消 | 恢复本次变更前的前置／中转组件和涉及防火墙快照；快照包含原来的存续规则。 |
| 保留线路的来源、隧道或实际业务无法复核 | 本次变更不提交。先处理已有线路或连接问题，再重新审阅；不省略已有线路验收以强行提交。 |
| 提交确认丢失 | 按原任务身份查询远端状态；部分提交也用同一快照补偿，不重放应用。 |
| 补偿未完成／归属不同 | 保留原待恢复记录。共享实例暂时禁止新的线路写入、归档删除与依赖维护，直到从原线路统一恢复完成。 |
| 仅一条线路最近检查失败 | 该线路旧节点不能导出；其他线路仍按各自来源和规则核对。若共享组件自身损坏，涉及该组件的线路分别反映其校验失败。 |
| 想删除实例归档 | 必须先移除或恢复全部依赖；手工删除实例中的依赖字段不能绕过线路记录的保护。 |

共享变更需要复验存续线路，因此即使待移除线路的落地可以离线，存续线路的落地和所借用通道仍须可检查。本轮不提供跳过复验的强制移除。

## 数据与事务

实例以 `TcpChains` 列表保存各条依赖，线路记录以两条规范规则的 `RuleFingerprints` 固定本线路资源。共享组件的整体远端摘要仍用于读写前后对账；它不会替代逐线路的归属检查。

v0.9.39 的单条 `TcpChain` 依赖和整体摘要记录继续按原样读取，不在打开界面或生成节点时重写。成功的线路变更写入依赖集合；涉及旧线路时，在原规则和实际业务均核对后保存逐规则摘要，原线路配置、节点身份和凭据不变。这是持久数据模型升级，不是旧品牌迁移补丁；两套依赖字段并存、重复身份、未知字段或错误摘要会停止操作。

共享变更审阅固定相关线路记录、全部参与实例、来源方案及所借用通道；执行按稳定次序获取实例锁。未知线路规则、同端口冲突和审阅后变化在写入前拒绝。远端修改只发生在本条线路的前置和中转，额外参与实例只用于验证；不会对存续线路重放部署。

本次事务保存保留线路的本次验证证明，已有线路的最近检查状态不会因为另一条线路成功而被清除。失败补偿恢复当前任务快照，不删除或重建其他线路的记录。

## 验证与复测

最终模型及故障专项通过 926 项断言，覆盖两个地址族、TCP／Hysteria2／TUIC、共享前置／中转、角色交叉、共享落地、TCP／UDP 共存、旧单依赖读取与升级、端口冲突、共享来源在审阅后变化、额外参与实例锁、独立检查失败、证据保留、未知归属、取消、提交确认丢失、补偿失败与续做。旧线路在成功新增、移除及失败补偿后均重新核对来源；存续记录不会被另一条失败任务覆盖。

实际测试在前置 Debian 12、中转／落地 Debian 13 的一次性三机执行。IPv4 原生连接三个协议场景通过 60 项断言；IPv6 三个协议场景使用前置→中转 WireGuard，通过 75 项断言。每个场景创建两条线路，确认两条均有有效来源、第二条成功后第一条完成本次业务复验、分别检查、移除第二条后第一条仍通过实际业务，再移除最后一条。两个矩阵各注入一次真实远端提交成功后丢失确认，均完成补偿并重验存续线路。合计六个双线路场景、135 项实际断言，不把模型数量加入实际测试数量。

原生 WinUI 在已有后台 `suite.tcp-chain` 中通过：同一中转列出两条独立线路，审阅保留范围，新建草稿保留，移除／恢复入口及取消均正确。最终构建的窗口激活 0、前台采样 0、生产连接 0，完全离屏且无任务栏／托盘；测试应用已经退出。Core／测试和 WinUI 构建均为零警告、零错误。

相关基础归档组通过 272 项、维护与恢复组通过 867 项；受 Windows 符号链接权限限制的项目明确跳过，不计为本机已验证。项目主校验 `ValidateProject` 通过，其主入口为 995 项断言，另包含交互、工作台、审计、GUI／更新和可运行的 Python／Bash 检查。679 份公开文本秘密扫描、改动夹具的 Python 编译及文档本地链接检查通过。这些是不同验证入口，不当作一组断言总数相加。

转发、线路、WireGuard 与入站相关组通过 2,951 项回归；独立 Reality 的实际 Xray 配置检查因缺少 `MAY_TEST_XRAY` 明确跳过，模型和事务检查仍执行。收尾将活动落地与转发角色混用设为显式拒绝，重新完成全部 926 项专项复验该边界；没有放宽独立入站来源的未完成事务检查。

一次 IPv4 夹具在等待系统初始化的 180 秒准备预算内未完成，夹具自动关闭，未进入业务阶段，不计为通过。共享夹具统一去掉不需要的 APT 翻译／源码索引后，在全新目录重建并通过完整矩阵；没有延长产品操作超时、跳过实际业务或改变宿主网络。早期测试代码的结果对象类型编译错误已修正，后续构建与测试通过，不将失败构建计为完成。
