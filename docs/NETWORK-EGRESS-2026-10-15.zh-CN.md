# 落地 IPv4 / IPv6 出站选择

原先“落地访问目标的出口”只允许选择一个出站地址族，双栈采集只展开了连接 VPS 的地址族。这无法在一轮中检查已经部署的 IPv4 和 IPv6 两个落地出口。

新名称为“落地访问网站使用的 IP”，选项包括仅 IPv4、仅 IPv6、IPv4 和 IPv6 都测。未部署 IPv6 出口时只显示 IPv4；只具有原生 IPv6 地址不满足双出口条件。新建双出口落地表单默认两者都测，已保存的单出口偏好继续保留。

连接 VPS 的地址族与落地出站独立选择，均选双栈时展开 4 条路径。中转的入口到落地连接仍按明确选择的单个地址族构造；选中的两个出站用户分别经过同一个真实入口，不绕过入口，也不修改落地。报告、审阅和前后复测按完整组合匹配，不只按连接地址族匹配。

所有组合共用整轮流量预算和时限，包括上传、下载及前后两轮。20 GiB 总预算下约 20% 预留给开销，单轮 4 条路径的有效载荷分别最多 2 GiB，不会各拿一份 20 GiB。未知或缺测结果不记为成功；缺少组合、重复组合、出站选择变化及任一路径退化都会阻止共享参数验收。落地本身仍只应用 fq + BBR。

本地回归：

- 网络专项 129 项断言通过，包括 IPv4 连接下的 IPv6 出站、4 种组合、共同预算、缺失出口拒绝、部分失败、重复/缺少组合、共享配置只应用一次及全部路径复测后的范围恢复。
- 完整核心边界及工作流 908 项断言通过。Windows 符号链接权限不足的既有测试明确跳过，未记为通过。
- Windows x64 自包含构建通过，41 项原生界面检查及其子套件通过。检查双出口默认值、显式选择、新名称、预算实时刷新和四条组合审阅；原有滚动防误选检查继续生效。
- 上述回归使用合成归档和测试适配器，没有激活前台窗口。原生控件检查不替代物理鼠标、触控板的手动验收。

公网只读实测（2026-10-15）：

| 执行环境 | 连接入口 | 落地访问网站 | 结果 |
| --- | --- | --- | --- |
| Windows 原生应用 | IPv4 | IPv4、IPv6 分别采集 | 两个出口身份均匹配，完成有限传输；公共目标或时限覆盖不足，结果为 `CompletedWithWarnings`，建议退回 `EntryBasic` |
| BERO 隔离客户端 | IPv4 | IPv4 | 出口身份匹配，完成有限上传、下载 |
| BERO 隔离客户端 | IPv4 | IPv6 | 出口身份匹配，完成有限上传、下载 |
| BERO 隔离客户端 | IPv6 | IPv4 | 出口身份匹配，完成有限上传、下载 |
| BERO 隔离客户端 | IPv6 | IPv6 | 出口身份匹配，完成有限上传、下载 |

Windows 使用当前应用的 Core、Infrastructure 和 WinUI，只在带有限定连接范围的私人归档副本中采集。所选真实路径为已有入口、中转到已有落地，再分别选择两个出站用户；入口到落地均使用已受信的 IPv4 连接。本机没有 IPv6 默认路由，因此 IPv6 连接由 BERO 补测，没有将本机直连 IPv6 记为通过。

BERO 的四条路径由当前 `SelectedPaths` 和 `ClientProfiles.SingProbe` 生成，使用经过固定哈希校验的 sing-box 1.14.2。每条路径经独立本机代理验证实际公网出口，Hetzner 下载返回 HTTP 206，Cloudflare 上传返回 HTTP 200；每条完成 1 MiB 下载与 8 MiB 上传，四条合计 36 MiB 有效载荷。四条路径的 Cloudflare 下载均返回 HTTP 403，明确保留为该公共下载端点未覆盖，不反复重试或以其他目标成功冒充通过。流量未超过共享预算分配。

BERO 补测证明四种真实连接与出口组合可用，不替代完整的应用 TCP 采样、优化参数前后比较、晚高峰覆盖或持续吞吐收益验收。Windows 采集没有执行调优应用；覆盖不足没有生成可接受的精细参数。缺测和退化后的共享参数恢复由工作流回归覆盖，本轮没有在生产机上人为制造故障。

经明确授权，只将客户端连接配置临时放入 BERO 的 dev 私有目录，没有上传 SSH 私钥；测试结束后核对客户端输入、生成的代理配置和出口核对文件均已删除。测试前后只读比对 MOE、入口和落地的内核、服务状态、配置文件哈希及队列描述，均无变化；没有修改生产防火墙、代理服务、系统代理或 TUN。

本次修改纳入 v0.9.27 正式发布；已安装旧版本需通过应用更新或安装新版取得这些选项。
