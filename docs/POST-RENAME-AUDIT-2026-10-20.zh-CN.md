# 改名后代码审计

本次复查 May VPS Deploy `0.9.31`、`0.9.32` 的命名、安装、更新及凭据处理。改名本身满足产品命名要求，不计作性能改善或已复现故障的修复。

| 项目 | 结论 | 证据与处理 |
| --- | --- | --- |
| May EXE、AppId、命名空间、归档叶目录与凭据格式 | 保留 | 持续使用的产品身份；实际 May 实例与凭据能够读取。凭据保护只使用当前 May 格式和当前 Windows 用户，没有旧熵或旧品牌自动解密回退。 |
| Git 使用副本允许旧 MXH origin | 删除 | 只为仓库改名提供别名。当前源仓库已使用 May，更新只接受 May 的 HTTPS / SSH origin。隔离运输验证旧名与外部账号在 fetch 前被拒绝。 |
| `mxh_route` 配置键 | 统一为 `may_route` | 版本目录、规则资产同步及查询脚本一起调整，不保留双键兼容。固定历史验证基线的旧版本标签和 SHA-256 不伪造为新的 May 附件。 |
| 安装器拒绝旧 MXH EXE 或其他未受管文件 | 保留 | 这是防止覆盖另一个安装的拒绝条件，不是旧品牌接管或迁移。删除会降低安装目录隔离；跨品牌安装拒绝和未受管文件保留已有真实安装回归。 |
| `installation.json` AppId 与受管清单核对 | 保留 | 后续每次更新都需要确认安装归属、文件未被修改及回滚范围，不是一次性改名补丁。 |
| 私人归档目录搬迁、目录锁及 CLI 协作锁 | 保留 | 属于现有功能；CLI 与桌面仍可能操作同一实例，锁保护不能因变量含 legacy 而删除。 |
| 卸载辅助程序命名与及时清理 | 保留 | 属于正常卸载资源管理；本次没有证据将它宣称为已修复的长期内存泄漏或持续临时文件泄漏。 |
| 远端服务、证书、事务标记、已发布内核版本与摘要 | 保留真实身份 | 它们对应现有 VPS、协议或固定构建产物，属于持久运维数据，不是本地改名兼容。应用改名不改变生产服务器状态。 |

旧凭据的数据转换是独立的一次性操作，不在正常应用启动、读取凭据或安装流程中执行。源码中的临时授权叙述已改为长期有效的格式约束注释。GitHub 账号、作者、签名和历史发布不修改。

验证包括真实更新/回滚测试、May/旧名 origin 运输门控、全部客户端兼容性与离线资产检查。安装器及更新清单未为审计增加特殊旧版分支。
