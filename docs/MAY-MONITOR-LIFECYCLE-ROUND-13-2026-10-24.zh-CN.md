# 监控支线 M2：May Monitor 生命周期与逐步迁移

编号纠正：本文件记录监控支线，历史文件名中的轮次不代表原主线完成。跨实例编排、通用多入站和 Hysteria2 的状态见[主线路线图](DEPLOY-ROADMAP-2026-10-24.zh-CN.md)。

日期：2026-10-24。本文描述本轮源码和隔离验证；发布与生产迁移是独立步骤。当前生产 Komari、Cloudflare Tunnel、代理配置及用户已安装应用没有变更。

## 目标与兼容组合

在监控支线 M1只读接入基础上，增加 May 服务端和 Agent 的显式部署、升级、核对、一致性备份、恢复及启停入口。用户决定逐步从 Komari 迁移到 May Monitor，因此两套监控可以并存，按节点核验后再决定旧节点的停用时间。

配套候选为 May Monitor Server `0.1.0-rc.2`、Agent `0.1.0-rc.1`、Web `0.1.0-rc.1`。Web 固定原已审查提交，未重新采用上游开发分支。Server RC2 包含监控支线 M1独立只读接口，以及本轮 Agent 凭据核验、初始化日志保护和在线租约修正。RC1 服务端不支持这两个新接入接口。

`config/may-monitor.json` 固定各组件的版本、文件名、字节数、SHA-256 和 May 仓库发行 URL。控制端没有 `latest`、任意 URL 或上游安装脚本入口。候选清单不代表 GitHub 附件已发布；发布前必须核对清单与最终附件完全一致，不能将本地候选当作已发行版本。

## 操作入口和审阅

在「监测」页选择「部署与维护」，明确目标实例、Server／Agent 和操作。只列出已纳管且没有未完成事务的实例。

| 操作 | 行为 |
| --- | --- |
| 只读核对 | 核对 May 所有权、文件摘要、权限、专用账号、服务和实际状态，更新 May 归档。允许正常服务状态变化，拒绝文件漂移。 |
| 安装 | 仅用于没有 May 资源的目标。先备份，再校验固定附件并安装专用服务。 |
| 升级 | 仅接受更高版本；保留既有连接参数、数据和启停状态，不能顺便更改地址。 |
| 应用只读授权 | 仅 Server；从本机加密连接取得摘要、明确 UUID 范围和 30 天期限，经来源指纹复核后下发。 |
| 一致性备份 | 暂停选中服务完成数据库及配置快照，再恢复原运行状态；不重写程序。 |
| 恢复 | 只列同实例、同 May 组件、安装前状态有效的恢复点，校验本机备份摘要及远端机器／事务身份。 |
| 启用／停用 | 只调整选中的 May 服务；执行前重新核对管理连接和组件归属。 |
| 移除 | 移除选中 May 组件的受管程序、配置和服务，保留私有数据、归属记录及无登录系统账号。重新启用使用同组件恢复点。 |

安装／升级的最终审阅显示具体版本、完整 SHA-256、回环端口／管理员名称或 Agent 服务地址。恢复显示任务 ID 和备份摘要；只读授权显示节点数量、到期时间和摘要。密码、Agent Token、原始只读令牌不进入公开表单、计划或任务说明。

## 独立资源和最小权限

| 资源 | Server | Agent |
| --- | --- | --- |
| systemd 服务／无登录用户 | `may-monitor-server` | `may-monitor-agent` |
| 程序 | `/usr/local/bin/may-monitor-server` | `/usr/local/bin/may-monitor-agent` |
| 配置 | `/etc/may-monitor-server` | `/etc/may-monitor-agent` |
| 私有数据 | `/var/lib/may-monitor-server` | `/var/lib/may-monitor-agent` |

Server 配置目录 root:root 0700，环境文件 0600；Agent 配置目录 root:专用组 0750，凭据文件 root:专用组 0640。两个数据根目录均为专用用户 0700。服务不以 root 身份运行，启用 `NoNewPrivileges`、`ProtectHome`、`ProtectSystem=strict` 和独立临时目录；Server 无 Linux capabilities，Agent 只保留监测 ping 所需 `CAP_NET_RAW`。

Agent 的远程终端和自动更新关闭，证书校验开启，默认每 3 秒采集、每 5 分钟上报基础信息、每 5 秒尝试重连。Server 的远程控制、扩展等默认关闭策略沿用已审查版本。

同名账号、文件、服务、配置目录、drop-in、链接、硬链接或归属不明对象会阻止接管。正常数据可以增长；程序及配置被外部编辑时必须先人工核对。不会把任意现有 Komari 安装认领成 May。

## 新服务端接入

1. 选中已纳管 VPS，执行只读核对，确认 May 资源不存在。
2. 安装表单选择空闲的非特权回环端口和管理员名称，审阅固定版本及摘要。
3. 执行时输入新的强管理员密码，控制端加密保存；初始化 Token 自动生成并加密归档。
4. 远端只从固定 May 发行地址下载，校验总大小、SHA-256、归档成员和程序版本后替换文件。
5. 仅监听 `127.0.0.1`；专用初始化 Token 经私有请求头传给本机安装向导，不进入服务日志。
6. 通过实际服务进程、运行二进制身份、初始化和本机 `/ping` 验证后提交。

本入口不自动修改现有 Komari 域名、Tunnel 或防火墙。新 May 的 HTTPS 反向代理／独立 Tunnel 需要另行配置与核验；不得把回环可用视为公网 HTTPS 已验收。

## 逐节点迁移 Agent

1. 保留现有 Komari 节点和服务，先在新 May 服务端创建一个明确节点。
2. 为该节点取得独立 Agent Token；不复用 Komari Token、管理员 Key 或只读令牌。
3. 在 Deploy 对应实例选择 May Agent 安装，填入可信的 May HTTPS 地址。仅同机隔离测试允许 HTTP 回环。
4. 执行时输入 Token。控制端经 SSH 私有通道传递，远端通过配套 Server 的 `POST /api/clients/credential-check` 核对 UUID 和版本；不通过 URL 探测、不自动创建节点、不伪造指标。
5. 查看真实上报、节点时间、UUID、在线与断线重连，再决定是否继续迁移下一节点。
6. 旧 Agent 的停用由用户显式选择；本入口不代为卸载旧监控。

旧历史指标、用户、告警、面板和数据库不会自动导入。新库与旧库并行保留，避免将不同上游版本的数据直接覆盖。

## 只读连接和授权更新

监控支线 M1本机连接使用独立 `may_read_` 凭据、HTTPS 地址和明确的实例到 UUID 绑定。保存后在 May 服务端选择「应用本机只读授权」，审阅范围及期限。

控制端同时核对来源指纹、令牌摘要和 UUID 集合；只有来源指纹相同但参数已被替换仍会拒绝。原始只读令牌留在本机加密档案中；服务端只收到 SHA-256、UUID 列表和期限。应用后在监测页手动刷新，验证实际外部 HTTPS 路径。

连接删除只影响本机。续期、轮换或撤销需要服务端更新环境并重启；不能通过删除本机文件推断远端已经撤销。

## 事务、取消和确认丢失

使用全局互斥锁和 owner，与旧协议、SSH 维护事务互斥；事务和快照本身归属于独立 May 组件。

每次远端变更先创建 `/root/vps-deploy-backups/may-monitor-<任务ID>`，记录机器身份、角色、原始状态、恢复程序摘要和备份摘要，并设置 20 分钟自动回退计时器。SQLite 数据库在选中服务暂停时快照，避免复制仍在写入的 WAL 状态。

文件写入采用先记录原值／计划摘要再原子替换的日志。控制端取消或 SSH 回复丢失后先读取原事务；不重复 Apply、升级、创建账号或提交。已确认提交只同步本地结果；结果不明保留 `NeedsRecovery`，由同实例恢复入口继续核对。

账号创建的确认丢失时，不凭名字删除可能由他人创建的账号。外部文件、权限或额外配置发生变化时停止自动恢复，保留快照和当前数据；不能为了“自动成功”覆盖这些修改。

快照限 2 GiB、100000 项，拒绝链接、异常类型、重复路径、越界成员及不符的账号和权限。数据恢复前将当前数据移入本次私有备份的 `preserved-data-*`，便于人工复核。恢复只处理所选 May 的程序、配置和数据，不触碰另一 May 组件或旧 Komari。

## 故障诊断

| 表现 | 核对方式 |
| --- | --- |
| 发现受管漂移 | 先只读比较配置／权限／服务 drop-in 与记录；不要删除未知文件后盲目重试。 |
| 下载摘要／版本不符 | 原程序不替换，保留失败事务；核对固定发行清单与附件。 |
| 端口冲突 | 检查真正监听进程。正常停止遗留的 `TIME_WAIT` 连接不再误判为冲突。 |
| Agent 凭据核验失败 | 核对 Server 是否为 RC2、HTTPS 路径和节点 Token；不回退到匿名或管理员凭据。 |
| 更新确认丢失 | 使用同实例事务恢复入口核对；不重新提交安装／升级。 |
| 启动失败 | 在目标 VPS 人工查看对应服务和私有日志；确认程序身份、目录权限及数据库状态。 |
| 在线状态与连接不符 | 区分 WebSocket 和 POST 回退；WebSocket 关闭直接撤销其在线状态，POST 回退使用有限租约。过期指标仍按过期展示。 |

## 本轮真实验证

使用新建 QEMU/KVM Debian 12 和 13，一台一份临时磁盘，768 MiB RAM、2 vCPU。仅回环 SSH，文件标记和 DMI UUID 双重核对后才运行；没有连接生产 VPS。

两系统均通过：RC1 新安装与初始化、RC1→RC2 升级、真实 RC1 Agent 凭据校验和指标、授权读取、Agent 停止及重连、一致性备份、重复升级拒绝、取消恢复、程序与数据库同范围恢复、重启后服务运行。旧监控替身的文件、数据和 PID 保持一致。替身用于证明边界，不等于现有生产 Komari 的迁移演练。

测试查出并修复 WebSocket 上报误刷 HTTP POST 在线租约的问题，避免真实断线仍被旧租约标为在线；补充传输边界及竞争回归。RC2 同时停止在服务日志中输出外部提供的首次安装 Token。

| 60 秒单节点持续上报＋每 3 秒只读查询 | Debian 12 | Debian 13 |
| --- | --- | --- |
| Server RSS 峰值 | 40.11 MiB | 53.05 MiB |
| Agent RSS 峰值 | 15.38 MiB | 16.86 MiB |
| Server 平均 CPU，单核百分比 | 0.050% | 0.232% |
| Agent 平均 CPU，单核百分比 | 0.033% | 0.166% |

另有停止 Agent 后 15 秒服务端观测，RSS 峰值分别 44.69／42.43 MiB。短窗口受启动、GC 和测试机负载影响，不能据此声称生产长期稳定或优于其他项目，也不能用短时间 RSS 增减证明内存泄漏或优化收益。

本地验证另包括最终 22 项 Linux 文件系统生命周期测试、最终专项 46 项 .NET 边界断言（此前主回归共 1783；补充无效凭据／缺失清单保护后重跑专项）、隐藏原生维护表单 7 项及既有只读界面 15 项。原生测试未获得前台焦点、未注册托盘、未启动远端任务。服务端执行全套 Go 回归及关键包竞争检测；依赖和源码验证的具体记录随候选构建保存。

Windows 主回归跳过未授权的符号链接创建、未提供运行时的 Reality／远端 Python 实测；本轮 May Linux 生命周期由上述真实 Debian 虚拟机独立覆盖。NuGet 漏洞数据源本次不可达，不能把成功编译当作新一次在线依赖审计。

## 后续范围

下一阶段先准备单节点试迁移清单和独立 HTTPS 发布路径，再由用户选择实际节点与维护时间；核验断线、重连、资源、告警和回退后逐步扩大范围。旧数据导入、长期资源曲线、多节点压力、真实 SSO 和所有可选远程控制扩展不在本轮完成范围。

本轮没有自动安装用户应用、替换生产服务或更改 Route。生产迁移按用户后续授权逐节点执行。
