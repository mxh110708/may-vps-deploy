# 第二十七轮：客户端分享与导入往返

日期：2026-11-02。本轮按原定范围补齐现有协议的分享与导入缺口，随 v0.9.40 一并发行此前第24–26轮及共享实例多线路追加功能。输出对象仍为实际使用的 Mihomo／Clash 和 sing-box／May Route；没有因为存在其他客户端就另加未经验证的格式。

## 本轮修复

| 原问题 | 当前行为 |
| --- | --- |
| Base64 分享列表须先手动解码才能粘贴导入 | 同一导入入口直接接受纯文本或 Base64，使用严格 UTF-8，保留预览及取消。 |
| 分享200节点时附带的尾部换行被当成第201行 | 按非空节点行计数；保留原行号，最多200节点。 |
| 合法列表编码后超过256 KiB，自己的导入界面截断 | 原始输入限512 KiB，解码后仍限256 KiB；界面与模型使用同一上限。 |
| TUIC v5 已有部署和原生配置，但无分享往返 | 增加 UUID＋密码的有限 `tuic://` 导入、分享、Base64及订阅使用。 |
| 普通 TLS 的 VLESS／Trojan 链接被当作不支持的传输 | 增加 TLS TCP/raw 的完整参数往返；VLESS 不使用 Vision flow。 |
| 读取原生配置时遗漏这些 TLS TCP 节点 | 单客户端和双客户端来源读取均保留对应原生对象；未知传输继续拒绝支持声明。 |
| TUIC／普通 TLS 节点可能进入 Reality 专用编辑器 | 使用保留原生参数的外部连接编辑器，支持名称／分组调整和完整链接替换。 |
| 无节点组关联的方案分享可能绕过来源批量事务屏障 | 分享前也核对方案的待恢复来源事务，拒绝输出不确定的节点快照。 |

不改变服务器部署角色，不自动切换系统代理、TUN 或客户端运行配置；查看预览和生成分享文件不会部署服务器。

## 导入、分享和原生输出

1. 在「配置设计 → 节点」选择「导入分享链接」。粘贴每行一个链接的纯文本，或整个 Base64 列表，选择地区与节点用途。
2. 预览逐行的可导入、重复及拒绝结果；密码和完整 URI 不回显。只有明确可导入的行会加入方案，取消不改方案。输入框关闭后清空。
3. 编辑已有 TUIC／普通 TLS 节点时，名称和分组调整保留原生连接、稳定节点 ID 和依赖。更换连接须粘贴完整的新链接，不能用 Reality 字段替代另一协议的参数。
4. 到导出页打开「分享节点链接」，勾选可完整表达的连接，选择纯文本或 Base64。存在客户端入口依赖、不可表达字段或两份原生配置不一致的节点会逐项说明并禁用，不偷偷删字段。
5. 复制或保存到新的 `.txt`。文件含鉴权信息，Base64 仅是编码。分享保存不覆盖已有文件；保存前重新核对来源，来源或方案变化时重新预览。
6. 分享列表可直接回到同一导入入口重新预览。完整配置仍走「生成 → 固定核心校验 → 审阅导出」，Mihomo YAML／sing-box JSON 的读取走现有原生来源入口。

导入预览只证明可表达和字段校验；核心配置解析只证明格式。实际连接必须再验证协议鉴权、TLS／SNI、目标响应及需要的 UDP 回程。不要把“可分享”解释成某个公网节点此刻可用。

## TUIC v5 链接范围

采用现有客户端生态使用的 UUID＋密码 URI 结构，字段名与[3x-ui 的分享格式](https://docs.sanaei.dev/docs/config/tuic/#share-link-format)及[v2rayN 的 TUIC 解析实现](https://github.com/2dust/v2rayN/blob/master/v2rayN/ServiceLib/Handler/Fmt/TuicFmt.cs)核对；本轮验收针对本项目导入后的两种原生输出，不宣称其他客户端对每个查询字段都等价。

```text
tuic://<UUID>:<PASSWORD>@<HOST>:<PORT>?sni=<SNI>&alpn=h3&congestion_control=bbr&udp_relay_mode=native&allow_insecure=0#<NAME>
```

| 项目 | 支持与限制 |
| --- | --- |
| 身份 | TUIC v5 UUID 与非空密码，分别编码；拒绝 TUIC v4 Token。 |
| 端点 | 显式端口、域名、IPv4和方括号IPv6，保留 SNI。 |
| 拥塞控制 | cubic、new_reno、bbr。 |
| UDP 中继 | native、quic；不通过丢弃字段把它们混为一种模式。 |
| TLS | 开启验证；`allow_insecure=1` 明确拒绝。可表达的 ALPN 列表保留。 |
| 心跳与0-RTT | 通用链接仅表达既有10秒默认心跳、关闭0-RTT；自定义心跳、开启0-RTT、fast-open等仍使用完整配置。 |
| 高级原生字段 | 额外证书、ECH、接口绑定、客户端 detour 和其他不可表达字段不得被静默投影到链接。 |

内置 TUIC 默认参数可往返；在通用入站中自定义心跳后可能只有原生配置可用，分享界面会说明原因。转换不会改变已部署的入站、用户、证书或服务器出站。

## VLESS／Trojan TLS TCP

支持两种已有协议的普通 TLS 连接，保留服务器、端口、UUID或密码、SNI、可表达的 ALPN和TLS指纹。`tcp`／`raw` 作为裸流传输名称处理，仍必须启用 TLS。VLESS 采用 `encryption=none`、空 flow 与 XUDP 对应；不把明文连接或 Vision flow 改写成普通 TLS。

Reality＋Vision、WS、gRPC及XHTTP仍由原来的各自分支处理。Reality 的 `type=raw` 与既有 TCP 名称等价；非空 spiderX、未知加密、未知传输或不支持的高级字段仍拒绝，不移除参数后假装支持。

普通 TLS 样例仅列结构：

```text
vless://<UUID>@<HOST>:<PORT>?security=tls&type=tcp&encryption=none&sni=<SNI>#<NAME>
trojan://<PASSWORD>@<HOST>:<PORT>?security=tls&type=tcp&sni=<SNI>#<NAME>
```

## 输出一致性和安全边界

编码前按原生完整允许字段检查；同时持有两种配置时先检查语义一致，再生成链接，并重新解析核对序列化后的连接。URI、原生节点、分组和输出规则分别处理；普通链接不包含业务规则、客户端链式依赖或服务器配置。

使用已有的来源、节点组、受管入站、转发与线路来源复核。待恢复的来源批量事务、凭据轮换、节点组变化或审阅后修改会拒绝旧输出。拒绝路径只显示通用原因，不在错误和任务记录中保存鉴权 URI。

## 验收

第27轮专项通过96项断言：分享／重导入、单原生与双原生节点、UTF-8／Base64、200节点及大小边界、重复／未知参数、字段不一致、待恢复屏障、候选生成和两种固定核心校验。

16个真实客户端场景使用受控回环：VLESS TLS、Trojan TLS分别由 sing-box 和 Mihomo 连接；TUIC覆盖3种拥塞控制、2种UDP中继、2种客户端。每个场景均先分享和重新导入，再完成 HTTPS 与实际应用 UDP；错误鉴权被拒绝。自有进程全部关闭。没有为了此轮进行生产部署或资源调优。

WinUI 通过既有后台接口 `suite.client-roundtrip` 验证12项行为，包括Base64预览、取消、输入清理、脱敏、正确编辑器、改名保留身份、复制接收器和重导入；零窗口激活、零前台采样，不读取或改写系统剪贴板。另回归原 `suite.client-share`。

发行前 Actions 发现 Windows 混合监听夹具仅检查了 TCP 可用性，所选端口的 UDP 被系统拒绝。测试端口分配已改为在回环同时独占检查 TCP／UDP，加入两种单端占用和双端可用性断言；不改宿主网络、不忽略失败的协议检查。其后按新提交重建发行附件并复核 Actions。

维护者使用 `--client-roundtrip-only`，模型子集为 `--client-roundtrip-model-only`；完整流程已纳入 `.NET --group clients`。Python原生来源读取测试覆盖两种QUIC、普通TLS、单／双来源及未知传输边界。主线状态见[路线图](DEPLOY-ROADMAP-2026-10-24.zh-CN.md)，其他客户端格式待明确实际需求后逐项加入。
