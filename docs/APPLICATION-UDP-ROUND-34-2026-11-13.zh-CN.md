## 入口与作用范围

固定 Reality／AnyTLS 角色的「配置出站」与「通用多入站 → 管理入站」共用应用协议规则。独立入站覆盖 SS2022、AnyTLS、Hysteria2、TUIC v5、Reality 和现有 VLESS XHTTP。默认出站、指定出站、入口机直连和阻断继续复用原有资源身份与恢复范围。

应用 UDP 是代理传递的 UDP 请求，不是核心与服务器之间采用的传输协议。Hysteria2、TUIC 或 XHTTP HTTP/3 使用 UDP／QUIC 承载，不等于其中的应用流量都应匹配 UDP 规则。

一条规则可选：

| 应用协议 | 保存与匹配 |
| --- | --- |
| TCP | 旧规则的默认含义；规范保存时省略 `Network`，既有配置和身份不因本轮自动变化。 |
| UDP | 显式保存 `Network: "UDP"`，只匹配应用 UDP 会话。 |
| TCP + UDP | 显式保存 `Network: "Both"`，同一匹配项及去向作用于两类会话。 |

规则仍按显示顺序首条命中；未命中使用原默认出站。相同匹配值可以分别设置 TCP 与 UDP 动作；相同应用协议上的重复项以及与 Both 重叠的同值项会被拒绝，不让重复规则掩盖实际含义。跨不同匹配类型或更宽网段的优先级仍由显示顺序决定。

## 域名、IP 与会话边界

域名规则只使用路由时实际可见的原始目标域名。IP 规则只匹配实际 IP 目标，不为分类增加 DNS 反查、流量嗅探或按 DNS 报文中的查询名称选路。

- 若代理路径保留域名，完整域名与后缀规则可以匹配。
- 若客户端或传输先解析，只向路由层提供 IP，域名规则不会补猜；继续匹配对应地址族的 CIDR 或默认去向。
- 试算选择 TCP／UDP，并输入实际收到的域名或 IP。它是离线规则试算，不证明目标可达、元数据在链路中得到保留或真实命中。
- UDP 按固定核心的目标会话元数据选路，通常在会话首包完成选择；本轮不增加同一关联内更换目的地后的逐数据报重新分类机制。需要不同目标使用不同分类时，客户端应按目标建立独立 UDP 会话，不能将此功能当作逐包安全 ACL。
- 修改策略会重启本次受影响服务，既有 TCP／UDP 会话可能需要重连。新策略不靠继续复用旧会话验证。

「服务器直连」始终使用该 VPS 的网络。需要校园 IP 才能访问的论文库仍须在客户端走校园网络直连，服务器分流不能产生校园身份。

## 固定分类版本与依赖

第26轮规则库的 `Schema: 1`、ID、版本及域名／CIDR 内容格式保持不变。`Network` 属于引用规则，不塞入分类库的匹配原语。同一份固定快照可以分别用于 TCP、UDP 或两者，选择应用协议不会更改快照的摘要。

示例仅为策略片段，全部使用保留域名／网段：

```json
{
  "Version": 1,
  "Rules": [
    { "Kind": "Domain", "Value": "service.example.test", "Action": "Direct" },
    { "Kind": "Domain", "Value": "service.example.test", "Action": "Reject", "Network": "UDP" },
    { "Kind": "Cidr", "Value": "192.0.2.0/24", "Action": "Reject", "Network": "Both" }
  ]
}
```

独立入站的指定去向仍是同目录已存在的32位出站 ID；固定角色仍使用既有的16位附加落地 ID。JSON 中不接受任意原生出站名。删除被 UDP 规则引用的资源同样会被阻止，包含只被 UDP 引用的资源。

最多32条逻辑规则、单规则集2048项、展开4096项和1 MiB 配置上限沿用原设计。独立入站默认与引用资源合计最多8个；固定角色最多7个附加落地。Both 不增加常驻代理进程。

修改 Network、规则顺序、固定版本、去向或来源都会改变对应策略／资源身份。已有客户端验证资格不能继续当作新策略的验收。单纯更新私人规则库不会悄悄改变已部署快照。

## 操作步骤

1. 先建立并核对默认及例外出站资源，确认协议、鉴权、TLS／SNI、地址族和预期出口。已有下一跳支持范围沿用第29轮；本轮没有新增下一跳协议。
2. 打开目标入口的规则编辑器，逐条选择应用协议、匹配项和去向。旧规则最初仍显示 TCP。
3. 分类项选择固定版本；具体 UDP 目的地只有 IP 时，使用明确 CIDR 或默认路径，不凭客户端网页域名推断服务器一定收到域名。
4. 用试算协议选择器比较同一目标的 TCP 与 UDP 结果；需要两个不同动作时建立不重叠的协议项。
5. 保留默认路径的验收目标。现有 HTTPS 默认验收域名继续受保护；新增 UDP 规则还须让对应地址族的 `1.1.1.1` 或 `2606:4700:4700::1111` DNS 回程目标走默认去向。宽泛规则覆盖它时需显式添加默认例外或缩小范围，程序不插入隐藏规则。
6. 审阅应用协议、分类版本、全部引用、受影响服务及恢复范围。取消不会建立远端任务、保存草稿到实例或改动服务器。
7. 执行后等待入口验收和逐去向检查完成；失败或证据不完整时不提交成功。保留真实业务的实际分类核对结果，不能仅用「试算正确」代替。
8. 策略变更后重新验证、生成客户端候选。恢复旧策略时明确选择旧版本／协议范围并审阅，或使用该次事务的恢复点。

## 验证口径

### 入口与默认路径

继续使用真实客户端、入站鉴权及 HTTPS 验收，并按既有条件检查应用 UDP 回程。TCP 成功、QUIC 握手或 UDP 监听存在均不能替代数据报返回。

### 逐出站的有限检查

每个原生出站继续执行验证 TLS 的 HTTPS 出口检查。UDP 策略额外要求默认出站、UDP 规则指定的出站和显式直连完成独立 DNS 数据报往返。

UDP 数据必须经只绑定回环的临时 SOCKS UDP 中继返回。请求使用新的 DNS 事务身份，核对原始问题、响应标志、完整记录和地址族；没有直接 DNS、TCP DNS 或其他去向回退。返回非回环 SOCKS 中继地址时在发包前拒绝。

返回证据标为 `NativeOutboundUdpDns`，并与当前配置、策略及原生出站证据共同核对。它证明该去向支持本次应用 UDP 和指定 DNS 地址族，**不测量 UDP 公网出口 IP，不证明任意游戏／QUIC 业务质量，也不等于任意域名已经命中分类**。HTTPS 出口 IP 与 UDP 回程分开记录。

只涉及 TCP 的旧策略不增加新的 UDP 分支检查。UDP 策略使用当前已安装核心的临时配置，不覆盖正式配置、不修改主机 DNS／代理／防火墙；核心、私密临时文件与套接字均有预算并在完成、失败或取消时关闭。

## 失败与恢复

| 情况 | 行为 |
| --- | --- |
| TCP／HTTPS 成功但 UDP 无匹配回答 | 该去向不能通过 UDP 验收，不用 TCP 结果补齐。 |
| 指定分类出站不可用 | 不改走默认出站或直连；有限检查失败，维护事务恢复本次范围。 |
| UDP 规则选择阻断 | 对新目标会话执行核心拒绝；测试同时检查目标未收到报文，不把超时本身当唯一证据。 |
| 域名丢失 | 只按 IP 规则或默认去向处理；不记录为域名命中。 |
| 协议范围、分类版本、来源或配置改变 | 拒绝旧证据／过期审阅，要求按新身份重新验证。 |
| 服务写入／提交回复丢失 | 沿用原有事务身份核对，不重放写入。 |
| 恢复范围之外的资源变化 | 拒绝覆盖，保留待恢复状态与私人材料。 |

独立入站按实际受影响身份恢复，固定角色只恢复本角色；其他入站、SSH、监控和 Tunnel 不参与。托管证书维护完成后也复用相同分类验收，避免只验证默认连接便遗漏原有 UDP 例外。
