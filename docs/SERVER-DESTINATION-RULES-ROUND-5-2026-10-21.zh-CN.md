# 第五轮：服务器 TCP 域名与网段分流

本轮在已有固定落地上增加有顺序的 TCP 分流例外，支持 Xray Reality 和 sing-box AnyTLS。未命中的 TCP、全部 UDP 仍使用原固定落地。规则、审阅、更新和移除沿用前四轮的来源校验、配置摘要与组件恢复事务。

## 支持范围

| 项目 | 本轮行为 |
| --- | --- |
| 入站 | Reality 主备端口及双栈监听；或 AnyTLS 单入站；每个组件独立配置 |
| 默认去向 | 已保存的同一个 Shadowsocks / SS2022 落地，不提供直连故障备用 |
| 例外协议 | **仅 TCP**；UDP 不应用这些例外，保留原固定落地 |
| 匹配 | 完整域名、域名及其子域名、IPv4 / IPv6 CIDR |
| 动作 | 所选落地、入口机直连、阻断 |
| 顺序 | 从上向下，首条命中；可上移、下移、移除 |
| 数量 | 每个组件最多 32 条，每条一个匹配值 |
| 暂未支持 | UDP 分流、多个不同落地、默认直连模式、GeoIP / Geosite、正则、远程规则集、端口条件和任意多入站 |

这是一台入口服务器上的出站策略。客户端配置不需要增加落地代理，也不会把这些规则写入客户端模板。

## 为什么本轮限定 TCP

真实 AnyTLS 回环测试发现：同一 UDP 会话先向允许的目标发送，再向拒绝的网段发送时，后续数据包可能继续使用第一次确定的出站，不能把会话路由当作逐包过滤器。官方 [UoT 路由实现](https://github.com/SagerNet/sing-box/blob/v1.14.2/common/uot/router.go)把整个 packet connection 交给路由，且 [UoT 协议](https://sing-box.sagernet.org/configuration/shared/udp-over-tcp/)允许非连接格式携带不同目标地址。

因此，每条新增的原生例外规则显式限定 `network: tcp`，元数据也记录 TCP 范围。界面、试算和最终审阅均明确说明 UDP 不受这些规则影响。没有关闭 UDP，也没有通过强制连接第一个目标、缩短会话或修改客户端来掩盖问题。

UDP 分流需要另行实现并验证会话拆分、目标变化、跨地址族与恢复行为，本轮没有将其标作已完成。

## 使用与试算

1. 打开实例的「配置出站」，选择 Reality 或 AnyTLS。
2. 沿用或选择已经保存的落地，核对默认落地的预期网站出口 IP。
3. 展开「TCP 分流例外」，添加规则，填写匹配类型、匹配值和去向。
4. 用「TCP 试算目标」输入域名或 IP，检查首条命中的去向。此步骤不联网，不代表服务或网站可用。
5. 调整顺序，进入最终审阅，核对规范化后的值、全部规则、默认落地、明确直连的影响和原有规则。
6. 确认后才执行远端任务。表单返回、审阅返回和试算都不写服务器。

例如：

| 顺序 | 匹配类型 | 值 | 去向 |
| --- | --- | --- | --- |
| 1 | 完整域名 | `ai.example.test` | 所选落地 |
| 2 | 域名及其子域名 | `example.test` | 入口机直连 |
| 3 | 目标 IP 网段 | `192.0.2.0/24` | 阻断 |

TCP 访问 `ai.example.test` 命中第一条；访问 `web.example.test` 命中第二条；`badexample.test` 不属于该后缀，继续使用落地。直接以 IP 访问文档示例网段时命中第三条。UDP 对上述目标仍按原固定落地处理。

直连是入口服务器直接连接网站，使用入口机的网络、DNS 与原有直连地址族策略；不是客户端本机直连，也不是落地离线时的备用动作。

## 匹配边界与输入处理

- 域名不区分大小写，规范化尾部点，国际化域名转换为 ASCII；完整域名不匹配其子域名。
- 后缀匹配包含根域名及点分隔的子域名，不匹配只是字符串末尾相同的其他域名。sing-box 分别生成根域名和带点后缀条件；Xray 使用明确的域名匹配前缀。
- CIDR 只匹配原始 IP 目标，不为了匹配网段额外解析域名，也不启用嗅探。网段中的主机位归零，最终审阅展示实际生效的规范网段。
- 不接受 URL、端口、通配符、正则表达式、作用域标识、IPv4 映射 IPv6 网段、错误前缀、控制字符、非字符串字段或重复的规范匹配项。
- 多条规则可以相互包含；首条命中决定去向。试算和上下移动用于核对这种覆盖关系，不自动重排规则。
- 走落地的 IP 网段须与落地预期出口地址族相符。入口原策略仅允许 IPv4 直连时，不能给 IPv6 网段设置直连。原策略和地址族约束不会因添加规则而被解除。

同一表单中切换入站组件会分别保留尚未提交的规则、选择及出口草稿，另一组件不会继承这些规则。最终执行仅提交当前所选组件；返回后不保存未提交草稿。

## 验收、来源与恢复

默认落地仍需通过真实代理的 HTTPS、出口 IP 和 UDP 验收。若 TCP 规则将现有出口查询目标改为直连或阻断，会明确阻止审阅执行，要求缩小规则范围或添加更靠前的明确落地规则。应用不会插入隐藏规则来绕过用户规则，也不会把入口机直连的出口检查冒充落地验收。

这项约束只保证原有默认落地验收路径仍有意义，不等于逐条验证用户所有网站或网段。每条生产例外是否能访问预期目标，仍需在获授权的实际目标上检查。试算只验证匹配关系。

规则使用当前保存的同一个落地快照。来源刷新不会自动改服务器；名称、参数、出口及受管凭据变化仍显示第四轮的提示。受管节点来源指纹包含服务器路由元数据，策略变化后需重新提取来源；拓扑标注将其显示为「默认服务器落地」及「存在服务器 TCP 分流例外」，避免把默认出口误作所有目标的唯一出口。

生成时在原配置上增加规则，不重建入站。规则顺序和协议范围参与归属摘要；删除、重排、外部编辑或元数据与配置不符时拒绝覆盖。仅移除例外会恢复原固定落地；移除整个受管链路会同时删除例外，并在审阅后恢复链路建立前的原策略。

升级、入站凭据轮换、手动协议配置恢复及任务失败恢复均保留或按备份还原规则、默认落地和范围标识。失去写入或提交回复时先对账，不重放写入；失败或取消只恢复本次授权范围，另一个组件的配置和规则保留。

## 验证记录

- Tests 与 Desktop Release 构建通过；完整 .NET 回归 **1315 项断言**，较第四轮新增 **114 项**，包括真实 Python 配置生成、固定核心校验、分客户端导出和删除流程。
- 两套真实回环分别经过 AnyTLS → SS2022、Reality 主／备 → SS2022。验证 TCP 的 CIDR 阻断、完整域名优先级、后缀根域名、默认落地和明确直连；落地进程停止后，默认请求失败，明确直连仍能工作。
- TCP 阻断测试先直接核验目标可用，再检查经代理的请求未到达该目标；不是用一个本就不可达的地址判断阻断成功。
- UDP 同会话更换目标的测试确认 TCP 例外不改变其原固定路径；落地停止后也没有绕过落地直连。原始未设置例外的两套回环继续执行。
- 配置行为覆盖双栈规则范围、域名边界、IDN、CIDR 规范化、错误字段、数量限制、重复项、地址族、验收覆盖、规则漂移和审阅指纹；覆盖新增与替换策略的失败、取消、回复丢失、升级、轮换及配置恢复。
- 原生 WinUI 隐藏测试 **19 组通过**，包括规则增删、顺序试算、非法输入保留表单、验收路径检查、组件草稿隔离、规范化审阅和已有规则的移除审阅。截图包含滚动后的规则编辑区；测试不使用鼠标或全局输入，不激活前台窗口。
- 隐藏测试退出证明记录 0 次窗口激活、0 次前台采样、无托盘注册、无全局输入和无未完成任务，测试实例已关闭。458 个文本文件的秘密扫描、差异空白检查、新文件尾随空白与文档本地链接检查通过。
- 本轮未修改远端 Bash 脚本、安装器、依赖或锁文件。构建中的 `NU1900` 仍表示 NuGet 在线漏洞元数据不可达，在线审计没有完成。

真实 Reality 回环仍要求 Windows 和 `MAY_TEST_XRAY` 指向已核验的官方 Xray 26.3.27；缺少运行条件时明确跳过。该核心只在忽略的开发缓存中，不新增到应用分发包。可使用 `--server-rules-only` 运行本轮专项测试；完整回归同样包含它。

本轮没有连接生产 VPS、修改现用代理配置、安装、推送或发布。回环测试、配置检查与模拟事务不能代替生产网络、实际白名单和用户网站的验收。
