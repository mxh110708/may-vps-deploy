# 第六轮：服务器 TCP 多落地分流

本轮在第五轮目的地规则上增加多个独立的 Shadowsocks / SS2022 落地。一个 Reality 或 AnyTLS 组件仍保留一个默认落地，TCP 规则可以明确选择附加落地；未命中的 TCP 和全部 UDP 继续使用默认落地。配置由现有组件持有，不新增常驻面板、Agent、数据库或轮询任务。

## 支持范围

| 项目 | 行为 |
| --- | --- |
| 入站 | Reality 主备端口和双栈监听；AnyTLS 单入站；组件之间独立 |
| 数量 | 一个默认落地，最多 7 个附加 TCP 落地；规则上限仍为 32 条 |
| 落地类型 | 已保存方案中的原生 Shadowsocks / SS2022；IP 端点；无插件、客户端 detour 或额外拨号设置 |
| 匹配 | 有顺序的完整域名、域名后缀、IPv4 / IPv6 CIDR，首条命中 |
| TCP 去向 | 默认落地、指定附加落地、入口机直连、阻断 |
| UDP | 全部保留默认固定落地，不应用 TCP 例外 |
| 故障行为 | 指定落地失败时连接失败，不改用默认落地、其他落地或直连 |
| 来源 | 每个落地分别锁定方案、节点和内容摘要；来源刷新不自动改服务器 |
| 维护 | 升级、入站凭据轮换和协议配置恢复保留完整多落地策略，并复验附加落地 |

本轮没有增加独立端口转发、任意多入站、UDP 逐目标分流、默认直连模式、GeoIP / Geosite、远程规则集或故障自动选择落地。

## 使用方式

1. 打开实例的「配置出站」，选定 Reality 或 AnyTLS。
2. 核对默认下一跳及其预期网站出口 IP。
3. 在「附加 TCP 落地」添加已保存的节点，分别填写预期网站出口 IP。
4. 在「TCP 分流例外」添加匹配条件，去向选择对应附加落地。默认落地、直连和阻断仍可使用。
5. 用本地试算核对目标会命中哪个落地，再核对最终审阅中的所有落地、独立出口、规则顺序及原策略。
6. 最终确认才执行服务器任务；返回表单、试算或取消审阅均不连接或写入服务器。

例如，默认落地 A 承接一般流量，`ai.example.test` 经附加落地 B，`media.example.test` 经附加落地 C。三个名称都是示例；本轮不内置业务网站清单，也不改变客户端规则模板。

每个附加落地必须被至少一条规则引用。规则仍在引用时不能直接删除落地，需先修改或删除对应规则。不接受重复来源、重复连接参数、超出数量限制或指向当前入口机的下一跳。相同服务器的不同 SS 用户仍可分别使用，不按服务器地址粗略去重。

在同一个表单内切换组件会分别保留默认落地、附加落地、每个出口地址和规则草稿；最终只提交当前组件。已删除或不再受支持的来源保持缺失状态，不能因为候选列表变化就自动选另一个节点。

## 身份、规则与地址族

附加落地采用与显示名分离的稳定 ID，原生标签为 `may-hop-<id>`。规则持有该 ID，修改显示名不会把规则悄悄转向其他节点。规则动作从附加落地改成默认落地、直连或阻断时会移除旧目标引用；缺失的引用阻止提交，不默认降级。

来源节点的改名、鉴权、服务器参数或出口标注变化均需要重新审阅。状态说明会分别检查默认和附加来源；已经应用的服务器继续使用原快照。维护服务器已有链路不要求来源方案仍存在，但重新配置需要有效的新来源。

走指定落地的 **IP 网段** 根据该落地的预期出口地址族检查，不能借用默认落地的地址族通过检查。域名仍交给原有落地及其解析策略处理，不额外启用入口 DNS 解析、嗅探或强制解析策略；预期出口标注不等于强制所有业务域名使用该地址族。

默认出口查询目标继续受保护。规则不能把默认验收目标送往附加落地、直连或阻断；可以通过更靠前的明确默认落地规则保留验收路径。程序不插入隐藏优先规则。

配置仍在已归档的原配置上编辑，保留监听和入站凭据。每个受管原生出站和整组有序规则都有归属摘要；无归属标签、缺失出站、重复标签、原生内容漂移或元数据与规则不符时拒绝覆盖。

## 独立验收与恢复

默认落地沿用从客户端经过实际入口的 HTTPS、出口及 UDP 验收。每个附加落地由入口机另外执行一次独立验证：

1. 重新读取受管服务器配置，检查归属和规则，提取已经生效的附加出站。
2. 使用该组件当前安装的核心，启动仅监听 `127.0.0.1` 的临时 SOCKS 代理；只包含一个对应 SS 出站，不配置直连或其他落地作为备用。
3. 经 SOCKS 建立目标连接，使用系统 CA 校验证书和主机名的 HTTPS 请求查询公网出口，结果必须与此落地的预期 IP 完全一致。
4. 顺序验证全部附加落地；任一失败、取消、缺项、重复结果或出口不符都不能提交。
5. 正常或受控异常退出时结束临时核心并清除私有临时配置，不安装服务或修改系统代理。每个落地有约 20 秒探测预算，整段远端程序有 210 秒上限。

生产查询使用 `api.ipify.org` / `api64.ipify.org` 的 HTTPS 接口。默认落地的客户端验收和附加落地的入口机验收分别记录，后者明确标注 `EntryServer` 与 `TCP`；不会冒充从用户本机经过完整入口的业务访问。

附加探针确认的是 **入口机 → 指定 SS 落地 → HTTPS 出口查询**。它不枚举每条生产业务规则，也不能保证所有网站、地区库和网段均可达。多落地原生规则的真实转发另有本地实际核心测试；生产业务仍需授权后针对真实目标检查。

应用、升级、轮换或恢复中的验收失败，会沿用当前事务恢复本次组件范围。另一个组件及其路由不变；SSH、防火墙和监控不纳入本次出站写入。写入回复丢失先核对事务，不重放写入；提交回复丢失也按已有事务状态核对。移除整个受管链路会一并移除附加落地和例外，恢复原出口策略。

## 验证记录

- Tests 和 Desktop 的 Release 构建通过。完整 .NET 回归 **1468 项断言**通过，比第五轮增加 153 项；包括实际 Python 配置生成和固定客户端核心校验。
- 真实 AnyTLS → SS2022 与 Reality 主／备 → SS2022 多落地回环通过。停止附加落地后，命中它的请求失败，而默认请求继续成功；重启附加落地、停止默认落地后，指定附加落地仍能转发。未配置例外和第五轮的 TCP／UDP 测试继续通过。
- 新增探针使用实际 Xray、sing-box 与 Python 完成 **34 项断言**：两个落地全部成功、出口不符、第二个落地不可达、不受信任证书和受控取消。验证没有部分成功标记、凭据输出、存活的探针子进程或临时鉴权配置。上述 34 项包含在 1468 项内。
- TLS 测试先核对本地目标确实可用，再让真实代理访问；仅对该测试进程提供合成 CA，不写入 Windows 证书库。最初使用 Windows TLS 服务端的临时证书目标自身不可用，改用独立 OpenSSL 测试目标后完成复验；产品探针没有关闭 TLS 校验。
- 行为测试覆盖双落地渲染、默认与指定规则、不同出口地址族、缺失／重复／漂移／自环／未使用落地、来源变更和审阅摘要、缺项或伪造验收、取消、写入与提交回复丢失、升级、轮换、配置恢复及组件隔离。
- 隐藏原生 WinUI 测试 **27 组通过**，新增 8 组涉及独立出口、未使用落地、引用删除保护、具名试算、组件草稿、脱敏审阅、现有多落地预选与移除、缺失来源保护。已检查编辑区和审阅截图，测试实例已关闭，退出证明记录 0 次窗口激活、0 次前台采样、无托盘、无全局输入和无未完成任务。
- 新增远端探针的 **7 组 Python 边界测试**及 Bash 语法检查通过；旧出站 Bash 行为检查执行 19 组，其中 2 组因 Windows 链接权限跳过。既有 .NET 链接测试也明确跳过，不将缺测计为本机验证通过。465 个文本文件的秘密扫描、Git 差异空白、新文件尾随空白、Bash LF 和新增文档的本地链接检查通过。

实际 Reality 回环仍要求 Windows 和 `MAY_TEST_XRAY` 指向已核验的官方 Xray 26.3.27；探针真实测试还需 `MAY_TEST_PYTHON`。运行条件缺失时明确跳过；开发缓存核心不纳入发行包。专项入口为 `--server-hops-only`，探针专项为 `--hop-probe-only`；完整回归同样覆盖本轮。

本轮没有连接生产 VPS、修改现用代理、安装、推送或发布。安装器、依赖及锁文件未修改。构建中的 `NU1900` 表示在线 NuGet 漏洞元数据不可达，在线审计没有完成。ShellCheck 不在本机可用命令中，未声称完成其检查。

## 实现入口

- `ServerOutboundRouting.Hops.cs`：附加来源、原生出站、归属与逐项验收结果。
- `ServerDestinationRules.cs`：稳定目标引用、选定落地的地址族、具名试算和原生规则。
- `WorkflowEngine.ServerOutbound.cs`、`WorkflowEngine.Deployment.cs`：应用及维护时的独立探针和事务接线。
- `MainWindow.ServerHops.cs`、`MainWindow.ServerOutbound.cs`：多落地编辑、出口草稿和来源状态。
- `assets/remote/server-hop-probe.sh`：现有核心的临时 SOCKS、TLS 与出口验证。
- `ServerHopTests.cs`、`ServerHopProbeTests.cs`、两套 `*OutboundLoopbackTests.cs` 和 `tests/test_server_hops.py`：行为、维护恢复及实际流量验证。
