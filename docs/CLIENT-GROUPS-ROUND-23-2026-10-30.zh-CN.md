# 第二十三轮：节点组复用与客户端输出一致性

本文对应 v0.9.39 的配置设计功能。它管理控制端的可复用连接快照，不创建服务器服务，也不托管在线订阅。既有协议、服务器下一跳及跨实例线路的边界仍分别适用。

## 节点组与方案

方案决定客户端目标、基础配置、业务默认出口、输出筛选和导出文件。节点组保存一组可以一起使用的节点，包含原生连接、地区归属、入口依赖和原始来源。一个节点组可以复用到多个方案，各方案分别保留引用的版本。

保存节点组不会重写原方案。更新节点组也不会后台改写其他方案或自动发布客户端文件：使用者必须查看差异、确认同步，再重新生成并校验配置。节点组没有定时刷新、网络抓取或第二个常驻服务。

节点组及其中的订阅来源信息位于应用私人归档的 `private/client-node-groups/`，通过与方案相同的凭据保护器保存；Windows 使用现有加密实现。不要复制原始归档作为公开分享材料。预览只显示名称、变更种类和影响说明，不展示鉴权值。

## 保存与更新

1. 打开「配置设计」，创建或打开方案，完成节点导入和连接关系。
2. 在「节点」页选择「保存节点组」，填写名称并勾选成员。一次保存 1–200 个节点，保持方案中的顺序。
3. 若选择了落地，必须同时选择它依赖的地区入口。原生 `detour`／`dialer-proxy` 引用的节点或地区也必须在快照中，避免把一个不能独立使用的半条路径保存为完整组。
4. 「保存到」选择新建，或显式选择更新已有组。更新使用打开对话框时的版本进行核对；其他操作已更新该组时，当前保存会被拒绝。
5. 保存后在需要的方案中选择「复用节点组」。原方案继续独立编辑；如需改变组的成员或参数，应重新保存组快照，再在引用它的方案中同步。

更新已复用的节点组时会保留原成员身份。把它另存为新的组则获得独立组身份。不能通过重名或相同连接自动接管其他来源的节点。

## 复用、同步与解除关联

1. 打开目标方案，在「节点」页选择「复用节点组」。目标方案必须有该组使用的地区布局；不会隐式创建或改写业务默认出口。
2. 选择组并查看差异。名称与现有节点、内置动作或布局组冲突，连接与其他来源重复，或缺少所需地区时，应用按钮不可用。先调整方案或重新保存合适的组。
3. 确认后，节点加入当前方案，保留全部原生参数与来源。节点在不同方案有各自本地身份，同组后续同步保留这些本地身份。
4. 已关联组通过「同步预览」读取最新快照。新增、变化和删除分别显示，其他节点保留。删除成员影响到业务默认出口时，默认值被清空并要求用户重新指定；不会静默换成直连。其他节点依赖被删除的成员时，阻止应用。
5. 同步前发现本地连接或归属修改，且与最新组内容不一致时，阻止覆盖。可以取消，或「解除关联」后独立保留并编辑当前节点。
6. 解除关联保留节点、鉴权、原生高级字段及原始来源，不修改节点组或其他方案。随后保存方案。仍有已保存方案引用时，不能删除组；解除这些引用并保存后再删除。

关闭差异窗口不改变方案。同步应用后仍要保存当前方案；原候选会失效，需要重新生成和校验。

## 来源与导出

生成、核心校验、准备导出和实际写入前都会复核关联版本及其成员。节点组已更新、归档缺失、成员被修改或移除，都会阻止沿用旧候选。既有文件来源摘要、受管实例、独立入站、转发及链路来源也继续复核。

组保存的是手动确认的订阅快照，复用不会联网刷新订阅。需要刷新订阅时，先在管理该订阅的原方案完成获取与差异确认，再更新节点组。关联方案之后分别同步。完整配置或分享文件不会携带用于管理来源的订阅 URL。

| 输出 | 本轮行为 |
| --- | --- |
| Mihomo / Clash YAML | 使用节点原有 Clash 连接，保留鉴权、TLS、传输与地区／业务分组；经固定 Mihomo 校验。 |
| sing-box / May Route JSON | 使用节点原有 sing-box 连接；普通协议用固定官方核心，XHTTP 用配套 May Core 校验。不会把 May 扩展宣称为上游核心能力。 |
| 纯文本分享链接 | 只输出已选且可完整表达的独立连接；不携带业务规则或客户端组依赖。依赖入口的落地、不可等价表达的参数仍明确拒绝。 |
| Base64 链接列表 | 与纯文本使用同一选择和序列化规则，只增加编码；Base64 不提供加密。 |

不因为支持完整配置而声称每种协议都具有通用 URI。TUIC 等仍按现有能力报告决定，无法完整分享时使用完整配置。第三方客户端的版本差异需要实际验证，不能仅因接受 YAML／JSON 就声称兼容。

读取现有配置已补齐 Hysteria2 与 TUIC v5 的单格式／双格式提取，完整保留原生字段；仅有一个客户端表示时，不伪造另一个客户端的配置。

## 常见问题

- **节点组已更新**：在对应方案同步预览；若要继续使用旧参数，解除关联后独立保存，然后重新生成和校验。
- **本地修改冲突**：取消同步，先保留或另存本地修改；不要通过删除来源字段强行绕过审阅。
- **默认出口为空**：在「连接与分组」重新指定有效出口，之后再生成。不会自动直连。
- **来源失效**：回到原始受管实例、入站、转发或订阅完成更新与验收，重新保存组快照。仅重试导出不能恢复来源资格。
- **组不能删除**：解除所有保存方案的引用并保存；仅退出编辑不等于已保存解除操作。
- **分享格式不支持**：完整配置可以保留更多参数。分享错误不会自动省略字段或回退为其他传输。

## 验收与范围

本轮回归覆盖加密读回、两个方案复用、差异取消、参数变化、旧候选拒绝、节点身份、名称／连接冲突、上游完整性、成员移除影响、手动解除与删除保护。实际配置由现有生成器输出，再用固定核心校验并重新读取，核对原生连接及显式落地上游。

原生桌面使用现有后台接口 `suite.client-groups`；合成归档中测试保存、取消、复用、预览与重复同步，要求不激活窗口、不出现在切换器或托盘。CI 同时运行跨平台客户端回归和 Hysteria2／TUIC 来源提取测试。

上一轮 CI 的防火墙模板独立检查缺少共享 `mxh_firewall` 函数。本次改为先加载仓库内同一辅助函数再运行模板，仍使用真实 nftables 检查，未将失败改成跳过或忽略。

本轮不安装桌面更新，不操作生产 VPS，不增加在线订阅托管、配额和计费。

### 本地验证记录

- 节点组专项 34 项断言通过，包含实际双客户端生成、固定核心校验、连接与显式入口往返、来源轮换和拒绝旧候选。
- 完整客户端组 751 项断言通过；随后补充的地区默认值、循环依赖及复用订阅来源保护包含在上述最终节点组专项。其余组分别为 foundation 272、XHTTP 144、chains 897、QUIC 194、UDP 257、operations 884，全部通过。Windows 无符号链接权限的两个测试由 Unix CI 覆盖。
- 原生隐藏界面 8 项行为通过；窗口激活 0、前台采样 0，不注册托盘、不进入切换器，测试应用已关闭。
- Hysteria2／TUIC 原生来源在两种单格式及双格式共 6 个场景完整读回；主项目验证入口通过。新增更新元数据测试后，敏感信息扫描覆盖 671 个文本文件。
- 既有 WS／gRPC 真实验收修复 stdout 计数任务与 HTTP 响应的先后竞态后通过，仍要求正确响应、目标收包和真实 UDP，不以延长网络失败超时放宽结果。

上述是控制端隔离验收，不是新跑一轮生产迁移或公网长测。第二十二轮真实 Debian 双机与重启证据继续见对应报告；本轮未再次修改这些测试或生产主机。

本次 Actions 另捕获旧 Linux 核心升级夹具的端口竞争：先选出的客户端 UDP 端口可能等于随后启动的 SS 服务器端口。改为服务器启动后再申请客户端端口，并显式排除已分配的服务器与客户端 TCP 端口，保留真实核心启动、认证与 UDP 回程标准；Debian 矩阵改为分别跑完，避免另一发行版结果被提前取消。

发行交付检查发现包含配套核心的 ZIP 超过旧 300 MiB 附件门限。新版本统一使用 512 MiB 有界限制，仍按实际大小、SHA-256 和固定下载来源校验，清单上限保持更小范围。Windows 元数据回归与 CLI 更新回归覆盖新包大小、超限、错误来源和摘要。旧便携版本首次须手动下载本版 ZIP；安装版使用仍在旧限制内的安装器更新。

更新专项本地通过 19 项 Windows 密钥／ACL／元数据断言和 52 项 CLI 更新断言；只有合成接收器和临时目录，没有调用真实安装器。
