# 第二轮：输出规则、客户端能力与订阅来源

本轮沿用第一轮的节点、连接图、轻量诊断和导出事务，完善「来源 → 本地方案 → 输出处理 → 候选 → 校验 → 审阅导出」。入口仍在 WinUI 的「配置设计」。

## 输出规则

在方案的「生成与导出」页点击「筛选与命名」：

| 设置 | 行为 |
| --- | --- |
| 包含名称 | 每行一个子串，不区分大小写；命中任一项保留，留空保留全部 |
| 排除名称 | 每行一个子串，不区分大小写；排除优先 |
| 协议 | 每行一个名称，例如 `vless`、`anytls`、`ss`；留空不限制 |
| 节点用途 | 全部、入口或落地 |
| 替换文本 | 区分大小写的普通文本替换；不是正则表达式 |
| 前缀、后缀 | 只作用于输出名称 |
| 顺序 | 保留源顺序，或按输出名升序、降序；排序使用固定序数比较 |

先点击「预览」，核对保留／筛除数量、逐项名称变化、输出顺序和客户端能力，再保存规则。返回或取消不修改方案。默认不开启输出规则，沿用原有源节点与顺序。

这些规则只生成有效方案的副本，不改源节点的 ID、原名、凭据、归属或私人归档。业务默认值、顺序列表和已知原生上游引用与输出名一起映射，两个客户端使用同一份处理结果。连接图和按需诊断继续展示源方案，最终输出名称和筛选结果在生成预览中核对。

不执行 JavaScript、外部命令或任意转换脚本。包含、排除各最多 32 行，协议最多 16 行，单项文本最多 4096 字符；未知处理字段明确拒绝。输出名仍限 1–120 个可打印字符。

以下情况阻止生成，需先调整规则或连接关系：

- 所有节点被筛空。
- 输出名重复、与组名／内置名称冲突，或复用其他源节点的名字造成引用歧义。
- 业务组明确选择的默认出口被筛除。
- 保留的落地失去入口，或保留的节点失去原生上游。
- 保留下来的来源自定义选择组，其显式默认节点被移除。

没有被引用的空地区组可从生成结果中移除，预览会列出。规则不会把缺失的业务默认值或自定义组默认值自动替换成 `DIRECT`。来源自定义组的检查在生成器读取原生配置时执行，发现问题会停止并给出中文提示；修正来源中的默认值后重新生成。

保存规则会使旧候选失效。生成规范记录规则摘要，即使绕过界面改变规则，也不能继续使用旧的校验结果导出。DNS、TUN、自定义规则和未涉及的原生配置继续由现有构建器保留。

## 客户端能力报告

「预览与能力报告」按实际选择的 Clash / sing-box 目标逐节点展示：

- 是否具有该目标的原生节点配置，名称／标签、服务器、端口是否完整。
- 协议、TLS、Reality、ECH 的配置状态。
- 显式 UDP 设置或协议默认值，以及客户端链式字段。

缺少所选目标的原生配置时，生成入口阻止输出，不静默省略节点，也不猜测另一客户端的等效配置。只选择一个目标时，不要求未选目标的参数。

这是配置完整性和功能标注报告，不宣称所有高级字段已经通过运行时验收。原生高级参数完整保留，之后仍须执行固定版本 Mihomo / sing-box 的实际校验。报告不等同于 UDP、TLS 握手或公网线路的实际连接测试。

## 手动订阅来源

### 添加与下载

在「节点」页选择「添加订阅来源」，填写来源名称、URL、下载方式、默认地区及用途，点击「获取并预览」。

- 本轮接受纯文本或 Base64 / Base64URL 分享链接列表，支持未补齐的 Base64 填充。
- 节点协议及参数范围沿用第一轮，不通过订阅入口扩大协议支持范围。
- Clash YAML / sing-box JSON 继续通过「读取现有配置」使用；本轮不把它们自动转成分享链接列表。
- 远程来源使用 HTTPS，本机服务可使用 HTTP；拒绝 URL 内嵌账号密码和片段。
- 下载可跟随系统代理、直连，或明确指定无认证的 HTTP / HTTPS / SOCKS5 代理。不会修改系统代理、TUN 或正在运行的客户端。

URL 输入框遮蔽显示；地址、查询令牌和节点凭据随方案加密保存。来源列表和差异预览只展示来源名称与主机名，错误信息不回显完整 URL。相同地址在同一方案中只能有一个来源管理者。

整次下载最多 30 秒，建立连接最多 8 秒；最多跟随 3 次重定向，不允许从 HTTPS 降到 HTTP。响应头限 8 KiB，解压后的响应体限 512 KiB；节点文本、行数和单行长度继续遵守第一轮限制。支持 gzip、deflate 和 Brotli，使用严格 UTF-8 解码。不将订阅响应正文写入磁盘。

通过既有「取消任务」停止下载。下载完成后，差异计算在后台任务中执行；出错或取消均不会更新源节点。没有自动刷新计时器或常驻下载进程。

### 差异与身份

「订阅来源差异」逐项列出新增、删除、参数变化、来源改名、引用影响和冲突。新增项展示协议及端点，参数变化标出鉴权、加密方法或 TLS 等类别，不显示密码或密钥值。确认前不修改方案。

匹配顺序如下：

1. 先比较完整连接参数摘要，名称不同也可识别为同一连接，保留节点 ID。
2. 参数变化时，仅在同一来源内，原来源名称、协议、服务器和端口唯一匹配的情况下提出更新。
3. 名称和连接参数同时变化、或端点变化而无法确认身份时，列为新增与删除，不仅凭 IP／端口猜测覆盖旧用户。

仅来源改名时，未手动覆盖的显示名会同步；本地覆盖名保留。自动解决重名产生的序号后缀在下一次刷新中保持稳定。多个节点同时交换名称时，引用一次性映射，避免连续替换把业务组指向另一个连接。

确认参数更新后保留 ID、用途、地区／连接组和本地出口标注。来源未变而本地参数有修改时，保留本地修改。来源与本地都修改了同一连接，或来源移除了本地已修改的连接时，更新被阻止。

其他来源、受管实例或手动节点中已有相同连接时，保留原归属，订阅不接管该连接。来源移除节点时展示对默认出口和上游依赖的影响；受影响业务默认值标为待重新指定，旧候选失效。部分链接解析失败、身份有歧义或来源为空时，不应用整个来源更新，不用「已解析部分」清空剩余节点。

无变化的刷新只更新时间和内容摘要，不更换节点 ID，也不强制丢弃原候选。实际参数、名称或关系变化后，必须重新生成并校验。

### 本地修改与停止管理

发生冲突时，可取消刷新，或先在节点行点击「转为手动」，保留本地连接再刷新。新来源连接会作为独立节点预览，重名先显示调整后的名称，不覆盖该手动节点。

「订阅来源（手动刷新）」中可刷新已有来源，也可「停止管理来源」。停止管理会移除本方案中的来源地址，保留其节点并转为手动；不联系或修改服务商服务器。

## 实现与验证

- Core：`ClientOutputRules` 生成不可变输出视图；`ClientCapabilities` 分目标检查原生配置；`ClientSubscriptions` 做来源差异和本地／来源冲突核对；`ClientSchemes` 保留规则摘要及同时改名引用映射。
- Infrastructure：`ClientSubscriptionDownload` 负责有限下载、代理、重定向和取消；`ClientWorkbench` 在生成入口执行能力检查及原有来源、候选和导出事务检查。
- Desktop：节点页新增来源管理，导出页新增规则与报告。URL 使用密码输入控件，验证接口不读取密码文本。
- Python 构建器：处理启用输出规则或订阅来源的方案时，保留自定义组的显式默认值被移除会阻止生成；没有新增跨客户端参数转换器。
