## 与已有主备的关系

原 TLS、SSH、UDP DNS／回显及代理 TCP `Connect` 模式继续保留。旧组不会自动获得新凭据或悄悄换成业务探测。用户在已有主备编辑区明确勾选「启用协议健康，并授权在此 VPS 私有保存所选来源的探测凭据」，审阅后保存，才能使用新模式。

新模式不按延迟排序或分配负载。仍为固定主→备顺序，连续失败确认、连续恢复、稳定持续时间及是否自动返回均沿用第36轮策略。两端均失效时拒绝新连接／会话，不直连；已有 TCP 不迁移或重放，UDP 不把已发数据报改投另一目标。

## 协议与结果范围

| 模式 | 本轮行为 |
| --- | --- |
| TCP SS／SS2022 | 使用所选原生代理参数，经固定核心完成鉴权后的可信 HTTPS、实际出口 IP 与地址族核对。 |
| TCP AnyTLS、Trojan TLS、VLESS TLS／Reality | 保留来源的鉴权、SNI、信任和传输参数，验证经代理取得的 HTTPS 与出口。禁用证书校验的来源不能启用此模式。 |
| UDP SS／SS2022 | 同时要求同一目标的代理 HTTPS／出口成功，以及加密 UDP 返回匹配 DNS 问题和事务的有效回答；TCP 成功不能代替 UDP 回程。 |
| 旧 TCP Connect | 仍仅代表端口可连接，不能证明密码、UUID、TLS 或出口正确。 |
| 旧 TLS／SSH／DNS／回显 | 保持原协议响应与证书范围；SSH 仍不核实主机公钥。 |

SS 方法限定为 AES-128-GCM、AES-256-GCM、ChaCha20-IETF-Poly1305 及对应已支持的三种 SS2022 方法。不支持无认证方法、插件、额外客户端链式、XHTTP、QUIC 或 UDP-over-TCP。SS／SS2022 的加密 UDP 主备要求对端相同端口也提供 TCP 代理，以完成 HTTPS 鉴权与出口检查；本轮不将任意 UDP 应用视为等价支持。

主备共用同一套代理身份、鉴权及 TLS 参数，只替换目标 IP／端口；不能把两套不同密码、UUID、Reality 公钥或 SNI 的服务塞入同一组。原生参数的支持仍受固定核心和已有来源适配约束。WS／gRPC 等来源参数按既有投影保留，本轮没有重新穷举其全部组合。

## 实际探测与失败含义

每个目标依次检查端口连接、经代理的 HTTPS，以及适用的加密 UDP。HTTPS 固定使用 `api4.ipify.org` 或 `api6.ipify.org`，保留系统信任链、主机名校验、HTTP 成功状态和小尺寸 IP 响应检查；不允许换成任意 URL、跳过 TLS 或在代理失败时改走直连。UDP 使用规则已声明的 DNS 地址、端口、问题和类型，每次生成新的随机事务身份。

| 观测 | 能说明什么 |
| --- | --- |
| `TcpReachable` | 明确端口是否可连接。端口开放但密码错误不会因此通过协议健康。 |
| `ProxyAuthenticated`／`HttpsVerified` | 经该目标的代理参数成功完成可信 HTTPS 并取得有效出口。不是简单本地 SOCKS 握手。 |
| `EgressAddress` | 该次 HTTPS 路径观察的实际出口；始终检查地址族，可另约束主、备各自的具体 IP。 |
| `UdpResponseMatched` | 经该 SS／SS2022 目标收到匹配问题、事务和记录类型的加密 UDP 回答。它单独证明应用回程，不把 HTTPS 出口当作 UDP 出口测量。 |
| `Stage` | 区分目标连接、代理／HTTPS、出口不符、加密 UDP 和通过阶段。SS 静默丢包时不能仅凭超时精确区分错误密码、网络阻断或远端 HTTPS 故障。 |

结果绑定完整规则摘要、目标序号、端点、配置资源摘要和健康方式；新建组要求两端均通过，保存过的组在故障检查时允许降级到健康备用。缺少鉴权／HTTPS、出口或 UDP 证明不能提交。

运行观测保留最近采样、连续成功／失败、选择及分阶段结果。未运行、陈旧或损坏的报告不当成当前健康。状态与历史不包含密码、UUID、私钥、原生连接配置或随机 SOCKS 凭据。

公网 HTTPS 服务不可达、限流、证书错误或出口 DNS 故障都可能使目标不健康。此模式检查这条明确业务路径，不是任意网站可用性或运营商长期质量的证明；可通过增加间隔降低探测频率，但没有忽略失败或直连兜底开关。

## 使用步骤

1. 在实例中打开 TCP／UDP 转发，选择已保存的原始代理来源。SS UDP 另填写出口 DNS、端口、问题和类型。
2. 启用显式主备，确认主备是两套端点但提供相同身份的服务；填备用 IP／端口，保留原监听与来源白名单。
3. 明确勾选协议健康及凭据授权。TCP 可继续保留旧 Connect 模式；加密 UDP 主备必须授权，不能不带凭据冒充检测加密协议。
4. 选择「探测 HTTPS 出口地址族」。主、备预期出口 IP 可分别填写；留空仍要求实际 IP 合法且地址族相符。该字段不改变客户端本身的出口策略。
5. 核对频率、单目标超时、失败次数、恢复次数、稳定窗口和自动返回。参数边界同第36轮：5–300 秒间隔、1–10 秒单目标超时，间隔至少容纳主备两次超时；失败／恢复各2–10次，稳定窗口10–600秒。
6. 审阅授权、探测方式、资源、监听／防火墙及恢复范围，再保存。未授权、非法出口、重复目标等错误保留原输入；取消不部署凭据或执行任务。
7. 新组需逐目标协议探测和真实转发入口验收全部通过。此后使用「只读检查已保存转发」读取归属、入口、逐目标健康及运行快照。

来源或凭据变化后，应重新读取所选代理参数、审阅并保存。旧引用不会自动转成新的凭据。执行中来源或固定核心声明变化会停止，不能把新材料当作已审阅内容。

## 私人资料、固定核心与资源

计划和操作参数只保存来源引用、授权和健康选项，不写代理秘密。控制端从当前已核对来源生成私有探测文档，经 SSH 的 `0600` 临时文件传送，退出时清理；秘密不放进环境变量、命令参数、审阅说明或状态报告。

远端当前材料在组件目录：

- `/etc/may-tcp-forward/proxy-health.json` 或 `/etc/may-udp-forward/proxy-health.json`：root 私有组件材料。
- 同目录 `probe-<规则ID>.json`：仅含该规则的来源，root 所有、`0600`。systemd `LoadCredential` 给对应动态用户服务提供只读副本，不给一个规则的进程暴露其他规则的凭据。
- `/usr/local/lib/may-forward-probe-cores/<归档SHA256>/`：从已固定官方归档验证的不可变核心及身份记录；本轮沿用1.14.2，不从 latest 获取。预检可准备该缓存，普通只读检查不下载。
- `/run/may-<tcp或udp>-forward-<规则ID>/`：有时效观测和私有核心临时配置，退出／停止时清理。

核心只读取本规则凭据，两个目标共用一个子进程和两个带随机认证的本地 SOCKS 入口。数据转发仍走原透明 TCP／UDP 工作者；探测核心只产生健康请求，不处理或重放用户负载。核心按固定归档、安装记录和实际字节摘要核对；程序漂移、链接或非私有材料拒绝采用。

每组件最多4个协议健康组。每个被激活组含原转发和一个核心子进程，cgroup 内存硬上限160 MiB、任务数48，核心设置64 MiB Go内存目标及单逻辑CPU调度；这些不等于实际常驻内存或整机容量保证。多个组会累积资源开销，保存前应按 VPS 容量选择组数。单目标探测有总时限，核心启动／检查也有独立边界，失败不重复启动无限重试。

关闭 Deploy 后，已激活组在 VPS 自主探测。原无连接／会话60秒退出机制保留，健康计数不跨进程保存；下次 socket 激活重新按明确顺序选择。停止组件由 systemd 控制组结束工作者和核心子进程。

上述本地 SOCKS 用户及凭据设计依据[sing-box SOCKS 入站](https://sing-box.sagernet.org/configuration/inbound/socks/)；只读凭据传递与动态用户依据[systemd exec](https://www.freedesktop.org/software/systemd/man/262/systemd.exec.html)。具体兼容性以本轮固定核心和 Debian 12／13 实测为准。

## 客户端来源、换址与恢复

匹配的 TCP 与 SS UDP 主备规则可以生成保留 UDP 的转发节点：监听、主／备目标、来源身份及健康选项必须一致，且两组件各自已有对应验收。任何一侧变化都会使旧来源资格失效；单目标 UDP 不会被暗中绑定给 TCP 主备。

TCP 与 UDP 是独立健康和会话状态，不承诺两种传输在任意瞬间选择同一目标或相同出口。主备本身不是跨服务器迁移登录会话的机制。

本轮接通第39轮换址：更新主备目标、预期出口、来源摘要和私有探测材料，保留凭据及固定核心；过渡阶段也有对应规则摘要。恢复仍按原事务精确字节核对，不能借换址改凭据或用新程序解释旧快照。

转发应用沿用原组件事务。取消、验收失败和确认丢失先核对原任务身份，不自动重放变更。快照包含配置、单元、白名单、固定工作程序、组件私有材料和每规则凭据；恢复核对版本、范围、字节、权限及归属，不覆盖外部修改，不触碰另一转发组件、协议服务、SSH、监控或独立隧道。

关闭协议健康或移除组件会移除当前部署的探测材料；已有私有恢复点仍可能包含旧凭据，应按私人备份策略保留／清理。核心缓存为可复用、无代理凭据的固定资产，不随组件移除而删除。旧程序只能按其原资源摘要核对，不能将外部替换的程序当作已受管版本；只读检查会提示需要显式保存更新。
