# 第33轮：独立入站的托管证书生命周期

发行更新（2026-11-14）：本轮已纳入 v0.9.42，见[汇总检查](TESTING-0.9.42.zh-CN.md)。以下保留实施当时的验证结果和未发布状态，不能当作当前发行或生产状态。


日期：2026-11-12。原定范围是把既有 Cloudflare／Certbot 能力接入独立证书资源，贯通申请、VPS 自动续期、共享使用者、部署核验与失败恢复。当前为未发布源码，已发行版本仍为 v0.9.41。本轮没有安装桌面更新、修改生产 VPS 或申请真实公网证书。

## 入口与适用范围

实例详情「托管证书 → 证书自动化」提供新申请、检查、到期续期、停用／启用、授权替换和无引用资源移除。运维资源总览的托管证书维护入口定位同一证书。

本轮首先支持 Cloudflare DNS-01、Let's Encrypt 正式 ACME 服务和 Debian 12／13 amd64 上既有的 Certbot Cloudflare 插件。每份证书最多8个同一区域的准确域名或单层通配符，DNS 等待时间10–300秒。国际域名使用 ASCII 编码。

手动导入证书继续使用原有替换流程。托管证书使用独立身份与目录，不把现有手动材料原地改造成自动申请任务。先申请新资源，再在入站中审阅切换引用；共享证书的停用入站仍保留引用。

## 申请前准备

1. 完成实例接入，确保管理和救援连接可用，没有未完成维护事务。
2. 准备已由 Cloudflare 管理的区域域名、所需 SAN 和 ACME 联系邮箱。通配符 `*.example.com` 覆盖一层子域名，不覆盖 `example.com` 本身或更深层名称。
3. 创建该区域所需的 DNS 编辑与区域读取 Token，保存在本机私密文件中。输入一行 Token 或唯一的 `dns_cloudflare_api_token = <TOKEN>`；界面填写文件路径。审阅绑定文件内容，确认前更换文件须重新审阅。
4. VPS 需要能访问 Debian 软件源、Cloudflare API 和 Let's Encrypt。Token 的客户端 IP 限制要允许其实际 API 出口。DNS-01 不需要开放业务80端口。

插件通过临时 TXT 完成域名验证，不创建业务 A／AAAA 记录，不配置 Tunnel。DNS 区域授权在申请前核对；DNS API 使用已成功的源地址，ACME 其他连接不绑定这个地址。

## 新申请与关联入站

1. 选择「申请新证书并启用自动续期」，填写名称、区域、邮箱、域名和授权文件。
2. 审阅域名、共享使用者、续期行为与恢复范围。返回不建立任务或改动服务器。
3. 执行时建立证书及入站范围恢复点，然后检查／安装既有 Debian Certbot 插件。应用只管理本证书的账户、凭据、材料和 timer；软件包依赖安装不会在失败时卸载。
4. 申请后检查私钥配对、系统 CA 信任链、有效期和域名覆盖。CA 已签发的记录不能通过本机恢复撤销；本轮不自动吊销证书。
5. 成功后资源加入独立入站证书列表。在「管理入站」选择引用并审阅应用，原流程按用户与地址族进行实际代理验收。

自动化只负责已引用它的入站。固定角色 AnyTLS／本机 Reality target 的既有 Certbot 方案继续通过原入口维护，不接管其他站点或全局 Certbot 定时任务。

## VPS 自动续期与部署

每份证书拥有独立 `may-certificate-<ID>.timer`，每天两次检查并加随机延迟；不需要 Windows 控制端持续开机，也不增加常驻证书进程。到期剩余不超过30天时才申请，手动「检查到期并续期部署」也遵守此门槛。

签发使用独立临时 Certbot 配置／工作／日志目录，复用本资源保存的 ACME 账户，显式隔离全局 CLI 配置。Cloudflare Token 只写根用户可读的资源文件，作为文件交给插件；不放入进程参数、普通结果或审阅文字。敏感的 Certbot／API 原始响应不会写进任务错误。

新材料验证通过后按当前入站目录识别共享使用者。每个服务通过 systemd `LoadCredential` 获得自己的证书和私钥；运行配置引用固定凭据路径。续期只重启当前启用且身份吻合的使用者，停用入站保持停用，既有连接可能短暂重连。重启后核对服务状态；该步骤不等于从所有公网客户端完成完整 QUIC／代理业务测试。

证书正常轮换不会重写入站目录、鉴权、监听和客户端连接参数。客户端继续使用系统 CA 与 SNI 验证；客户端来源中的申请快照不是续期后的叶证书钉扎。旧快照到期不会阻止托管入站维护，实际有效期通过远端材料与真实 TLS 连接核验；手动证书仍按导入材料检查有效期。域名、用户、出站等其他变更仍沿用既有来源失效规则。

定时器与桌面维护／独立恢复使用相同写锁。存在未完成事务时跳过本次定时检查，不抢占写入，也不重复签发。签发、验证、服务操作及整个定时服务均有时间／资源上限。

## 检查、停用与授权维护

「检查」读取实际文件、证书配对与信任、单位归属和续期观察，更新本地核对记录；有启用的引用入站时沿用实际代理验收。检查不签发证书。无人引用的证书也会核对实际材料，不仅信任保存的有效期。

自动续期后远端摘要会变化。普通维护若提示状态已变化，先检查再重新审阅；不能用旧摘要覆盖新证书。总览显示当前核验到的公开证书，不会仅因正常续期的叶证书摘要改变就误判为手动证书漂移；尚未核对的材料保持归档／未知证据标注。

「停用自动续期」保留当前证书与运行中的入站。到期前需要恢复续期或显式替换引用；停用不是吊销。「启用」恢复原 timer。「替换 Cloudflare 授权」先核对新授权的区域访问，再替换本资源凭据，失败保留原值；不改其他资源的 Token。

「移除」要求全部入站解除引用，包含停用入站。移除仅处理本证书的材料、账户和 timer。通用入站的普通删除／手动替换入口会拒绝绕过这一清理；实例退役也先要求清理托管证书。

## 失败与恢复

| 情况 | 行为与处理 |
| --- | --- |
| 授权、网络、CA 或域名验证失败 | 不替换在用材料；查看任务阶段并修复，保留原服务。 |
| 新材料无效、私钥不配对或名称不匹配 | 在部署前拒绝，不通过跳过 TLS 检查继续。 |
| 某个共享服务加载新材料失败 | 恢复旧材料并重启本次原本启用的使用者；其他入站不参与。 |
| 续期进程意外退出 | 保留有界的原材料／目标摘要日志，下次核对后恢复；发现外部修改或引用变化时停止，保留恢复信息。 |
| 桌面失去写入或提交确认 | 沿用原维护事务核对身份与状态；不自动重放签发。 |
| 恢复时文件、来源、单位或归档摘要不符 | 拒绝覆盖，显示需要恢复并保留私人备份。 |
| 定时续期失败 | 保留原材料，记录脱敏 `RenewalFailed`；后续定时检查再尝试。未完成日志标为 `PendingRenewalRecovery`。 |

手动操作使用证书和独立入站两种范围的同一恢复点，复原证书后重新加载相关原服务。证书自动化不修改 SSH、防火墙、网络调优、监控或 Tunnel。固定核心缓存及系统软件依赖的保留不等于本次证书仍在运行。
