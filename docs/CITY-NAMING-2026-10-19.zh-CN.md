# 入口与落地出口的城市命名

新方案的美国西部入口使用 `US-West-LA Entry` 和 `US-West-SF Entry`。SF 是本项目统一采用的旧金山湾区简称，包含 San Jose；它不表示湾区内所有实例都位于旧金山市。实例目录与服务商原始产品名称保持不变。

入口与最终出口分别命名。比如通过 LA 入口连接一台落地机器，其原生 IPv4 可以命名为 `US-West-LA Exit A IPv4`，租用的湾区 ATT IPv6 可以命名为 `US-West-SF Exit A ATT IPv6`。入口组不会根据出口标签改变，租用地址的城市也不会从机器原生位置自动推断。

新部署及追加安装表单可分别填写 IPv4、IPv6 出口节点名。审阅页展示两个出口名称与客户端入口组。计划保存在 `Shadowsocks.ClientPrimaryName`、`Shadowsocks.ClientSecondaryName`；这两个字段仅影响客户端导出的名称，不改变监听地址、源地址、密钥、鉴权用户或服务端路由。未填写的旧计划继续使用原命名算法。已保存的自定义方案不会因为默认模板更新而自动改名。

桌面核心会分别枚举连接服务器的 IPv4 / IPv6 与最终 IPv4 / IPv6 出口。显式命名时，IPv4 连接使用所填名称；同一用户的 IPv6 连接追加 `-Via-IPv6`，以免与出口地址族混淆。旧 CLI 导出继续使用 IPv4 连接，其两种出口同样读取显式名称。系统内部历史鉴权用户和路由标签不属于客户端城市名称，不应据其名称判断地理位置。

同步重装后的私人实例档案时，应分别核对当前管理账号与端口、已登记主机指纹、实际源地址、运行版本与服务端配置。桌面凭据仍由原账号的 DPAPI 保护，不能用明文 CLI 凭据直接覆盖；归档路径也必须对应实际使用副本。旧系统内核检查与健康结果归档为历史证据，重新执行只读检查后才能作为本次结果。

验证覆盖新默认组、LA / SF 独立出口、双连接地址族名称唯一性、两套客户端名称一致、改名不改变连接与凭据、受管来源身份稳定、旧自定义方案兼容，以及真实客户端核心解析。服务器在线恢复与重启验收需要独立证据，离线测试不能替代这些检查。

本轮 956 项 .NET 边界与工作流断言、项目离线自检、60 项审计行为断言、真实 Python 生成器、固定客户端核心及泄密扫描通过。命名管道和 Git Bash 测试在允许当前用户临时 IPC 的环境运行。线上实例健康状态另按 Deploy 原生只读审计写入私人档案；没有据此宣称额外完成整机重启测试。
