# 客户端配置与服务端线路

适用：May VPS Deploy v0.9.39。先完成[实例接入与验收](USER-GUIDE.zh-CN.md)。配置设计、服务端转发和客户端选择组是三个不同层面，只有最后真实走过目标路径的请求才能证明整条链路可用。

## 理解对象

| 对象 | 保存内容 | 不代表什么 |
| --- | --- | --- |
| 实例归档 | 已受管服务、凭据引用、运行状态与验收来源 | 文件存在不证明远端仍未变化。 |
| 方案草稿 | 所选输出目标、节点、连接、组和路由设置 | 保存草稿不写入服务器或外部客户端文件。 |
| 候选配置 | 生成、合并和校验后的待导出文件 | 解析通过不证明实际出口或学校授权可用。 |
| 转发／编排事务 | 监听、目标、依赖、白名单和分阶段验收 | 一个端口可连不代表协议鉴权或 UDP 已通过。 |
| 权威客户端文件 | 由用户选定、长期管理的最终文件 | 应用导出后，运行中的客户端仍需明确加载或更新。 |

## 生成配置

1. 新建或打开方案。点亮 sing-box、Clash 两个目标中的一个或两个；只要求所选目标的输出位置。
2. 从已验收实例、通用入站或受支持的导入材料添加节点。保持协议认证、SNI、证书校验、地址族及来源身份，不把名称相同当作同一节点。
3. 给入口组与落地组明确角色。美西名称采用 `US-West-城市`，例如 LA、SF 或 SJ；城市取实际已确认位置，不凭服务商营销名猜测。名称影响可读性及部分地区预设，不能证明地理位置。
4. 配置连接与分组。Clash 的 `dialer-proxy` 和 sing-box 的 `detour` 表示由另一个节点／组建立连接；不要把相同服务重复经过自身而形成环路。
5. 选择默认出口与业务分类，检查 DIRECT、入口和落地的关系，生成候选并使用固定客户端核心校验。
6. 审阅所选目标、差异、备份和路径后导出。禁止把 Clash Verge AppData 内运行副本当作权威输出。
7. 在客户端加载新配置，检查实际命中规则、连接链和目标出口。测试规则模式的请求不能只在全局模式验证后就宣布分类已正确。

更新节点来源时会保留允许保留的自定义名称和地区归属；凭据、证书、出站、核心身份或入站启用状态变化会使旧验证失效。重新核对来源，不手改归档摘要绕过检查。

## 外部 WS／gRPC 节点（v0.9.39）

第十八轮本版源码新增外部 VLESS／Trojan 的 TLS WS／gRPC 导入和双客户端输出；只接入客户端节点，不新增服务器部署默认项。独立编辑表单保留节点身份及传输配置，无法完整表达的分享参数明确拒绝，见[外部 WS／gRPC 节点](CLIENT-STREAMS-ROUND-18-2026-10-29.zh-CN.md)。

## VLESS XHTTP（v0.9.39）

第二十轮已扩展 TLS／Reality XHTTP 独立入站与原生来源，覆盖四模式、合法 HTTP/1.1／2／3、独立下载身份及高级字段。原生输出需要配套 May Core，不能用上游 sing-box 校验冒充；可等价表达时同时输出 Mihomo，不可表达时保留单客户端并说明原因。完整来源、标准 URI／订阅均按预览核对，分享必须完整往返。SNI、Host、路径、UUID、下载身份、Reality 和固定核心变化使旧连接资格失效；本轮不扩展 XHTTP 服务器下一跳或客户端落地编排。步骤、核心来源与验收边界见[第二十轮指南](XHTTP-ROUND-20-2026-10-29.zh-CN.md)。

## WireGuard 实例间通道（v0.9.39）

第二十二轮为两台可信受管实例提供内核加密通道，外层 IPv4／IPv6，内层各为对端 IPv4 `/32` 主机路由。实例详情「管理隧道」统一处理两端部署、双向 TCP／UDP 验收、检查、移除及补偿；私钥只留在服务器。既有服务或端口转发可明确使用对端私网地址，不自动重写原三机链路或客户端节点。受管防火墙允许隧道对端访问本机已有监听服务，使用前核对信任范围和服务监听。步骤和限制见[第二十二轮](WIREGUARD-ROUND-22-2026-10-30.zh-CN.md)。

## 学术与 AI 分类

交互式 AI 服务、模型／数据集开发资源、学术数据库和国内／校园站点应分开考虑。Hugging Face 的下载及重定向域名不能仅因涉及模型就全部当作交互式 AI；学术检索站点也不应统一强制代理。

学校已购买数据库常按校园出口地址授权。先核对学校身份域名、数据库正式域名和实际下载重定向，再在 Academic Research 及相关选择组中明确选择 DIRECT。国内／校园直连规则的优先级不能被更泛的研究或代理分类抢先覆盖。

「直连」只表示使用当前机器的网络出口。校外网络不会因此变成校园网络；是否需要学校 VPN／统一身份认证由学校的实际授权方式决定。第三方代理改写域名、学校子域名、出版社 CDN 和对象存储需要分别验证；不能把所有 `cnki.net` 子域名都当成同一学校身份入口。路由分类审查见[学术审查记录](ACADEMIC-ROUTING-AUDIT-2026-10-23.zh-CN.md)和[Hugging Face 修订](HUGGINGFACE-RESEARCH-ROUTING-2026-10-22.zh-CN.md)。

## TCP／UDP 转发

先选择明确的监听与目标，并列出允许来源、地址族、端口占用、系统转发条件和防火墙影响。采用「预检 → 快照 → 应用 → 路径验收 → 提交」流程，失败或取消按该事务恢复。

TCP 透明转发只承载 TCP。通过已有目标生成客户端节点时必须保留用户鉴权、TLS SNI 及证书规则，不能把目标 IP 替换为转发入口后顺带改掉协议身份。详细见[经转发节点](FORWARDED-NODES-ROUND-11-2026-10-23.zh-CN.md)。

UDP 转发必须使用转发后的真实 UDP 回程验收；DNS、nonce 回显及 Shadowsocks／SS2022 验收各自证明对应路径。不能用直接 DNS 或普通 TCP 请求替代。UDP 模型和验收边界见[UDP 转发](UDP-FORWARDING-ROUND-9-2026-10-21.zh-CN.md)与[代理 UDP 验收](UDP-PROXY-ROUND-10-2026-10-23.zh-CN.md)。

## 跨实例线路编排

v0.9.39 支持有限的 IPv4 TCP 前置→中转→落地链路。第二十一轮本版源码扩展为同地址族 IPv4／IPv6 TCP，以及固定端口 Hysteria2／TUIC v5 的 UDP；三台实例必须不同，不支持共享实例、混合地址族、任意 UDP 或端口跳跃。显式维护实例依赖、监听、目标、白名单和验收阶段，先核对主机身份及受管归属。

从前置实例打开「跨实例线路编排」，选择地址族、传输、中转和已保存的原始落地来源。前置允许来源与线路同族；中转仅允许前置的真实出口 `/32` 或 `/128`。原落地鉴权、SNI 和证书保持来源参数。UDP 分段选路不代表可达，必须再通过所选 QUIC、HTTPS 和真实应用 UDP 回程才能提交。

任一阶段失联先核对事务状态，不因本地未收到成功就从第一台自动重放。删除或恢复只处理本次已确认归属的 TCP 或 UDP 组件；逐台提交后发生失败仍按原快照补偿。完成后在配置设计「添加转发节点」生成带统一来源的候选。使用步骤、取消、恢复与验收范围见[第二十一轮指南](CHAIN-ROUND-21-2026-10-30.zh-CN.md)；[第十二轮记录](TCP-CHAIN-ROUND-12-2026-10-24.zh-CN.md)保留旧 IPv4 TCP 范围。第二十二轮另增加限定的 WireGuard 双实例通道，不自动替换这些三机链路；任意深度拓扑仍未实现。

## 导出与恢复

所选文件逐份写入前先备份和记录阶段。两个文件跨磁盘不能原子提交；第二份失败时保留恢复状态，核对外部文件摘要后再恢复，不覆盖用户后来修改的内容。

分享文件可能包含可直接使用的节点凭据，即使只含一台机器也按私人材料处理。配置设计不自动托管在线订阅、不自动更新客户端运行副本、不更改 Windows 系统代理或 TUN。

第十五轮源码增加 `hysteria2://`／`hy2://` 导入、分享及订阅来源刷新，并保持双客户端端口集对应；自 v0.9.39 提供。标准链接只表达支持的鉴权、TLS／SNI、Salamander 和默认间隔多端口，不能表达的自定义间隔、带宽和高级 TLS 设置会明确拒绝分享。此时使用完整配置导出，详见[第十五轮](HYSTERIA2-ROUND-15-2026-10-28.zh-CN.md)。

第十六轮源码从已验收 TUIC v5 入站生成两类原生节点及完整配置，保留 UUID、密码、SNI、ALPN、拥塞控制、UDP 中继及心跳单位；自 v0.9.39 提供。不支持 TUIC v4 Token 或 `tuic://` 分享，也不把 UDP／QUIC 节点加入仅 TCP 的透明转发，详见[第十六轮](TUIC-ROUND-16-2026-10-28.zh-CN.md)。

第十七轮本版源码接通服务器 Hysteria2／TUIC 下一跳，按 sing-box 与固定 Xray 的实际能力分别处理。客户端仍连接入口，服务器使用已审阅的下一跳快照；完整使用步骤、身份保护、UDP 验收及恢复见[第十七轮](SERVER-QUIC-ROUND-17-2026-10-28.zh-CN.md)。

## 节点组复用（v0.9.39）

在配置设计的节点页保存选中成员与完整入口依赖，再在其他方案中选择复用。组更新后逐个方案查看差异并同步；本地修改冲突时保留原值，必要时解除关联后独立使用。变更会使候选失效，生成、核心校验及实际导出前重新核对版本与来源。完整配置和分享链接使用同一组来源，不能将分组或不可表达参数塞进有损链接。详细操作与故障处理见[节点组手册](CLIENT-GROUPS-ROUND-23-2026-10-30.zh-CN.md)。
