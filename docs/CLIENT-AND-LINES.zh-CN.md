# 客户端配置与服务端线路

适用：May VPS Deploy v0.9.38。先完成[实例接入与验收](USER-GUIDE.zh-CN.md)。配置设计、服务端转发和客户端选择组是三个不同层面，只有最后真实走过目标路径的请求才能证明整条链路可用。

## 理解对象

| 对象 | 保存内容 | 不代表什么 |
| --- | --- | --- |
| 实例归档 | 已受管服务、凭据引用、运行状态与验收来源 | 文件存在不证明远端仍未变化。 |
| 方案草稿 | 所选输出目标、节点、连接、组和路由设置 | 保存草稿不写入服务器或外部客户端文件。 |
| 候选配置 | 生成、合并和校验后的待导出文件 | 解析通过不证明实际出口或学校授权可用。 |
| 转发／编排事务 | 监听、目标、依赖、白名单和分阶段验收 | 一个端口可连不代表协议鉴权或 UDP 已通过。 |
| 权威客户端文件 | 由用户选定、长期管理的最终文件 | 应用导出后，运行中的客户端仍需明确加载或更新。 |

## 生成配置

1. 新建或打开方案。点亮 sing-box、Clash 两个目标中的一个或两个；只要求所选目标的输出位置。
2. 从已验收实例、通用入站或受支持的导入材料添加节点。保持协议认证、SNI、证书校验、地址族及来源身份，不把名称相同当作同一节点。
3. 给入口组与落地组明确角色。美西名称采用 `US-West-城市`，例如 LA、SF 或 SJ；城市取实际已确认位置，不凭服务商营销名猜测。名称影响可读性及部分地区预设，不能证明地理位置。
4. 配置连接与分组。Clash 的 `dialer-proxy` 和 sing-box 的 `detour` 表示由另一个节点／组建立连接；不要把相同服务重复经过自身而形成环路。
5. 选择默认出口与业务分类，检查 DIRECT、入口和落地的关系，生成候选并使用固定客户端核心校验。
6. 审阅所选目标、差异、备份和路径后导出。禁止把 Clash Verge AppData 内运行副本当作权威输出。
7. 在客户端加载新配置，检查实际命中规则、连接链和目标出口。测试规则模式的请求不能只在全局模式验证后就宣布分类已正确。

更新节点来源时会保留允许保留的自定义名称和地区归属；凭据、证书、出站、核心身份或入站启用状态变化会使旧验证失效。重新核对来源，不手改归档摘要绕过检查。

## 学术与 AI 分类

交互式 AI 服务、模型／数据集开发资源、学术数据库和国内／校园站点应分开考虑。Hugging Face 的下载及重定向域名不能仅因涉及模型就全部当作交互式 AI；学术检索站点也不应统一强制代理。

学校已购买数据库常按校园出口地址授权。先核对学校身份域名、数据库正式域名和实际下载重定向，再在 Academic Research 及相关选择组中明确选择 DIRECT。国内／校园直连规则的优先级不能被更泛的研究或代理分类抢先覆盖。

「直连」只表示使用当前机器的网络出口。校外网络不会因此变成校园网络；是否需要学校 VPN／统一身份认证由学校的实际授权方式决定。第三方代理改写域名、学校子域名、出版社 CDN 和对象存储需要分别验证；不能把所有 `cnki.net` 子域名都当成同一学校身份入口。路由分类审查见[学术审查记录](ACADEMIC-ROUTING-AUDIT-2026-10-23.zh-CN.md)和[Hugging Face 修订](HUGGINGFACE-RESEARCH-ROUTING-2026-10-22.zh-CN.md)。

## TCP／UDP 转发

先选择明确的监听与目标，并列出允许来源、地址族、端口占用、系统转发条件和防火墙影响。采用「预检 → 快照 → 应用 → 路径验收 → 提交」流程，失败或取消按该事务恢复。

TCP 透明转发只承载 TCP。通过已有目标生成客户端节点时必须保留用户鉴权、TLS SNI 及证书规则，不能把目标 IP 替换为转发入口后顺带改掉协议身份。详细见[经转发节点](FORWARDED-NODES-ROUND-11-2026-10-23.zh-CN.md)。

UDP 转发必须使用转发后的真实 UDP 回程验收；DNS、nonce 回显及 Shadowsocks／SS2022 验收各自证明对应路径。不能用直接 DNS 或普通 TCP 请求替代。UDP 模型和验收边界见[UDP 转发](UDP-FORWARDING-ROUND-9-2026-10-21.zh-CN.md)与[代理 UDP 验收](UDP-PROXY-ROUND-10-2026-10-23.zh-CN.md)。

## 跨实例 TCP 编排

当前支持有限的 TCP 前置→中转→落地链路，显式维护实例依赖、监听、目标、白名单和验收阶段。先核对各主机身份及受管归属，再按计划建立后续依赖；前置端的成功必须经完整链路抵达最终目标。

任一阶段失联先核对事务状态，不因本地未收到成功就从第一台自动重放。删除或恢复链路只处理本次已确认归属的规则；共享目标或其他业务不属于默认恢复范围。编排、取消、恢复及测试范围见[TCP 链路记录](TCP-CHAIN-ROUND-12-2026-10-24.zh-CN.md)。通用 UDP 编排、封装隧道和任意深度拓扑未在此承诺。

## 导出与恢复

所选文件逐份写入前先备份和记录阶段。两个文件跨磁盘不能原子提交；第二份失败时保留恢复状态，核对外部文件摘要后再恢复，不覆盖用户后来修改的内容。

分享文件可能包含可直接使用的节点凭据，即使只含一台机器也按私人材料处理。配置设计不自动托管在线订阅、不自动更新客户端运行副本、不更改 Windows 系统代理或 TUN。
