# 组件版本维护

新部署及已有实例追加安装也可选择版本来源，默认“应用固定版本”。选择“官方最新稳定版”后，在审阅前由控制端查询所选组件，沿用设置中的更新代理；审阅展示具体版本、资产和 SHA256，查询失败不会静默改用固定版。安装期间不再次浮动解析最新版。

初次安装查询有效期为 24 小时；已接受的部署草稿保存完整版本清单及候选摘要，继续部署沿用原已锁定版本，包括应用固定清单更新后。草稿材料变化时拒绝续作。接入已有 VPS 仍保留现有程序，升级从实例维护入口单独执行。

在实例的“升级核心”、Agent、主控或 Tunnel 管理中选择版本来源：

| 组件 | 维护对象 | 可选来源 |
|---|---|---|
| Xray | 当前实例的 Reality 服务 | 应用固定版、官方最新稳定版 |
| sing-box | AnyTLS 与 Shadowsocks 分别选择 | 应用固定版、官方最新稳定版 |
| Komari Agent | 当前实例的采集程序 | 应用固定版、官方最新稳定版 |
| Komari 主控 | 当前实例的主控程序及数据库验收 | 应用固定版、官方最新稳定版 |
| cloudflared | 当前实例的 Tunnel 连接器程序 | 应用固定版、官方最新稳定版 |
| BBR v3 | 受管兼容 LTS 内核 | 应用固定版、官方最新兼容 LTS |

默认使用应用固定版本，随应用发行维护。选择最新稳定版后先点击查询，查看具体版本、资产名和 SHA256，再审阅执行。查询通过当前 VPS 读取对应官方 GitHub 仓库的稳定发行，排除草稿和预发行；资产必须来自指定仓库并提供可验证的 SHA256。查询材料有效期为 24 小时，审阅后材料或程序变化时停止执行。版本已一致时提示无需升级；固定版仍可用于明确审阅的重新安装。最新稳定版低于归档版本时不会自动降级。

代理核心升级只替换所选程序，保留配置、端口和凭据。候选程序通过版本及现有配置检查后才替换，再重启所选服务并进行实际协议验收。协议恢复点覆盖本机受管代理协议，恢复范围在审阅中显示。

Agent 保留连接配置和原启停状态，通过发行摘要及运行进程核对程序身份。主控先创建一致性专用备份，再升级、检查本机接口和数据库迁移状态；需要人工迁移时等待完成，失败或取消按主控范围恢复。使用归档的本机端口，不强制改成默认端口。

Tunnel 的程序升级与 Token 轮换是不同操作。程序升级保留服务配置、Token、路由和启停状态；原来运行时短暂重连并检查连接器就绪。失败只恢复 Tunnel 范围。Token 轮换仍从独立操作入口执行。

BBR 的签名信任、兼容范围、直接升级与两种回退见 [网络调优说明](NETWORK-TUNING.zh-CN.md)。选择版本来源不会隐式安装或重启。

Windows 应用继续通过在线更新升级。随附的 .NET、WinUI、Python、YAML 和客户端校验核心由应用发行整体维护；Debian 的系统依赖沿用系统包管理及管理员维护，不加入通用的自动系统升级。
