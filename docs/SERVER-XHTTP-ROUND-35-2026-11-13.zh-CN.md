## 功能与使用边界

从已经保存的完整 VLESS XHTTP 节点建立服务器下一跳。固定 Reality 角色、独立 Reality 入站和独立 VLESS XHTTP 入站使用既有 Xray，默认出站与分类出站共用来源、依赖、审阅、实际验证和局部恢复。入站与下一跳分别拥有身份：入口使用 Reality 不意味着下一跳也必须使用 Reality。

这里配置的是服务器如何访问下一跳，不会部署下一跳的下载服务、反向代理或 CDN。上传／下载分离需要已有可协作的 XHTTP 后端、正确的路径和会话关系；两个任意 VLESS 服务不能仅通过填写两个地址就共享会话。

原版 sing-box 的受管入站仍不提供 XHTTP 下一跳。本轮不改变其核心，也不新增转接进程。共享出站资源若被不支持的消费者引用，审阅／配置生成会拒绝该组合；不能删除 XHTTP 字段后按普通 VLESS 应用。Mihomo 特有会话扩展、缺少等价原生参数的来源也不转换。

| 执行位置 | XHTTP 下一跳 |
| --- | --- |
| 固定 Xray Reality 角色 | 默认下一跳、附加分类落地；保留全部受管监听与入站身份。 |
| 独立 Xray Reality 入站 | 默认或分类出站；独立入站身份和恢复范围不合并。 |
| 独立 VLESS XHTTP 入站 | 默认或分类出站；入口的 HTTP 版本不决定下一跳版本。 |
| sing-box AnyTLS／SS2022／Hysteria2／TUIC 入站 | 明确拒绝 XHTTP 下一跳，可继续使用先前支持的其他下一跳。 |
| 客户端方案 | 继续使用既有完整导入、分享、原生参数编辑与来源引用，不因本轮自动修改。 |

## 固定核心和参数范围

Xray 固定为项目版本表中的 26.3.27。本轮使用其原生 `vless` 出站、`streamSettings.network: "xhttp"` 与 `xhttpSettings`；不引入另一个 Xray 构建或隐藏适配服务。固定角色同时核对归档版本和应用前读取的实际版本；独立入站核对所选核心的固定版本与既有核心身份，有限探测也查询实际可执行程序。旧版本、未知版本和未审阅的未来版本均拒绝使用这组参数，需要先通过既有核心维护流程处理。

| 参数 | 规则 |
| --- | --- |
| VLESS 身份 | 保留 UUID 与 XUDP；不附加 Vision flow 或另一层客户端 multiplex。 |
| 上传地址 | 明确的 IPv4／IPv6 字面量与端口；域名端点不在本轮服务器范围，SNI／Host 独立保留。 |
| 传输安全 | 验证 TLS 或固定 Reality 公钥、short ID 和 uTLS 指纹；不允许跳过验证。 |
| HTTP 版本 | TLS 可选 HTTP/1.1、HTTP/2、HTTP/3；Reality 使用 HTTP/2。版本与唯一 ALPN 一致，明确的 `auto` HTTP 版本不会被降级为固定值。 |
| 传输模式 | `auto`、`stream-one`、`stream-up`、`packet-up`；缺省模式按原核心的 auto 含义处理。模式 auto 与 HTTP 版本 auto 是不同字段。 |
| HTTP/3 | 使用 h3／TLS 1.3，不附带 uTLS；应用 UDP 与 HTTP/3 的 QUIC 承载分别验证。 |
| 身份及信任 | 保留 SNI、TLS 模式的公开 PEM 信任材料和版本约束、受支持指纹，以及 Reality 的公钥与 short ID；文件型凭据、私钥、ECH 和不能等价表达的 TLS／拨号字段拒绝投影。 |
| 高级参数 | 保留请求头、填充、会话／序号位置、上传数据位置、POST 限制和 XMux 等既有受支持字段；未知字段报错，不静默忽略。 |

上传和独立下载地址都检查格式与回指；固定角色不能把其中任一端点指回当前实例，独立入站也检查与当前入站监听构成的环路。原节点不受投影修改。

### 独立下载

原生来源中的 `transport.download_settings` 含独立地址、端口、TLS／Reality 与 XHTTP 传输。它投影到 Xray `xhttpSettings.extra.downloadSettings`，其中保留 `address`、`port`、`security`、对应身份设置和下载端的 `xhttpSettings`。上传和下载可以有不同的 SNI、Host、路径、高级参数与受支持 HTTP 版本；这些差异均进入来源／配置／传输摘要。

`stream-one` 不使用独立下载，不允许嵌套下载。下载设置不引入第二个 VLESS UUID，需与上传身份及后端会话配合。选择不同安全组合或 HTTP 版本仍须通过实际回程；参数可以表达不代表任意外部两端均可互通。

### 高级参数与资源限制

复用现有 XHTTP 参数校验：请求头最多64项，拒绝覆盖 Host、连接及内容长度等传输握手字段；请求头中的认证值不会出现在审阅或证明中。路径含查询串／转义时按原值保留。GET 上传和头部／Cookie 载荷要求显式 packet-up。XMux 的并发和连接数上限不能同时启用。

继续限制范围顺序和数值，单项受管数据范围上限16 MiB；整体生成配置上限1 MiB。独立入站合计最多8个默认／分类目标，固定角色最多7个附加落地。有限验证按需启动回环核心，完成、失败或取消后退出；没有新增常驻巡检或代理进程。

## 操作步骤

1. 在「配置设计」保存完整来源。只有链接时先导入并检查参数；无法等价表示的复杂来源使用既有原生配置编辑，不能只复制地址与 UUID。
2. 核对上传及下载的字面 IP、端口、SNI、Host、路径、安全身份、HTTP 版本、模式和高级参数。确认独立下载确实通向能协作的后端。
3. 先确认目标实例使用受支持的固定核心。固定角色打开「配置出站」并选择 Xray Reality；在默认下一跳或附加落地中选择来源。切换到 sing-box 时不会继续列出 XHTTP 候选。
4. 独立入站在「管理入站」建立／复用代理出站资源，引用完整来源，再分配给 Xray 入站的默认出站或分类规则。资源共享时核对所有使用者的核心能力。
5. 分类协议、固定规则版本、顺序与去向按第34轮设置。保留默认 HTTPS 与 UDP 验收目标；不要用「HTTP/3」代替「应用 UDP」的规则选择。
6. 审阅上传和独立下载的摘要、目标实例、使用者和受影响服务。审阅显示身份摘要，不展示 UUID、Reality 公钥全文或高级请求头值。取消不产生执行任务或远端写入。
7. 执行后完成入口与逐去向验证。默认 XHTTP 没有分类规则时，也必须完成原生下一跳的 HTTPS／UDP 和传输身份检查，不能跳过。
8. 生成客户端或继续业务前核对最终结果。来源更新、独立下载身份变化及规则变化需重新审阅与验收；刷新客户端方案不会自动改写服务器。

## 实际验证与证据含义

入口仍经真实客户端鉴权并验证 HTTPS／出口及所需应用 UDP。分类目标从入口服务器使用已安装的固定核心执行有限检查；默认 XHTTP 也使用相同检查。探测只绑定回环 SOCKS 端口，不修改主机 DNS、系统代理、防火墙或正式服务配置。

XHTTP 证据要求：

- `ValidatedProtocol: vless`、`Transport: xhttp`，正确的 TLS／Reality 标记和 ALPN。
- 上传和独立下载全部传输设置的摘要相符。跨语言摘要采用稳定类型和字符串编码，不暴露高级参数的实际值。
- 真实验证 TLS 的 HTTPS 返回，并核对所选地址族和预期网站出口。
- 经所选原生出站的独立 DNS 数据报往返，核对新事务、完整问题和响应；TCP、QUIC 握手或端口监听不能替代该结果。
- 独立入站的证据同时绑定当前配置、策略和出站摘要；配置改变或旧证据缺失不能继续生成已验证来源。

UDP DNS 回程不测量 UDP 公网出口 IP，不代表任意游戏／QUIC 业务质量。分类按核心可见的目标会话元数据处理；域名缺失和同一 UDP 关联中的目的地变化边界沿用第34轮。有限下一跳检查与真实业务分类命中分别记录。

## 失败、更新与恢复

| 情况 | 处理 |
| --- | --- |
| 不支持的核心、未知字段、两客户端参数冲突 | 应用前拒绝，不裁剪后重试。 |
| 上传／下载身份或预期出口错误 | 验证失败；不降级到普通 TCP、默认落地或入口直连。 |
| 独立下载不可达／后端不共享会话 | 该路径不通过，不以上传成功代替下载。 |
| TCP 成功但 UDP 不返回 | 不能提交为支持应用 UDP 的 XHTTP 路径。 |
| 来源、配置、证书／Reality 或高级设置变化 | 旧来源／审阅／证明失效，重新核对新快照。 |
| 应用或提交确认丢失 | 核对原事务身份和远端状态，不重放写入。 |
| 验证失败、取消或当前作用范围外发生变化 | 按既有事务恢复本角色／实际受影响独立入站；不覆盖其他资源。 |

移除固定下一跳时恢复原出站与规则，保留入站身份、监听和其他角色。独立入站沿用自己的服务、共享资源引用与凭据范围。已启用的托管证书维护继续执行相同下一跳验收；SSH、Monitor、Tunnel 不参与该变更。
