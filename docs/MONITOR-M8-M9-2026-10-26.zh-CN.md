## 迁移范围和接管证据

选定目标为 AetherCloud Los Angeles Prime、DMIT CORONA、DMIT MALIBU、VMISS、YUNYOO 和 BERO。MoeCloud／BreadCloud 不在此次名单。

只读重新盘点发现：当前 Komari 控制端和现有 Tunnel 实际在 BERO；MALIBU 旧控制端和 Tunnel 已不活动。旧归档不是在线事实。五台既有 Agent 的 Token 与旧控制端客户端身份逐一比对，AetherCloud 重装后没有有效旧 Agent，是新增第六台。

迁移先固定服务和备份身份，再停止所选旧监控、安装新受管组件。新用户口令、Agent Token 和只读授权独立生成；没有整体复制旧用户、密码、会话或 Token。节点名称、排序、计费和到期等元数据经白名单导入。节点 UUID 的关联用私有映射保存，不依赖显示名称。旧指标历史保存在一致性备份中，未声称已导入 May。

每台新 Agent 均核对真实节点 UUID、Server 安装 UUID、连续至少三份不同时间的报告；公网 HTTPS 再确认六台在线、报告推进和时间新鲜。错误只读凭据被拒绝，只读令牌不能调用管理员接口，Agent Token 不能读取集成快照。API 及 Cloudflare 缓存状态均复核。

旧组件退役只有在上述核对后才提交。备份按摘要下载到私人归档，自动回退计时器取消；已提交的退役不能由过时自动化恢复。代理业务、SSH、Tunnel 和 Docker 的进程身份、单元状态及单元文件摘要逐项保持不变。

## 实际遇到并修复的问题

1. 旧数据库到期时间使用 SQL 时间格式，新 API 要求 RFC3339。首次导入在两台节点创建后中断；先读取并核对已创建身份，再保留其 UUID／Token、按原时区转换时间，仅创建缺失的四台。没有重放整个创建过程或留下重复节点。
2. 默认 Python HTTP User-Agent 被既有 Cloudflare 入口拒绝，而正常 May／Go 请求可通过。真实 IPv4／IPv6 HTTPS 对照确认后，凭据核对请求使用明确的 `May-VPS-Deploy/May-Monitor` User-Agent；证书检查、禁止重定向和身份比对保持有效。增加真实回环 TLS 回归。首次失败发生在写服务前，先核对 Absent 状态并结束原事务，再使用新事务执行。
3. 旧一次性验收脚本使用 GET 退出，而产品接口要求 POST；GET 的 SPA 200 不能证明会话已撤销。脚本已更正为 POST，后续对本轮自有测试会话单独核对清理，不撤销未知或用户会话。原先仅凭 GET 200 的退出记录不作为有效证据。
4. 主题设置页浏览器脚本在导航时读取尚未创建的 `document.body`，产生测试异常。改为等待实际元素后，页面加载、真实保存和读回均通过；未为此添加产品兼容分支。
