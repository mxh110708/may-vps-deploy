# 第三轮：服务器侧固定下一跳

本轮为已纳管、已启用的 AnyTLS 入站增加固定下一跳维护入口。沿用 SSH、任务审阅、配置摘要、组件恢复事务和实际客户端验收，不新增常驻 Agent、轮询服务或数据库。

## 路径与支持范围

客户端仍连接原 AnyTLS 入站；由入口服务器建立到 Shadowsocks 落地的连接，再由落地访问网站。这与客户端配置中的 `detour` / `dialer-proxy` 不同，客户端无需增加一个落地代理。

| 对象 | 本轮范围 |
| --- | --- |
| 源入站 | 独立 sing-box AnyTLS 服务中的 `anytls-in`，单入站，覆盖该入站全部用户 |
| 下一跳 | 已保存配置方案中具有完整 sing-box 原生参数的 Shadowsocks / SS2022 节点 |
| 加密方法 | AES-128-GCM、AES-256-GCM、ChaCha20-IETF-Poly1305 及三种 SS2022 方法 |
| 连接端点 | 明确的 IPv4 / IPv6；本轮不解析域名端点，不接受回环、未指定、链路本地、多播地址或指回源实例 |
| 网络 | TCP 和 UDP；更换前后均需要独立验收 |
| 出口核验 | 用户明确填写预期网站出口 IP；按该 IP 的地址族约束该入站，并验证实际出口 |
| 原布局 | 一个 AnyTLS 入站、原有 `direct` 出站、默认直连出口和可选的 IPv6 拒绝规则 |
| 暂未支持 | Reality 入站、插件、自定义拨号字段、复制客户端链式、域名／网段分流、多入站和独立端口转发 |

已有自定义分流、出站列表、同名但没有本地归属记录的规则，或受管规则发生漂移时，停止并说明原因。不会为适配固定下一跳而重新生成整份服务器模板。

## 使用流程

1. 在「配置设计」中导入或添加落地节点，核对 sing-box 原生参数并保存方案。受管节点仍要通过实例、连接及凭据指纹检查。
2. 确认入口实例已接入／部署完成，并启用 AnyTLS。实例须有当前服务器配置的归档及摘要；缺失或实际配置有变化时，先重新接入核对。
3. 在「实例 → 日常维护 → 服务器固定下一跳」点击「配置出站」。
4. 选择已保存的下一跳，填写「预期网站出口 IP」。它是落地访问网站时的出口，不是入口服务器的 IP。已有节点出口标注会带入，仍需人工核对。
5. 点击「审阅」，核对入站、下一跳名称／端点、预期出口、地址族、服务中断、验证与恢复范围。此时尚未连接或写入服务器。
6. 明确确认后才执行。任一审阅前后的返回均不创建远端任务。

应用只读取保存后的方案。规则引用方案和稳定节点 ID，并锁定节点摘要及方案文件；审阅后发生变化必须重新选择。方案刷新、节点转为手动或来源停止管理，不会自动改写已配置的服务器下一跳；后续更新需要重新审阅执行。

落地服务必须允许入口 VPS 的来源地址。部署器不会在本操作中登录落地、放开其防火墙或修改可信入口列表；白名单等准备需另行明确操作。

## 生效策略

生成结果只增加本应用管理的 `may-fixed-next-hop` 出站及两条匹配 `anytls-in` 的规则：先拒绝相反地址族的 IP 目标，再路由到所选下一跳。它们位于原有默认策略之前，原规则保留。

例如选择 IPv6 出口时，该入站显式 IPv4 目标被拒绝，允许的流量转交落地。网站域名最终如何解析与出网仍取决于落地本身；必须使用实际出口和 UDP 验收确认，不能仅凭地址族标注认定成功。原来入口机的直连 IPv4 设置不再决定这条固定链路的最终出口。

下一跳失败时，这条路由不会转向直连；不会加入备用直连选择组。源入站的监听、用户、TLS / ECH、padding、DNS 和其他未涉及的字段保留。仅重启 `sing-box-anytls.service`，该服务中的现有连接会短暂中断。

「移除固定下一跳，恢复原出口策略」只删除归属和摘要匹配的出站及规则，原有规则顺序与默认出口保留。原出口策略如果是直连，移除后会恢复直连；这是一项需要审阅确认的操作。

## 执行、核验与恢复

任务依次显示六个阶段：

1. **只读核对。** 检查 Debian 12/13 amd64、管理 SSH、AnyTLS 实际启用／运行状态、服务命令、配置文件类型和摘要。远端摘要必须与审阅时的本地归档完全一致。
2. **建立恢复点。** 只为 `AnyTlsEntry` 组件建立本地及远端快照，并启用现有限时回滚保护；不用扩大到全部代理、防火墙或监控。
3. **应用配置。** 在原配置副本上修改；用远端实际 sing-box 核心校验候选，再次核对旧配置摘要，通过后原子替换并重启当前 AnyTLS 服务。
4. **独立验收。** 核对应用后的实际配置、管理连接，再使用固定版本 sing-box / Mihomo，分别检查真实代理 HTTPS、预期出口 IP 和 UDP。只验收 AnyTLS，不临时停启其他协议。
5. **归档结果。** 仅更新 AnyTLS 配置、摘要和本次验收证据。节点连接参数没有变化，不重写客户端片段；重新提取受管节点时带入正确的落地出口信息。
6. **提交事务。** 沿用本次任务身份确认提交，解除限时回滚保护。

跳过或部分通过的验收不能提交固定路由变更。失败、取消会按 AnyTLS 范围恢复配置、服务、元数据及证据。写入或提交回复丢失时先核对事务：已经提交则记录确认不完整，未提交则恢复；不会重放配置写入。

恢复期间发现外部编辑、事务身份不符或结果无法确认时，保留材料并标记待恢复，不能覆盖外部文件。组件快照用于本次失败／取消及待恢复流程；实例页通用「协议备份」入口仍筛选全部协议备份，正常移除当前固定链路请使用本页的移除操作。

修改服务器下一跳后，旧受管节点来源会因服务器路由指纹变化而失效，避免继续沿用旧出口标注。需要在「添加受管节点」中重新选择更新来源；节点的客户端监听与凭据保持原参数。

## 私人数据边界

操作选项只含实例／方案／节点引用、摘要及预期出口，不包含下一跳密码。下一跳从已有加密方案读取；审阅和历史不显示密码。服务器配置继续按既有私人归档保存，归属元数据只记录名称、端点、出口、来源引用及摘要。

不接管服务商 ATT IPv6 租约脚本，不改系统代理、TUN、SSH、防火墙、其他代理协议、Komari 或 Cloudflare Tunnel。恢复和卸载同步处理服务器路由元数据，避免留下已经不对应实际配置的标注。

## 实现与验证

- `ServerOutboundRouting`：受支持布局、原生下一跳能力、引用与配置摘要、固定规则生成、归属和移除检查。
- `WorkflowEngine.ServerOutbound`：六阶段任务、组件恢复点、实际配置核对和严格验收。
- `server-outbound-read.sh` / `server-outbound-apply.sh`：服务身份、文件与链接检查、候选实际核心校验、写入前再次核对及原子替换。
- 客户端来源、探测和受管指纹同步使用服务器固定链路的出口信息；原客户端连接内容不变。

本轮验证结果：

- 完整 .NET 回归通过 **1134 项断言**，较第二轮新增 55 项；包含真实双客户端配置生成、校验和隔离导出。
- 使用随应用固定的真实 Windows sing-box 核心，在本机分别启动 AnyTLS 入口、SS2022 落地和隔离客户端。实际 TCP 请求、SOCKS UDP 转发均通过；停止落地后请求失败，目标未收到绕过下一跳的请求。测试端点只映射到回环地址，没有接管系统代理或 TUN。
- 新增远端脚本行为测试共 8 项，7 项通过；本机没有创建符号链接的权限，链接测试跳过，保留给支持该权限的平台执行。实际运行 Bash 脚本的文件检查、摘要冲突、核心拒绝、校验期间漂移、服务停用和服务命令不匹配分支；系统服务与核心命令使用隔离替身。已有 13 项客户端相关 Python 测试全部通过。
- 原生 WinUI 隐藏测试的 6 组流程通过：实例入口、表单取消、出口预填、非法出口保留表单、无凭据的最终审阅取消、移除策略审阅取消。截图已检查；0 次窗口激活、0 次前台采样、不进入任务切换器、不注册托盘、不注入全局输入，测试实例已关闭。
- 覆盖远端配置漂移、写入回复丢失、提交回复丢失、验收跳过／失败、取消及本地外部编辑。前者阻止写入，已提交回复丢失按身份确认；其余未提交变更按范围恢复，外部编辑保持原样并标记待恢复。
- Tests / Desktop 的 Release 构建通过。NuGet 漏洞元数据服务不可达的 `NU1900` 警告仍存在，该项在线审计未完成；没有更换依赖或锁文件。447 个文本文件的秘密扫描及 `git diff --check` 通过。

真实生产 VPS、落地白名单和公网出口尚未在本轮操作；本机回环和模拟服务测试不等同生产验收。本轮未安装、推送或发布应用。跨平台共享 Core 仍执行边界与事务测试；需要随包 Windows 核心的两轮回环测试只在 Windows 执行，其他平台明确跳过，未在本轮实测其他操作系统。

配置字段参考 sing-box 官方文档：[入站匹配和路由规则](https://sing-box.sagernet.org/configuration/route/rule/)、[Shadowsocks 出站](https://sing-box.sagernet.org/configuration/outbound/shadowsocks/)。字段支持还须通过目标服务器实际核心的配置检查；本地通过不代替生产验收。
