# v0.9.14 部署中断、令牌与升级补测

2026 年 10 月 11 日，按用户限定的补测范围完成以下验证。MOE 使用用户重装并明确接纳新 SSH 身份的 Debian 12 专用测试机；VMISS 保留上一轮受管部署。使用 [B 方案接口](BACKGROUND-TESTING.zh-CN.md)驱动真实 WinUI 控件、审阅、凭据提示及任务协调器。没有注入全局鼠标/键盘、切换系统代理或 TUN，也没有修改非测试 VPS。

## 修正

- **托盘恢复的标题栏状态。** 关闭窗口转为隐藏时，Windows 可能没有机会清理关闭按钮的非客户区交互状态。隐藏前、恢复前后显式向本窗口清理状态，并让 DWM 处理鼠标离开消息。仅允许本进程自己的窗口；依据 [微软 DwmDefWindowProc 文档](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmdefwindowproc)。
- **DNS 凭据格式。** 新部署及追加安装接受原有单行 Token，也接受唯一的 `dns_cloudflare_api_token = Token` 项，可含注释和匹配引号。重复项、其他凭据、空值、含空白的 Token、链接和过大文件拒绝执行；本地先校验，错误信息不包含凭据。
- **可重复的后台中断验证。** 显式专用会话可在指定步骤关闭自己的 SSH 或退出自己的测试进程。消费标记跨进程保存，普通启动和默认后台会话不开启。该接口制造丢失确认，随后走正常核对与恢复流程，不接收任意远端命令。
- **后台接口连接复用。** Linux CI 发现关闭前一条连接时，销毁监听器会同时断开已排队的下一客户端。改为保留监听器、逐条断开已接受的连接，保持串行执行和防重放；增加在前一请求处理期间排队、连续请求及空客户端断开的回归。

## 首次部署中断恢复

| 中断边界 | 真实结果 |
|---|---|
| 第一个 SSH 审计请求发送前断开 | 远端请求数为零，恢复后的基线不变；可以明确重新开始 |
| SSH 管理入口切换成功、确认丢失 | 本地保留待恢复；核对远端基线后，恢复原始 SSH 访问，事务为 `RolledBack` |
| 防火墙步骤成功后退出应用 | 重新打开后显示未确认任务；核对并恢复部署前基线，事务为 `RolledBack` |
| Xray 安装成功后退出应用 | 重新打开后通过正常恢复撤回本轮安装，事务为 `RolledBack` |
| 远端提交完成、本地确认前退出应用 | 本地为 `LocalPrepared`；重启核对远端已完成状态及管理访问后，确认 `Committed`，没有重新安装或重新提交 |

请求/返回记录确认上述四个已执行的故障步骤各发出一次原请求。恢复到用户明确开始下一轮新部署之前，没有重放原变更；提交后的核对仅执行状态与访问检查。故障测试中的退出是实际进程退出，断开只影响本轮 SSH，不是模拟关闭电脑网络。

这是选定步骤的确认丢失测试，不覆盖任意指令执行到一半时的断电、磁盘损坏或服务商故障。最终 MOE 的 Reality 部署成功保留，未要求再次重装。

## 专用 Cloudflare 凭据

| 项目 | 真实结果 |
|---|---|
| DNS-A、DNS-B 初始权限 | 核对令牌有效、指定区域可读、DNS 可读；真实 DNS challenge 签发测试证书 |
| DNS-A 吊销 | API 拒绝旧令牌；新的 ACME 验证失败，原测试证书保留 |
| DNS-B 替换 | 新验证成功，签发新的测试证书 |
| Tunnel 轮换 | 同一专用测试 Tunnel 的旧 Token 新连接失败，新 Token 新连接就绪 |
| 应用内 Tunnel 轮换 | 正常管理入口更新连接令牌并重启连接器；公开测试网址验证通过 |
| 轮换范围 | 代理、SSH、防火墙、主控与 Agent 的已记录配置摘要不变；主控、Agent 和 Xray 进程未重启 |

DNS 测试使用独立 ACME staging 目录，没有替换正式证书。第一次吊销后强制续期仍成功，因为 ACME 可能复用已通过的授权；该结果不能证明吊销失效。随后使用新的验证会话确认失败，再换 DNS-B 确认恢复，没有把缓存授权结果误记为通过。

Tunnel 轮换后，已经建立的旧连接可能继续活动，所以不能只看现有连接器的健康状态；验证了旧 Token 建立新连接失败，见 [Cloudflare 令牌说明](https://developers.cloudflare.com/tunnel/reference/tunnel-tokens/)。正式 DNS Token 和正式监控 Tunnel 保留。本轮临时凭据探针及 staging 目录按精确所有者路径清理，运行服务保留。

## 旧版应用升级

使用已发布 v0.9.13 的原始 WinUI 程序，界面 DLL 字节保持不变。隔离 QA 安装包关闭快捷方式与卸载注册，安装到本轮私人测试目录；新包标记为 QA v0.9.14，绝不用于发布。

真实应用完成更新确认、下载与 SHA256 校验、辅助程序交接、实际安装和自动重启。归档、独立本地设置、导入字体、外观、关闭到托盘偏好、窗口记忆选项保留。外来地址、缺少发行摘要、过大资产、校验清单/安装包篡改、大小超限及重复版本等 8 项拒绝验证通过。

QA 发行响应及资产来自隔离夹具。QA 辅助程序只把安装器进度窗口放到未显示的 Windows 桌面，其安装范围和文件校验保留原流程；不切换用户桌面。旧 WinUI 自身在屏幕外运行，因为旧版本在无 Shell 的桌面上设置窗口切换器属性会失败。旧界面与新重启窗口均没有前台激活。

这证明隔离 QA 安装更新生命周期，不能单独代表用户实际安装的正式旧版本已通过公网完成整条升级路径。正式 GitHub 元数据、下载和摘要另行核对；正式安装器在用户当前安装目录的运行与普通前台重启不包含在这轮后台测试内。

## Komari 旧备份

在用户指定目录找到两份真实备份，包含 SQLite 主库及配套 WAL/SHM；先在本地副本上形成一致性 SQLite 备份，原压缩归档摘要保持不变。

- 较早备份中的旧程序构建对应 1.4.3。使用摘要核验后的官方 Windows 1.4.3 和 1.5.1 程序，在同一数据库副本上先启动旧版、再启动新版，版本 API 确认一致。账户及原有非通知设置保留。
- 含历史的备份有 5 个节点、100 个 metrics series、132,900 条 metrics rollups。新版实际启动后，原有账户、节点、主题设置及上述历史数据保留，完整性检查通过。
- 副本使用本机回环端口；关闭通知、发现和任务，调整副本中的数据路径及历史保留窗口。API 凭据仅用于本轮本地副本。原备份、正式监控和真实通知均未修改。

两份备份已采用独立 MetricStore，未找到更老的单库历史；固定新版未注册数据库迁移查询路由，返回 SPA 页面，不能据此宣称执行过历史重构迁移。该补测证明真实备份副本兼容与数据保留，不代表 Linux 服务升级或更老单库历史迁移已覆盖。

私人副本上传到 VMISS 的请求被自动审批拒绝，因此未上传，改做上述本地测试。Linux 隔离服务升级仍需明确允许该上传目的地；更老的单库历史迁移需要对应版本与备份材料。
