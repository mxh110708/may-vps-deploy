# 第41轮：多目标转发策略

日期：2026-11-24。本轮承接[第40轮](FORWARD-PROXY-HEALTH-ROUND-40-2026-11-16.zh-CN.md)，为独立 TCP／UDP 转发的同一入口增加轮询与来源 IP 哈希。当前工作区源码与隔离验收完成；未提交、推送、发行、安装或应用到生产。发行教程仍以 v0.9.42 为基线，第39、40轮的未发行改动保留。

## 使用方式

在实例的独立 TCP／UDP 转发表单中，先填写入口、目标 1、来源白名单及实际验收方式，再选择「目标分配方式」：

| 方式 | 新连接／会话如何分配 |
| --- | --- |
| 主备 | 保留原版本 1 的首选、备用、连续确认和自动返回行为。旧规则不会自动迁移。 |
| 轮询 | 版本 2，在当前健康目标中按配置顺序循环；一次新 TCP 连接或 UDP 会话只分配一次。 |
| 来源 IP 哈希 | 版本 2，按 socket 实际来源 IP 与固定目标身份计算 SHA-256 rendezvous 哈希，在健康目标中选择最高分者。 |

多目标组包含 2–8 个规范单播 IP／端口端点。上方目标是目标 1，可增删其余目标；不能重复端点、重复身份、使用域名、未指定地址、组播、映射 IPv6 或作用域地址。端点不得回指本组件的监听端口。三目标以上的组不能直接切回主备，须先明确移除多余目标。关闭后重开保留本次编辑草稿，切换两种多目标策略保留目标身份。

保存前审阅全部端点、策略、健康方式、确认次数与恢复持续时间。所有启用目标须逐一通过健康探测，并通过实际入口验收；只读检查允许部分目标故障，但至少一个目标和实际入口须通过。修改目标、身份、健康、凭据来源或策略均使旧证据及派生来源资格失效，不能仅凭端口开放保存。

## 会话与来源边界

轮询不按字节数或活动连接数均衡。健康探测和状态读取不推进轮询游标；新的实际连接会推进游标。哈希排除来源端口，将 IPv4 映射来源归一为 IPv4；规范等价的 IPv6 写法结果一致。在目标身份和健康集合相同时，重启及目标排列变化不改变哈希结果。摘除一个目标时，原本选择其他健康目标的来源保持选择；重新纳入目标只影响之后新建的会话。

哈希使用内核 socket 来源，不读取 PROXY 头或应用内声明。经过同一 NAT／上游中转的用户可能共享一个哈希结果；PROXY 接收属于[第42轮计划](DEPLOY-ROADMAP-2026-10-24.zh-CN.md)。本轮不提供权重、最少连接、全局流量整形或跨服务器分配协调。

既有 TCP 连接固定到建立时的目标，不迁移、重放或自动重连到另一个目标。UDP 以监听 socket、来源地址和端口、接收目的地址信息组成会话身份；同一活跃会话固定到一个目标，按原地址回包。超时、目标被确认摘除或状态过期时关闭该关联，后续新数据报可建立新的关联；已经发出的旧数据报不跨目标重发，旧目标的迟到响应不能流入新关联。保留每规则 10–600 秒超时及最多 1024 个会话的原有上限，满额时保留已建立会话并丢弃新会话。

TCP 和 UDP 组件各有自己的游标、健康与会话。多目标转发不会自动绑定成承诺两种传输选中同一后端的复合客户端节点；原有单目标与版本 1 协议健康主备的绑定条件继续保留。

## 健康与资源

| 参数 | 范围与含义 |
| --- | --- |
| 探测间隔 | 5–300 秒，必须不少于目标总数 × 单目标超时；版本 2 默认 30 秒。 |
| 单目标超时 | 1–10 秒；逐目标有界探测，不补发业务。 |
| 失败确认 | 连续 2–10 次失败后摘除。单次失败不会立即抖动。 |
| 恢复确认 | 连续 2–10 次成功，并持续 10–600 秒后重新纳入；任一次失败重新计时，使用单调时钟。 |
| 首轮／全部失效 | 首轮只纳入明确成功的目标；全部失效或状态过期时拒绝新分配，无直连回退。 |

TLS 健康保留证书和主机名校验；SSH 只验证协议响应，不核实服务器主机公钥；代理 TCP 的 Connect 仅证明 TCP 可达。普通 UDP 使用匹配的 DNS 查询或随机回显。所有目标必须提供同一协议、鉴权及有效 TLS 身份，透明转发不会替每个目标改写客户端凭据。

显式授权后，可沿用第40轮支持的代理 TCP 协议健康及 SS／SS2022 加密 UDP 健康：私有保存同一来源的探测凭据，以固定核心逐目标验证鉴权、可信 HTTPS、实际出口地址族；加密 UDP 另验证匹配的 DNS 回程。每个目标的可选预期出口通过固定目标身份关联，重排目标不会把约束套到另一个目标；留空仍约束地址族。SS／SS2022 UDP 不允许以 Connect 替代协议健康。

一个协议健康组仍最多一个核心子进程、每组件最多四个协议健康组，保留私有逐规则凭据、160 MiB／48 tasks 上限与退出清理；普通组保留 96 MiB 和既有连接／文件描述符限制。每个目标的探测通过独立的受认证回环入口路由到指定目标，不使用直连兜底。

无连接／会话后，工作进程按原设计空闲退出；socket 保持受管，下次流量激活时重新探测。只读状态可能是 NotRunning，不能据此声称目标失效。重启不保存既有连接、UDP 会话、轮询游标或之前健康判断；哈希算法及固定目标身份保持稳定。

## 身份、关联与恢复

版本 1 原样保留 `BackupAddress`／`BackupPort`／`AutoReturn`；版本 2 使用显式 `Strategy` 和 `AdditionalTargets`，每个附加目标有固定 `Id`、`Address`、`Port`。目标 1 身份来自原规则 ID；所有目标、身份和策略纳入跨语言一致的规则摘要。代理版本 2 的 `ExpectedExits` 按目标 ID 关联，不按数组位置猜测。

逐目标证据须匹配规则摘要、目标数量、顺序、ID、IP、端口、探测方式及明确结果。新组的远端健康探测在实际入口验收之前执行，探测预算按完整目标数量有界增加，最终仍复查远端配置摘要。审阅后改变策略、目标身份或工作程序将拒绝执行。

规则复制会重建目标 1 身份并重绑其预期出口，保留其他目标与原来源的有效身份；它仍需要新监听端口和重新审阅。实例换址会同步额外端点及按身份关联的预期出口，不改目标 ID。诊断分段枚举全部实际端点，仍遵守八分段的单次诊断上限。

保存／移除继续使用原组件事务，完整快照包含配置、白名单、单元及固定工作程序；取消、验收失败和确认丢失按原事务核对与局部恢复，不重放写入。恢复只接受原资源身份，不覆盖代理协议、Tunnel 或监控。旧快照恢复原程序后，重新保存才应用新策略。
