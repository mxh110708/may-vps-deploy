# 第45轮 CI：删除重复验证并保留平台预警

日期：2026-11-26。本轮调整 CI 调度和测试归属。第46轮及以后的原计划继续作废。应用发布版本保持 v0.9.43；本轮推送不发布新的应用安装包。

## 实际删除的执行量

| 原执行 | 现在的执行 |
| --- | --- |
| Windows、Linux、macOS 都重放九组业务回归 | 业务矩阵由 Windows 覆盖；Linux、macOS 构建 Core/Infrastructure 并执行平台薄测。删除 Unix 上共18组重复业务执行。 |
| macOS 用数千项相同模型断言作为适配预警 | 保留路径、符号链接、私人目录迁移、进程身份、主机信任及真实 SSH/SFTP 回环检查。保留未来 macOS 适配的预警能力，不宣称已经实现 macOS 图形客户端。 |
| 完整 CLI 验收运行 Python × PowerShell 四个组合 | 保留 Python 3.9 + PowerShell 7.4.20、Python 3.13 + runner PowerShell 两个边界组合，删除两个混合组合。普通 CLI 改动只跑当前组合。 |
| 安装验收嵌入存储、拖拽、方案设计、导出及整套后台界面回归 | 安装验收只负责真实启动、安装、更新重启、数据保留、碰撞拒绝及卸载边界。通用界面回归从安装作业移除。 |
| 安装更新验收默认产生界面截图 | 默认关闭截图；更新的确认、下载、SHA-256、进度状态和重启仍真实执行。仅显式传入 EvidenceDirectory 时采集图片。未采图的证据字段保持 false。 |
| 安装构建后再运行独立 WinUI 编译作业 | 安装作业已经构建真实消费端，调度器不再同时选择重复的桌面编译。 |
| 调整 CI 选择器也触发所有协议与安装验收 | 选择器、门禁和 CI 行为测试的修改只跑快速回归；workflow/运行器修改另跑基础入口与平台薄测。 |
| 修改一个协议夹具就重跑九组原生矩阵 | 按夹具所属功能选择对应组；未知公共夹具仍保守扩大范围。 |
| chains 被拆为八个子进程但总用例没有减少 | 撤销八子进程调度，恢复一个 chains 入口。未把单纯拆分计为性能改进。 |

完整模式的作业定义由原18个减为15个；更主要的减少来自删除两套业务矩阵、安装中的整套界面流程以及普通修改不再进入完整模式。作业数不能替代真实执行量和耗时。

## 选择范围

`checks` 是唯一 push/PR 调度器，`dotnet.yml` 仅供复用。

| 修改范围 | 必需验证 |
| --- | --- |
| README、文档、AGENTS.md | CI 行为回归、workflow 语法、文档链接、PowerShell 语法、公开文本秘密扫描。 |
| CI 选择器、门禁、行为测试 | 快速检查；不因自身修改重放应用全套。 |
| workflow 或 CI 运行器 | 快速检查、Windows 基础入口、Linux/macOS 平台薄测。 |
| Windows UI | 快速检查、基础模型和 Windows 适配器、WinUI 编译。 |
| 某个已识别的协议夹具 | 基础入口和对应功能组。例：TUIC 夹具不选 XHTTP、流式下一跳或安装生命周期。 |
| Core/Infrastructure 共享实现 | Windows 核心回归、两个 Unix 平台薄测、Debian 契约及消费端编译；共享层影响面未知时保守覆盖核心组。 |
| Debian 远端脚本 | 两版 Debian 契约、Bash/ShellCheck、防火墙 check-only 及相关控制端检查。 |
| 安装、更新、发布结构 | 一次真实安装生命周期；该作业替代重复的 WinUI 编译。 |
| 未识别的应用文件、依赖、固定核心清单、无有效差异证据 | 支持范围内的完整验收。完整模式也不恢复已删除的重复业务矩阵和通用截图。 |

测试源码仍保留原协议、所有权、补偿和模型用例。独立 UI 验证脚本供有明确 UI 验收需求时使用，不再隐式嵌入安装检查。

## 平台与数据边界

Linux/macOS 使用 `--platform-only`，构建共享项目后检查文件路径和链接、私人目录迁移、进程创建时间身份、主机信任，以及 Paramiko 回环服务端下的实际 SSH/SFTP 交互。平台作业不下载 Windows 协议核心，也不重复九组业务矩阵。

macOS 覆盖继续保留。调度器选择 macOS 时，最终门禁必须收到该子作业的实际 success；被跳过、失败或取消均不能作为平台通过。

安装验证继续使用隔离目录中的 QA 安装器，不注册正式卸载项或快捷方式。实际 EXE 启动、受管文件被编辑时拒绝覆盖、非受管文件碰撞、更新下载校验、进程交接重启、私人归档及字体/偏好保留、保留数据卸载和限定范围删除仍需通过。

CI 不触碰生产 VPS、现用客户端配置或已安装代理应用。

## 门禁、复用与证据

`CI result` 仍对选中的检查严格失败。精简范围不代表把失败、取消或跳过改成成功。完整凭据要求 Windows 全部核心组、Linux/macOS 平台薄测、两组运行时边界、Debian 12/13、Bash 检查和真实安装生命周期成功；安装构建已经覆盖 WinUI 编译。

同一提交的标签仅复用可信主分支完整凭据；不同提交、失败/取消运行和部分检查不能冒充完整凭据。普通主分支修改按实际差异验收，不要求每次先跑完整模式。

Debian pip 缓存使用工作区的 `.cache/pip`，通过 PIP_CACHE_DIR 与缓存 action 指向同一路径。此前线上已验证两版 Debian 均能保存并在下一次运行命中恢复。固定客户端及 Xray 摘要检查继续保留。

本地结果写入 `.tmp/ci45-resume/prune-*`；线上耗时附件保留14天，区分排队和执行。当前修改的选择清单、实际通过的作业和耗时须另行核对。不得把本地通过写成线上通过，也不以子流程数量增加冒充验证量减少。
