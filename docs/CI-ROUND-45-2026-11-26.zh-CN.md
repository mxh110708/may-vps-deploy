# 第45轮 CI 调度与测试分层

日期：2026-11-26。本轮调整 GitHub Actions、测试入口和验证记录。应用正式版保持 v0.9.43；VPS、客户端配置和已安装应用不在本轮变更范围。

## 调度和选择

`checks` 是唯一的调度 workflow。main 推送、PR、`v*` 标签和手动完整验收从 `.github/workflows/ci.yml` 进入；`dotnet.yml` 只接受内部复用调用。普通分支通过 PR 检查，main 检查合并后的实际提交。新提交取消同 PR／分支过期的自动检查；手动完整验收和标签验收不自动取消。

| 变更 | 选择的检查 |
| --- | --- |
| 根目录说明和 `docs/*.md` | CI 行为、workflow 语法、PowerShell 语法、本地文档链接、秘密扫描。 |
| WinUI 页面和资源 | 快速检查和 WinUI 编译；页面源码还检查基础模型与 Windows 适配器。 |
| Core／Infrastructure | Linux 完整核心组、三个独立 Windows 核心分组、Debian 12／13 契约及 WinUI 消费端编译。Windows 适配器 API 改动也编译 WinUI。 |
| 远端脚本 | 共享核心、两版 Debian、Bash／ShellCheck 和防火墙 check-only。 |
| CLI 和客户端生成 | 对应 CLI／固定客户端检查；共享渲染器变更扩大到核心与远端契约。 |
| 安装、更新、打包 | 独立安装生命周期，按所改适配器增加相关检查。 |
| workflow、CI 调度器、固定依赖、核心清单、项目文件、未知路径 | 完整验收，包括四个最低／当前运行时组合、macOS 和安装生命周期。 |

`scripts/ci/plan.py` 输出的选择作为 `ci-plan` 附件保留14天。未知事件、无效基线、首次推送或差异读取失败均要求完整验收。Git 使用 NUL 分隔的完整差异，并禁用重命名归并，同时检查删除及新增路径；不依赖有文件数量上限的 API 路径列表。

## 测试归属

`scripts/ci/contracts.json` 集中维护46个原有 Python／内核契约入口，并新增 UDP 就绪回归，共47个入口，每个受支持 Debian 版本各运行一次。原 Ubuntu root 专项的私有健康资源、换址文件归属和恢复也由这两个 root 容器覆盖。两版 Debian 验证各自的包、OpenSSH 和远端契约，属于有意保留的平台矩阵。

CI 使用 `Run-Tests.ps1 -SkipPortableRegressions`：保留 PowerShell、CLI、凭据、更新、GUI 合成和配置生成检查，将结尾的公共 Python 契约交给 Debian 作业。原 `ValidateProject` 和不带该开关的本地完整入口仍运行全部回归。旧的 workflow 文本正则断言改为调度行为测试。

普通 CLI 变更使用 Python 3.13／runner PowerShell；完整验收仍覆盖 Python 3.9／3.13 × runner／7.4.20 四个组合。改变的是运行频率，最低版本契约仍然保留。

| Windows 独立作业 | 原有完整测试入口 |
| --- | --- |
| clients-quic | clients、quic。 |
| foundation-forwarding | foundation、chains、operations；同时运行 Windows 适配器。 |
| streams-udp | xhttp、udp、server-stream，第44轮地址族模型及真实核心路径。 |

三个作业根据本地实测重新平衡，各自 checkout、构建、临时目录和进程互不共享。Linux 执行所选核心组，macOS 留给完整验收。server-stream 继续分开普通流式下一跳与 XHTTP。Windows 显式准备固定核心和原生构建所需 Python；Unix 不携带 Windows 核心环境变量。平台限制和跳过分别记录，不能当成实际协议通过；chains 与两个流式专项保留原有8分钟预算。

Linux 核心升级夹具原先只等待 TCP 监听，UDP 可能晚于 TCP 启动，导致首次业务包提前发送。现在还需从 `/proc` 核对该测试子进程实际持有目标 UDP 监听，再发唯一业务包。新增回归分别验证 TCP 先就绪、无关进程的 UDP 监听不能满足条件、进程提前退出；没有增加业务包重试。

## 缓存和固定来源

pip 缓存对应依赖文件，NuGet 缓存对应锁文件；SDK 单独按项目版本准备，每次仍执行 locked restore 和实际构建。Windows 客户端核心沿用既有摘要验证。Xray 26.3.27 的缓存同时验证归档和 EXE，再传给测试子进程。安装依赖继续经 `Initialize-DesktopBuild.ps1` 检查，不缓存私人归档或生产配置。

workflow 使用固定 actionlint 1.7.12，官方下载包经过 SHA-256 校验，只提取预期程序；Bash 继续由独立 ShellCheck 检查。

## 完整验收和标签复用

手动运行 `checks` 总是完整验收。标签查询同一提交在 main 已成功完成的 `checks`，并要求存在成功的 `Full validation receipt` 作业。

PR、不同提交、其他 workflow、失败／取消的运行、没有完整凭据的普通检查均不能复用。查询失败或无合格记录时，标签自动运行完整验收。复用标签仍执行快速检查，但不签发新的完整凭据，避免把重复复用当成新的全套验证。

稳定必需检查名为 **CI result**：plan 必须成功；选中的作业缺失、跳过、失败或取消均失败；完整计划必须选齐检查。只有最终门禁通过，完整运行才生成凭据。仓库如配置了旧矩阵名称的分支保护，需要对应到这个稳定检查；本轮不改远端保护设置。

完整 CI 与发行资产核对仍是发版前独立步骤，本轮没有自动发布逻辑。

## 耗时和证据

原 v0.9.43 main 的 [.NET 运行](https://github.com/mxh110708/may-vps-deploy/actions/runs/45583950649)用时30分05秒，其中 Windows 排队12分56秒、执行17分09秒；[安装检查](https://github.com/mxh110708/may-vps-deploy/actions/runs/45583950400)中的生命周期步骤为6分37秒。同提交标签随后又启动两套 workflow。

新 runner 为每个入口保留执行时间、截止时间、退出码和结果，失败或超时后停止后续入口并清理自己的子进程。最终作业另外读取 GitHub 时间，分别展示排队和执行。附件保留14天。

目标为纯文档约1–2分钟，普通修改必需检查约5–8分钟。GitHub 排队、冷缓存和完整验收分别记录；本地时间不能当作 Actions 已达到目标的证明。

本地证据在 `.tmp/ci45/`。新增 `tests/test_ci45.py` 验证路径分类、超过300文件的真实 Git 差异、重命名／删除、标签复用、失败／跳过／取消的门禁、子进程超时和耗时区分。首次推送后的 Actions 需另行验收，Windows 本地测试不代替 Debian root 或 macOS。

初版 Windows 分组实测约413／479／279秒，据此重新分布为上述三个最终作业。分组调整保留同一批独立测试子进程，没有重放整套协议测试；这些时间不含 GitHub 排队、checkout 或冷依赖下载。

WSL 默认网络下，独立于项目代码的纯 UDP 探针也丢失4 KiB／60 KiB的 IPv4 报文，12项中8项成功；临时网络命名空间中12项全部成功。完整契约随后在该隔离环境复验通过，没有为迁就 WSL 修改生产转发程序、降低报文尺寸或重试业务报文。首次竞态失败和 WSL 默认网络失败记录均保留。

首次 Actions 发现秘密扫描在 Linux 读取 `.gitattributes` 等点文件时缺少 `Get-Item -Force`。已补齐显式读取，并在审计回归中验证隐藏公开文件可读取、其中的合成凭据仍被拒绝；本地62项审计断言通过。扫描入口变更归入完整 CI 验收范围。

首次启用完整原生客户端路径时，Windows 托管环境的 WS 夹具还暴露了固定客户端的 `tls: invalid server key share`。诊断显示请求在证书／HTTP 路径之前中止，与[uTLS Firefox 次级 key share 问题](https://github.com/refraction-networking/utls/issues/402)一致。Schannel 录制夹具改用 Chrome 指纹；Go gRPC 对端继续实际验证 Firefox，模型检查仍保留 Firefox 参数往返。证书、错误 SNI／鉴权／路径拒绝及真实 UDP 保持原验收，不改生产配置、核心版本或 Windows 全局加密策略。此处不宣称修复了上游 Firefox 兼容问题。

托管 Windows 的第27轮真实客户端场景全部通过后，退出检查还发现四处夹具只保存 PID。Windows 复用编号时，已经退出的本次子进程可能被其他进程替代，旧检查会误报残留。第27轮、Hysteria 跳跃端口、TUIC 与 XHTTP 统一采用现有的 PID 加创建时间身份检查，保留实际退出断言；不会因为同编号的其他进程仍在运行就归属到本次测试。增加活跃进程、旧创建时间及当前进程不受影响三项回归，并纳入 foundation 组。

线上最终验收以对应提交的 CI result 和完整运行的 Full validation receipt 为准；失败、取消的旧运行保留为排查证据，不算作成功。本轮恢复验收只处理第45轮 CI，已作废的第46轮及后续安排继续保持作废。

## 本地操作和恢复

```powershell
python tests/test_ci45.py
python scripts/ci/tools.py
python scripts/ci/run.py --suite quick
python scripts/ci/run.py --suite legacy
python scripts/ci/run.py --suite dotnet --groups '["clients","quic"]'
python scripts/ci/run.py --suite dotnet --groups '["foundation","chains","operations"]'
python scripts/ci/run.py --suite dotnet --groups '["xhttp","udp","server-stream","outbound"]'
```

Debian 契约在依赖齐全的临时 Debian 运行 `python scripts/ci/run.py --suite contracts`。安装／更新改动或完整验收使用 `--suite installer`；普通页面修改只编译，完整原生界面与安装验证仍留在完整验收。

恢复时同时恢复两份 workflow 和 PowerShell 的 CI 开关调用，保留产品代码和私人资料。恢复 CI 无需安装应用、切换代理或回滚 VPS。
