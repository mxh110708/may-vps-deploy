# 第三十二轮：节点批量处理、原生片段与导出差异

本轮延续既定的「节点处理和输出交互」，面向实际使用的 Mihomo／Clash YAML 与 May Route／sing-box JSON。纳入 v0.9.41，与第二十八至三十一轮一起发行。发行与本机安装、导入权威配置、生产服务器应用是分别执行的动作。

## 选择哪种输出

| 需求 | 入口 | 包含内容 | 不包含内容 |
| --- | --- | --- | --- |
| 将可完整表达的单节点交给其他客户端 | 配置设计 → 导出 → 分享节点链接 | 选中节点的协议、地址、鉴权及链接支持的参数 | 入口组、链路关系、复杂 ECH 和其他不可表达字段 |
| 保留高级连接参数，合并到已有原生配置 | 配置设计 → 导出 → 导出原生节点片段 | 所选格式的原生连接字段，所选节点及审阅中列出的必要上游节点／地区组 | 完整 DNS、分流、监听、外部规则集与外部文件 |
| 生成含业务组和 DNS 的完整配置 | 生成配置 → 校验配置 → 审阅并导出 | 方案选择的完整客户端配置；沿用内置模板或已读取的来源 | 自动导入正在运行的客户端、自动接管流量或应用服务器变更 |

节点片段是合并材料，不是直接启动文件；不能仅把文件扩展名改成客户端配置就认为完整。原生格式保留字段不代表另一种客户端也支持同名字段。两种格式仍分别使用其自身的原生对象，不做丢字段的通用降级。

## 批量管理节点

1. 打开一个配置方案，进入「节点」→「批量管理节点」。
2. 按名称或协议筛选并勾选节点。「选中筛选结果」追加当前可见成员；筛选外已经勾选的成员仍保留，计数会明确列出。需要重新开始时使用「清空全部选择」。
3. 选择操作。移动到开头／末尾保留所选成员的相对顺序；名称排序仅调整所选位置，其他位置不参与排序。入口地区调整仅适用入口节点，落地上游调整仅适用落地节点。
4. 点「预览影响」，核对每个发生变化的节点、排列或关联。不能应用时先解决提示中的业务默认出口、保护组、上游或空地区依赖。
5. 点「应用到草稿」。确认返回后再保存方案；已有候选会失效，需要重新生成与校验。取消任一审阅不改草稿。

批量移除只从本方案移除，不删除订阅或复用节点组的原始快照。删除仍被其他节点原生 `detour`／`dialer-proxy` 引用的上游会被阻止。业务组当前选定出口不能悄悄回退成其他出口。移除后会清理指向已删除节点／空地区的排序项，其他顺序和默认值保留。

复用节点组成员不能通过单独批量修改绕过组版本校验。需要独立修改时，先选中该组全部成员并执行「解除整组关联」；只在当前方案解除，保留连接和原始来源，其他方案与组快照不变。订阅成员「转为手动」沿用已有手动来源模型，连接参数保留；不会取消整个订阅或修改远端。

批量预览绑定完整方案摘要。预览后有其他编辑时必须重新预览，不能重放旧操作。应用会重新计算依赖，不信任预览对象里可能已变化的草稿内容。方案上有未完成的来源同步事务时，先从来源中心完成恢复。

## 原生节点片段

1. 在「目标」启用需要的客户端格式。在「导出」核对已设置的筛选、命名与排序；片段采用这些输出规则，原始节点不会被改名。
2. 进入「导出原生节点片段」，选择格式和节点，点「预览节点与依赖」。
3. 核对「所选」「依赖」与「入口组」。例如选择一个经地区入口的落地，片段会包含该入口组的所有候选入口；这些额外节点也含鉴权信息，不会隐藏加入。
4. 确认后复制，或保存为新 `.yaml`／`.json`。不覆盖已有文件，文件夹需已存在；保存临时文件成功后再次核对来源并移动到新文件。
5. 将 `proxies`／`proxy-groups` 或 `outbounds` 合并到目标配置，处理名称碰撞，并保留目标配置要求的 DNS、规则与监听。合并后用目标客户端对应核心重新校验，再由用户显式导入使用。

片段依赖闭包只支持方案节点与地区入口组，以及必要的内置 DIRECT。未知上游、任意业务策略图、依赖循环、空入口组或名称碰撞会阻止输出，提示改用完整配置；不会删除依赖来制造看似可用的单节点。落地原生上游与当前方案选择不一致时也必须先明确修正。

每次复制／保存都会重新核对方案、来源文件、受管节点、入站、转发、线路与节点组快照身份。来源变化需重新读取或同步，重新生成适用的预览。片段限 200 节点、1 MiB，完整保留原生配置字段；外部证书文件、规则资源和系统环境的可用性仍由合并后的完整配置验证。

复制与保存的内容包括连接凭据，预览只显示节点名、角色与依赖。此功能不把凭据放进差异日志；Base64 也不是凭据加密。

## 完整配置导出差异

先生成候选并通过所选固定核心校验，再选导出路径，点「审阅并导出」。程序只读解析当前目标与候选，分别显示：

- 新建／替换／内容相同；
- 节点或出站新增、移除、修改数量；
- 代理组新增、移除、修改数量；
- 分流规则、DNS、监听／入站和其他设置是否变化。

这里统计的是原生配置中的定义数量。sing-box 的内置 DIRECT／BLOCK 也属于出站，因此其数量可以和 Mihomo 代理节点数量不同。密码、密钥、UUID、地址和原始字段值不进入差异摘要。连接参数变化仍会被统计为修改，不因脱敏而漏记。

只有确认后才写目标文件、恢复副本与事务。取消差异界面不会预先保存候选的审阅目标，也不创建导出事务。候选、来源、方案或目标文件在预览后变化，会停止导出并要求重审。已有目标无法安全解析时也停止，不能把解析失败当作空配置；检查其格式或选择新路径。

全部目标字节相同时不另建替换事务。有实际变化时继续使用既有双文件事务、导出锁、恢复副本与外部改动保护；写入第二份失败会按原范围补偿，不能覆盖写入后由其他程序产生的改动。未确认恢复的事务继续从原恢复入口处理，不能反复点击导出来代替恢复。

## 排错与恢复

| 提示／现象 | 处理 |
| --- | --- |
| 复用组阻止批量修改 | 在来源中心同步；确实需要独立使用时，完整选择该组后解除关联，再编辑。 |
| 移除节点导致出口或上游失效 | 先显式调整相关业务默认、保护组、落地入口或原生依赖，再重新预览。 |
| 片段出现额外入口节点 | 这是审阅中披露的完整入口依赖。只需要单节点直连时，先明确更改方案连接关系，不能删掉必要上游后宣称等价。 |
| 片段依赖未知业务组或形成循环 | 回到连接关系修复，或使用完整配置输出。 |
| 文件已存在 | 为片段选择新文件名；完整配置替换走差异审阅与事务。 |
| 目标解析失败 | 核对 YAML／JSON、重复键、重复节点身份或文件大小；未写原文件。错误不回显可能带凭据的解析器内容。 |
| 方案／来源／文件已经变化 | 保留外部改动，重新读取、生成、校验、审阅。 |

误改草稿但未保存时可放弃编辑；已经保存时从事先保留的方案快照恢复并重做候选。导出已替换文件的恢复沿用导出事务范围，不操作服务器。片段本身只创建新文件，不需要全机回滚。

## 本轮验证与边界

专项验证覆盖批量身份／顺序／空地区／业务默认／原生上游／整组解除、过期预览、片段依赖闭包／循环／高级字段／输出命名、原生序列化、重新导入、两个固定核心校验、取消及外部改动保护。

Python 只读辅助验证覆盖差异计数、连接鉴权变化、重复键／身份、超深／循环／膨胀别名、16 MiB 解析上限、不可解析类型及错误脱敏。原生界面验收通过现有测试接口在隐藏合成工作区执行，复制使用隔离接收器，不使用用户剪贴板、鼠标、焦点或托盘。

发行的汇总检查与打包范围见[v0.9.41 验证记录](TESTING-0.9.41.zh-CN.md)。本轮不新增在线订阅托管、用户配额、计费、常驻任务或第三方客户端格式，不自动安装桌面更新或改写正在使用的代理配置。
