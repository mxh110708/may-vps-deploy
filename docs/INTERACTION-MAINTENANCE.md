# 交互维护与回归约定

> 文档定位：保留的 PowerShell CLI／模块技术参考，不是当前 WinUI 桌面导航。桌面操作见[使用手册](USER-GUIDE.zh-CN.md)。


## 本次升级范围

- 防火墙、SSH、凭据轮换、受控升级、Komari、退役的动作输入页返回到所属子菜单；子菜单自身的 0 再交给父菜单处理。
- 协议启停的确认页 → 协议选择 → 启停选择，以及恢复中心的确认页 → 恢复范围 → 恢复点，分别建立独立返回边界。
- 协议卸载确认取消或短语错误时留在卸载选择范围内；客户端默认值编辑取消时丢弃当前未保存草稿并回到默认值菜单。
- 网络调优字段和手动客户端节点采用字段级回退；节点协议切换重置协议相关字段，敏感值不显示为默认值。
- SSH 与代理凭据轮换增加默认拒绝的确认；Komari Controller 卸载确认前不启动事务；防火墙接管在建立旧状态备份后才修改计划。
- JSON 使用同目录临时文件写入并替换，准备或写入失败时保留旧文件；这不是多个文件的联合原子事务，也不承诺断电后的磁盘持久性。既有私有归档继续沿用目录权限，保护函数不额外调整 ACL。
- 新配置工作台、草稿加密、发布与远端事务恢复见 [方案工作台与事务恢复](WORKBENCH-AND-RECOVERY.zh-CN.md)。

## 开发约定

1. 菜单本身的读取放在该菜单动作的返回捕获范围外。否则菜单自身的 0 会被吞掉，无法离开。
2. 每一层只捕获返回标记。真实错误及输入终止继续传播，不能转成正常返回。
3. `Read-VpsForm` 只收集输入，步骤里不得连接服务器、写文件或启动事务。它只重新访问用户返回到的字段，不重跑前面的步骤。
4. 条件字段通过 `When` 控制；返回使用实际访问记录，不按固定索引盲退。前置选择改变时由字段明确清理依赖值。
5. 输入和确认尽量在变更前完成。不要为修复导航自动重试已执行的远端动作。
6. 保持旧计划兼容读取和受管目录布局；本次没有提升外部组件固定版本。远端改动集中在事务互斥、SSH 维护收尾和恢复流程，并增加独立阶段记录。

## 验证

```powershell
pwsh -NoProfile -File .\tests\Test-Interaction.ps1 -ProjectRoot $PWD
pwsh -NoProfile -File .\tests\Run-Tests.ps1 -ProjectRoot $PWD
```

交互测试使用输入队列和禁止远端访问的替身，验证逐层返回、默认值、协议分支、取消前无事务，以及私有 JSON 保存失败保留旧文件。完整测试入口会自动运行它。

本地离线测试不等于真实 VPS 事务验收。SSH 切换、防火墙接管、恢复、升级、卸载和退役仍应在有恢复控制台的测试 VPS 上验证；没有执行任何生产 VPS 变更。尚未将所有历史多字段页面统一迁移到 `Read-VpsForm`，本次覆盖上述明确列出的路径，不能据此宣称全部交互页面已完成逐字段审计。
