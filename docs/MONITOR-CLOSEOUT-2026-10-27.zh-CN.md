## 邮件功能

告警与独立 watchdog 共用 SMTP 发送实现，规则可选择不发送、本地 HTTP 或邮件。邮件设置由专用账户私密文件提供，不进入 Web 设置、只读 API 或响应正文；缺失配置时界面明确提示未配置，规则仍可评估。

仅支持 TLS 465 或必须升级加密的 STARTTLS 587，校验证书、主机名和 TLS 版本。解析后只连接已经核对的公网地址，拒绝内网、回环、元数据地址、混合 DNS 和明文回退。发送限时十秒、收件人最多五个，复用现有确认、冷却、静默、恢复、事件 ID 和最多三次尝试。发送成功代表 SMTP 接受 DATA，不保证已经进入收件箱，也不声称严格仅投递一次。

本地 TLS SMTP 夹具覆盖加密故障与恢复内容、稳定 Message-ID、未提供 STARTTLS、不可信证书、错误域名、认证拒绝、内网／混合 DNS、危险头部、私密文件权限及无配置不发信。真实浏览器验证了渠道选择、保存和未配置提示；临时账户、数据及进程均属于隔离夹具。

配置与后续收信验收见 [Server 邮件手册](https://github.com/mxh110708/may-monitor-server/blob/main/docs/EMAIL.zh-CN.md)。目前没有真实发件账户、收件人或外发测试邮件。

## 独立主机检查

watchdog 部署在与 BERO 不同的受管主机，由独立系统账户运行，使用原有只读授权和固定 Server UUID。每 30 秒检查，异常连续确认三次、恢复两次；凭据、证书、身份及普通失联保留不同状态。CPU 上限 2%、内存上限 64 MiB、任务上限 32，不依赖本机持续开机。

生产单元直接通过真实 HTTPS 检查并确认健康。故障注入限定在同主机的独立回环夹具：夹具健康时读取同一真实 HTTPS／安装身份，失败时只令该夹具路径返回异常；验证单次故障、恢复、重启去重和重复进程拒绝。没有停止生产 Server 或整台宿主机来制造故障，也不将其写成真实机房断电演练。

约 50.12 秒、11 个样本的短测，主检查单元 cgroup 内存中位数和采样峰值约 11.40 MiB，平均 CPU 约单核的 0.01175%。这不是进程 RSS 或新的 24 小时长测。自有夹具进程和文件已清理，生产检查继续运行。邮件未启用时仅保存状态和事件，不向用户外发。

watchdog 的状态文件增加 Linux 内核互斥锁，重复进程不能同时写入；进程退出自动释放锁。部署、授权续期及恢复见 [独立检查手册](MONITOR-WATCHDOG.zh-CN.md)。共享读取授权轮换或续期后，Deploy 与 watchdog 都要更新；真实截止时间保存在私人记录，不假设授权永久有效。

## 部署器修正

实际升级暴露了已发布资产与早期精简包校验的不一致。Server 包现在只接受二进制、LICENSE、SECURITY.md、CHANGELOG.md 和与当前固定版本完全匹配的 RELEASE 文档；先验证全部成员，再写出候选程序。继续拒绝未知文件、路径、链接、重复名称、错误版本及越界尺寸。

完整配置和凭据校验前移至停服务之前。升级输入缺少 Server／Agent 凭据时，原服务继续运行，不进入应用阶段。若升级已经停止但尚无文件写入，恢复会重新证明完整原文件身份，只恢复运行标志并关闭事务，不将新增指标倒退到早期快照。

本次操作中发生过一次参数遗漏导致的未写入升级中断。确认原文件后恢复了原服务，未覆盖数据库；此后用新的事务完成升级，没有重放状态不明的 Apply。上述修正分别有正反例和新数据保持回归，属于正常维护与恢复行为，不是迁移临时兼容桥。

本地主题 ZIP 与公开附件的归档散列也曾不同；比较确认全部文件条目内容一致。部署采用准确公开附件并重新核对 SHA-256，没有放宽完整性检查或替换已发布附件。
