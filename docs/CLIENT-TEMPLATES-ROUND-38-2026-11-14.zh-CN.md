# 第38轮：客户端模板库

本轮面向 Mihomo 与 May Route，提供通用基础配置的版本、参数、依赖、差异和恢复。纳入 v0.9.42；发行验证见[版本检查](TESTING-0.9.42.zh-CN.md)。模板操作只修改 Deploy 私人归档，不会安装客户端、修改系统代理或把配置直接应用到正在运行的代理。

## 模板与方案的关系

模板保存基础 DNS、路由规则、地区／业务布局和通用参数。方案继续管理节点、身份、订阅、节点组引用、输出处理及导出位置。模板不能夹带固定代理节点或代理订阅，已有连接应从节点来源加入方案。

每个模板有稳定身份和从1开始的修订号。编辑创建新修订，另存创建新的模板；既有修订不覆盖，已用方案不自动跟随最新版本。内置模板首次使用时也保存私有固定快照，从内置版本派生修订时保留父快照。每组最多32个修订、库最多32组；达到上限时可以另存新模板，不自动删除仍可能使用的历史。

原有“读取现有配置”和通用模板工作流保留。主动读取其他基础配置或在草稿中恢复内置模板会解除该草稿的版本绑定；它们不会改写模板库，也不等同于恢复一条已保存应用记录。

## 开始使用

1. 在“配置设计”打开客户端模板库；未打开方案时可以查看、派生和检查模板。
2. 选择版本，点击“新建修订”或“另存为新模板”。修改参数；需要时展开高级区域，修改布局 JSON 和完整基础 YAML／JSON。
3. 保存前检查参数与引用，并核对本机固定核心归档。失败保留原版本和编辑内容。
4. 打开并保存目标方案，再从模板库预览应用差异。未保存草稿不能被模板应用覆盖。
5. 审阅 DNS、规则、监听、其他设置、布局及来源变化后确认。节点、凭据、订阅、节点组引用和导出目标保留。
6. 回方案重新生成候选，完成所选客户端的固定核心校验，再审阅导出。模板保存、依赖检查和语法校验都不等于真实线路验收。

## 参数

| 参数 | 默认值 | 作用与限制 |
| --- | --- | --- |
| Mihomo混合端口 | 7890 | 整数1–65535，只作用于Mihomo基础配置。 |
| May Route混合端口 | 2080 | 整数1–65535，设置mixed入站端口。 |
| 允许局域网访问 | 关闭 | 显式开启后，混合监听改为所有IPv4接口；只改输出配置，不修改Windows防火墙或当前代理。使用前自行核对访问范围。 |
| 日志等级 | info | debug、info、warn、error；Mihomo的warn映射为warning。 |
| 默认路由模式 | rule | rule、global、direct；定义配置默认值，不切换运行中的客户端。 |
| Mihomo允许IPv6 | 开启 | 修改Mihomo顶层IPv6开关，不推断网站出口，也不同时改写其DNS IPv6策略。 |
| TUN MTU | 0 | 0保留基础值；显式值1280–9000。只设置已有TUN定义，不启用系统TUN。 |

参数区覆盖基础文件中对应的监听、模式、日志等字段。完整基础文件可编辑DNS和规则；节点和最终分组仍由方案生成。两个客户端是替代输出，混合端口允许相同，但额外的独立HTTP／SOCKS／透明监听不能通过模板隐式加入。

高级布局使用当前布局格式：地区名称、默认出口、业务默认值、候选顺序和保护组。引用须能在模板中解释，不接受指向具体节点的业务默认值。模板移除某地区而现有节点仍归属该地区时，应用会拒绝，不能悄悄改组或删除节点。

## 依赖与版本

模板固定所选客户端的校验核心版本与归档身份：Mihomo对应Mihomo；May Route配置同时记录通用sing-box及配套May Core。声明来自随应用提供的固定校验资源，不代表已探测本机所安装的客户端版本。归档缺失或摘要错误会阻止检查／应用。

核心资源发生变化时，需显式创建并审阅新修订，旧版本不被静默改成新的依赖。含XHTTP的完整候选仍要求配套May Core能力，不能拿上游sing-box替代验证。

| 依赖 | 检查行为 |
| --- | --- |
| 固定核心 | 核对本机归档和摘要；完整生成后再实际运行所选核心的配置校验。 |
| 地区／组／下一跳引用 | 检查已知引用和模板布局；最终候选继续执行既有关系及核心检查。 |
| HTTPS规则集／GeoData | 记录来源身份，界面仅显示安全的主机名；不下载、不证明公网可达，也不把URL查询凭据放进摘要说明。 |
| 未附带的本地规则文件 | 拒绝保存，不读取任意本机文件或以空规则替代。可改为完整内联规则或HTTPS来源。 |
| 固定节点／代理订阅 | 拒绝进入基础模板，使用已有节点／订阅功能管理。 |

单份基础文本最多256 KiB，渲染输入和输出有总上限。解析不执行脚本、命令或网络请求；复杂配置仍需完整核心校验和适用的实际连接验收。

## 差异、应用与取消

应用差异由现有基础文件与所选版本的实际渲染结果比较，显示DNS、规则、监听及其他设置的变化，另列布局和来源模式变更。不把完整节点身份、密码、原始工具错误或URL查询令牌写进差异说明。

审阅同时固定方案、基础来源文件、模板修订、渲染程序及核心依赖。任一对象在审阅后变化都会拒绝应用。预览和取消不修改方案或创建应用事务；预览可能准备可复现的私有模板快照／渲染文件。应用相同版本且基础字段完全相同时不写方案、不清除已有候选、不重复记录事务。

确认后仅替换基础来源、布局和模板绑定，清除旧候选。不会直接写导出文件，实际客户端保持原配置，直到用户另行生成、校验、导出并自行加载。

## 恢复与确认不明

在模板库打开“应用记录与恢复”，选择记录并审阅恢复。恢复只涉及该记录前的基础字段；当前节点、凭据、订阅、输出处理和导出文件保留。恢复后需要重新生成候选。

应用先记录准备状态，再原子保存方案，最后写完成状态。若最后确认丢失，不自动重放应用；待核对状态会阻止保存、生成及下游来源使用。恢复核对当前基础字段是否与该记录的前态或后态相符：前态不重复写入，后态才恢复；其他状态拒绝覆盖。

| 情况 | 结果 |
| --- | --- |
| 审阅后方案或来源文件变化 | 拒绝应用，重新预览。 |
| 应用后只调整了节点 | 恢复基础配置时保留节点；如果旧布局不能容纳新节点地区，则拒绝恢复。 |
| 应用后又修改了基础／布局 | 不覆盖新数据；先核对当前变更。 |
| 原基础来源丢失或变化 | 不恢复到过期来源；保留记录供核对。 |
| 固定渲染文件被外部编辑 | 不覆盖，也不继续当成已固定模板生成或导出。 |
| 未知事务版本、错误归属或摘要 | 保留材料，停止使用和恢复。 |

模板版本、快照和应用记录在私人归档中加密保存；供配置生成读取的渲染文件位于同一私人根目录。迁移私人根目录时一并迁移，不把它们发布到GitHub或安装包。

## 开发与验证

专项入口为 `--client-templates-only`、`tests/test_client_template_library.py` 和后台原生 `suite.client-templates`。模型、事务和候选闭环纳入 `--group clients`；Python检查纳入主校验及CI。非Windows的CI运行跨平台模型／渲染，Windows固定核心的执行明确单列。

维护者修改基础模板、布局或固定核心目录身份后，必须同步增加 `config/client-templates.json` 的内置修订号，并保留已应用的私有版本；不得用同一修订号替换不同内容。

v0.9.43 的1.14.4核心基线使用新的内置模板身份和修订2，避免与用户在旧内置身份下自行派生的修订2冲突。旧私人模板和参数保留原身份；需要升级其核心时，从该模板最新私人修订显式派生并审阅新修订。模板库默认打开当前内置基线，不自动应用它。
