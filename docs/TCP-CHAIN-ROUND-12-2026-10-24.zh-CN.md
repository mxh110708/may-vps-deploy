# 第十二轮：跨实例 TCP 前置、中转与落地

日期：2026-10-24。原定主线第十二轮的**有限 TCP 阶段**已补齐源码与隔离验收，尚未发布、安装或操作生产实例。监控 M1–M3 继续独立编号；下一主线仍为通用多入站模型。

## 支持的线路

本轮固定为三台不同的受管实例：前置、中转，以及已有代理协议的落地。前置和中转使用系统自带的 TCP socket activation；落地沿用已有 Reality、AnyTLS 或 Shadowsocks／SS2022 的原生节点参数。

```mermaid
flowchart LR
  C[客户端] -->|允许来源内的 TCP| A[前置监听]
  A -->|TCP；中转仅允许前置出口| B[中转监听]
  B -->|TCP；原代理鉴权与 TLS| D[已有落地代理]
  D --> H[HTTPS 验收目标]
```

两段转发都是透明 TCP。鉴权、TLS/SNI、Reality、ECH、用户密钥和预期出口保留在原代理节点中；转发层不解密代理协议。Shadowsocks 的新线路节点明确标为仅 TCP；VLESS／AnyTLS 原本由 TCP 承载的协议能力继续沿用原参数。

Windows 控制端通过现有 SSH 运行时完成编排。正常使用此功能不依赖 WSL；本轮的 WSL/QEMU 仅用于开发隔离验收。

当前限制：

- 三台实例都须已完成接入或部署，且机器身份不同；多份归档实际连接同一台机器会在写入前被拒绝。
- 仅支持 IPv4 的两段 TCP 转发，每台实例限参与一条线路。
- 落地须为配置设计中已保存的原始受管节点；本轮不将另一条转发线路再次作为落地。
- 新建后可以检查、移除和恢复。改变参与实例或端口时先移除，再新建并验收。
- UDP、QUIC 转发、隧道封装、任意图及多线路共享实例留待后续扩展。

## 界面与参数

在任意参与实例的详情中选择 **跨实例 TCP 编排 → 管理线路**。新建时当前实例作为前置；从中转或落地打开时，也能看到同一条已保存线路及其恢复入口。

| 参数 | 作用与约束 |
| --- | --- |
| 线路名称 | 1–60 个可打印字符；用于选择、审阅和客户端投影。 |
| 中转实例 | 已受管、与前置和落地均不同的实例。 |
| 落地节点 | 已保存方案中的受管 IPv4 原始代理节点，固定方案、节点及连接摘要。 |
| 前置 TCP 端口 | 客户端连接的监听端口；检查管理端口、已安装组件及实际监听冲突。 |
| 中转 TCP 端口 | 前置连接的监听端口；相同端口在不同机器上可以使用。 |
| 前置允许来源 | 必填 IPv4 地址或 CIDR，每行一个；须包含验收电脑的实际出口。规范化网络地址、去重并排序。 |
| 前置真实出口 | 中转只允许这个 IPv4 的 `/32`；默认取前置归档地址，存在 NAT 时须填写真实出口。 |

最终审阅统一列出三台依赖、三端端口、两处来源白名单、防火墙处理方式、应用顺序、已有连接的中断范围和恢复范围。审阅取消不会连接 VPS、启动任务或保存线路依赖。

执行页显示预检、备份、应用、验收、提交五个阶段及各自的完成/失败状态；只读检查和恢复使用相应的简化计划。已保存线路分别显示上次整链 HTTPS 结果与两段 TCP 结果，最近检查失败会明确提示重新检查。

前置允许来源填所有 IPv4 时，相当于公开前置监听；落地原协议的鉴权仍然有效。中转始终只允许审阅中的前置出口，不自动追加控制端来源。分段检查从前一台实例执行，不要求为了检查而公开中转。

若实例使用受管防火墙，本次保存同步其 TCP 放行并纳入快照。使用“保留既有防火墙”时只维护独立转发白名单；宿主及服务商防火墙的端口由维护者事先放行。落地现有来源限制仍须允许中转出口，本轮不修改落地防火墙或代理服务。

应用会重建前置、中转当前 TCP 转发组件的监听，已有转发连接会短暂中断，原有规则保留。这里只保存相应转发和必要的受管防火墙；SSH、代理协议、监控和网络调优不进入恢复范围。

## 应用与分阶段验收

1. **锁定审阅对象。** 审阅摘要包含三台本地计划、状态、凭据、未完成事务、线路记录、来源方案和相关脚本摘要。执行前按固定顺序取得三台实例锁，重新核对摘要。任一实例已有任务时释放已经取得的锁。
2. **全部预检。** 核对 Debian 12/13 amd64、管理连接、不同的实际机器身份、转发实际资源摘要、候选端口、白名单和防火墙范围。落地只读核对实际代理配置与归档 SHA256，同时确认来源节点仍匹配。
3. **建立两台快照。** 先中转、再前置；每台记录原计划、组件状态、受管文件摘要及恢复材料，并启用原有 20 分钟回退保护。线路快照另外固定自己的恢复程序及校验值。
4. **从后向前应用。** 先使中转转发到原落地端口，再使前置转发到中转。每台执行后立即读取实际配置、socket 与白名单摘要，保留原有独立转发规则。
5. **分段检查。** 从中转连接落地，从前置连接中转；记录来源实例、地址、端口和耗时。这两项明确标为 `TcpConnectOnly`，不能单独作为代理可用证据。
6. **整链应用验收。** 控制端使用固定验证核心，经前置、中转、落地完成原代理协议握手和 HTTPS 请求。核对节点连接摘要、出口地址族及已设置的预期出口。现有独立规则也执行各自的应用验收。
7. **提交前再核对。** 再读两台转发摘要、落地配置和管理连接；验收期间的变更会阻止提交。
8. **逐台提交与归档。** 全部验收通过后才依次提交中转、前置，最后保存线路状态和三台的依赖绑定，解除本地任务占用。

跨机器提交是逐台完成的，不能保证网络分区时瞬间同时提交。应用保留跨实例协调记录，并对部分提交执行组件范围补偿；无法安全完成时显示待恢复，不能报告线路已经完成或已经全部恢复。

## 失败、取消与恢复

线路协调记录位于私人归档的 `tcp-chains/<线路身份>.json`。每台自己的 `operation-pending.dotnet.json`、`maintenance-backups/<任务身份>/` 和远端快照仍保留。记录使用相对实例身份及来源方案引用，不复制明文代理密钥。

| 情况 | 行为 |
| --- | --- |
| 预检不符、端口冲突、机器重复或落地漂移 | 停止应用；清理本次本地占用，不接管其他实例或资源。 |
| 快照命令的响应丢失 | 查询实际任务身份与阶段。尚未武装且转发仍为原摘要时，只释放本次未武装事务。 |
| 应用命令的响应丢失 | 查询原事务并按快照恢复，不自动重放应用。 |
| 分段、HTTPS、原有规则或管理连接验收失败 | 先恢复前置，再恢复中转；重新读取原摘要和管理连接。 |
| 用户取消 | 在安全边界结束远端步骤，再按同一范围恢复。 |
| 中转已经提交，前置失败或提交响应丢失 | 使用原任务身份、线路身份和固定恢复程序，对已提交参与实例补偿；另一台也恢复到本次操作之前。 |
| 补偿已完成但响应丢失 | 后续恢复读取完成标记和实际资源，继续本地对账，不重放原应用。 |
| 远端不可达、其他任务归属或文件/白名单外部编辑 | 保留待恢复记录，拒绝覆盖未知资源。 |
| 移除线路时中途失败 | 恢复移除前的活动线路与依赖，而不是将它误标为已删除。 |

从任一参与实例打开“管理线路”，选择该线路的 **恢复本次整条线路**。恢复协调两台转发；不是从某一台通用恢复入口单独恢复。未完成线路会保留三台依赖占用，避免后续维护或删除归档破坏恢复依据。

应用意外退出后，尚未提交的远端参与实例仍有回退计时器。已提交实例的恢复仍需控制端按原协调记录完成；不要手动清除本地记录或远端事务归属来跳过恢复。

## 日常检查、客户端生成和移除

**只读检查整条线路**重新核对三台、分段连接、整链代理 HTTPS 及已有规则，只保存本机检查结果。已知检查失败的线路不能继续生成新候选或导出，原有客户端文件不会被自动改写；重新检查通过后恢复可选。

完成应用后，在配置设计中使用 **添加转发节点**，选择跨实例线路及入口地区组。生成的是前置地址、前置端口和原始落地鉴权/TLS 的双客户端节点。该节点可以改显示名称、用途和分组；连接参数保持受管来源。

添加、生成、校验、发布审阅、分享和线路诊断都会核对线路及来源摘要。线路移除、依赖缺失、落地凭据改变或连接被手改时，旧投影不再作为有效来源导出。线路本身不托管在线订阅，也不自动修改客户端的当前选择。

**移除这条线路**先保存本次快照，先关闭前置，再移除中转中的本条规则。其他独立转发规则继续验收，落地无需在线；三台本地依赖在成功后一起解除。线路记录与恢复材料保留为历史。

当前有线路依赖时，禁止从单机 TCP 编辑器、协议身份维护或归档删除入口破坏参与实例；先通过线路页统一移除或恢复。其他独立组件的维护仍按各自事务执行。

- 最终跨实例 .NET 专项 193 项断言通过，覆盖审阅失效、三台锁及释放、机器别名、漂移、保留规则、快照/应用/提交/补偿响应丢失、取消、部分恢复、移除失败、来源保密、客户端投影和失效检查。完整 .NET 回归 2163 项断言通过，包含真实 Python 构建、固定核心、回环 SSH/TLS 及已有功能。
- 隐藏原生 WinUI 回归 14 组结果通过，覆盖表单、受管落地回填、规范来源、三台审阅、取消、从中转打开同一线路、移除和恢复入口，以及草稿保留、五阶段进度与失败显示；截图已检查，测试证明零窗口激活、零前台采样、无托盘及无生产目标。
- Linux TCP 回归 21 项通过，无跳过，包含真实 socket-proxyd 和 TIME_WAIT：关闭连接可以重新绑定，仍在使用的监听必须拒绝。UDP 不启用 TCP 的复用行为。
- 三台真实隔离虚拟机：前置 Debian 12，中转与落地 Debian 13。使用应用锁定的 sing-box 1.14.2，实际运行 SS2022、两段原生 TCP 转发及 HTTPS 应用，17 项断言通过。
- 三机实测包括双客户端生成并由固定核心校验、中转来源拒绝、前置/中转真实重启后的整链检查、快速移除重建，以及在中转真实提交成功后注入响应丢失。最终核对两台规则、事务归属和计时器均恢复，落地代理字节保持原样。
- HTTPS 验收目标为临时落地机内服务，证书只在测试进程提供临时信任；未安装系统根证书。另验证默认系统信任拒绝该证书、主机名不符时拒绝。两次公网目标失败没有被当作成功证据，均触发恢复。
- Windows Release 构建、`ValidateProject` 主校验及其密钥扫描通过。NuGet 在线漏洞元数据不可达的 `NU1900` 不作为依赖漏洞审计已完成的证据；Windows .NET 符号链接用例因本机权限跳过，Linux TCP 回归无跳过。

这些结果证明隔离环境中的控制流程及实际转发行为，不代表生产公网路径、服务商 ACL、带宽或长期资源曲线已经验收。临时虚拟机已经关闭，未修改宿主路由、系统代理或生产实例。
